## 0. 关键决策一页纸

1. **ruleRef 语法 = `rule:<namespace>.<path><locator>`**，locator 三种：`#<index>`（数组）/ `@<key>`（字典键）/ `.default`（占位）。namespace 全集：`sampleId / condition / substrate / channel / measurementName / measurementTag / fallback / migration`。
2. **`ParsedFilenameHints` 扩展用平行字段 `hintSources: [String: String]`**（key→ruleRef 字符串映射），不升 `Sourced<T>`。30+ 调用点零破坏。
3. **`RuleLoader` 暴露 `ruleSetFingerprint = metadata.fingerprint`**（复用 5 文件联合 SHA + schemaVersion 前缀），**`ruleSetVersion`** 来自新增独立状态文件 `rule_set_state.json`，不复用 `currentSchemaVersion`。
4. **`ruleSetVersion` 存储位点 = `<RulesConfigPaths.configDirectoryURL>/rule_set_state.json`**，schema = `{version: 1, ruleSetVersion: Int, updatedAt: ISO-8601}`。**Save All 多 section 合并为一次 +1**；**不**进入 `compositeHash` 计算（避免自循环）。
5. **Sidecar v2 双层 schema**：顶层平移 v1 的 `version/workflow/workflowDisplayName/sourceFilePath/appliedAt/channels`，新增 `ruleSnapshot { ruleSetVersion, ruleSetFingerprint, appliedAt, fields }` + `userOverrides { conditions }`。
6. **`ruleSnapshot.fields` 范围：`sampleID / conditions / substrateTags`**（与 ROADMAP 顶层设计示例一致）；**channels 不带 source**（顶层平移），本期不为 channels 加 provenance。
7. **`userOverrides` 范围本期仅 `conditions` 字典覆盖**：不开 sampleID 覆盖（id 应 100% 来自规则）、不开数组类（substrateTags / channels）覆盖。数组覆盖延后到后续版本看实际需求再加。
8. **v1→v2 迁移 = "首读即升级 + 立即原子回写"**。失败仅 warning 不阻断；conditions source 路径化为 `rule:migration.v1.conditions.<id>.default`；`ruleSetVersion=0` / `ruleSetFingerprint="legacy:v1-unknown"`。
9. **`effectiveConditions` 由 `extension SpinLabFileSidecar` 计算属性暴露**，不引入 `SidecarReader`。
10. **Import / Recompute 共享 `buildRuleSnapshot(...) -> RuleSnapshot` pure function**；唯一分支差异 = `composeSidecarV2(..., preserveUserOverrides: Bool, ...)` 的 bool 参数。AG5 结构性满足。
11. **Recompute "stale" 判定 = `sidecar.ruleSnapshot.ruleSetFingerprint != currentLoader.ruleSetFingerprint`**（fingerprint 不等即 stale，不用 version）。`稍后`抑制 = per-root + 记 `dismissedFingerprint`，规则下次内容变化重显。
12. **Recompute 全量入口（软提示条 + 工具栏按钮）共用 `openRecomputePreview()`**；详情页编辑只动 `userOverrides`，**不**触发 Recompute、**不**刷新 staleCount（解耦）。

## 1. Provenance Schema（s2 契约源）

### 1.1 ruleRef Grammar

#### ABNF

```
rule-ref   = "rule:" namespace "." path locator
namespace  = "sampleId" / "condition" / "substrate" / "channel"
           / "measurementName" / "measurementTag"
           / "fallback" / "migration"
path       = segment *("." segment)
segment    = 1*(ALPHA / DIGIT / "_" / "-")
locator    = ("#" 1*DIGIT) / ("@" key-token) / ".default"
key-token  = 1*(ALPHA / DIGIT / "_" / "-")
```

- `#<index>` 引用配置 decode 后的**原始 0 基数组下标**，不是匹配顺序
- `@<key>` 用于字典键命中（channel.aliases / extraConditions binding 等）
- `.default` 占位"无显式命中走默认值或迁移占位"

#### 规则类型 → ruleRef 映射表

| 规则数据 | ruleRef 模板 | 示例 |
|---|---|---|
| `sampleId.batchPrefixes[i]` | `rule:sampleId.batchPrefixes#<i>` | `rule:sampleId.batchPrefixes#3` |
| `sampleId.patterns[i]` | `rule:sampleId.patterns#<i>` | `rule:sampleId.patterns#1` |
| `ConditionDefinition(id=X, kind=unitSuffix)` | `rule:condition.<X>.unitSuffix#<index-of-def>` | `rule:condition.temperature.unitSuffix#0` |
| `ConditionDefinition(id=X, kind=tokenMap, tokenMap[i])` | `rule:condition.<X>.tokenMap#<i>` | `rule:condition.voltage.tokenMap#0` |
| `conditions.tokenMapRules[X][i]`（binding 形式） | `rule:condition.<X>.tokenMap#<i>` | `rule:condition.device.tokenMap#2` |
| `conditions.extraConditions[X]`（binding unit 来源） | `rule:condition.<X>.extraPattern@<X>` | `rule:condition.temperature.extraPattern@temperature` |
| `substrate.materials[i]` | `rule:substrate.materials#<i>` | `rule:substrate.materials#2` |
| `substrate.orientations[i]` | `rule:substrate.orientations#<i>` | `rule:substrate.orientations#0` |
| `substrate.treatments[i]` | `rule:substrate.treatments#<i>` | `rule:substrate.treatments#1` |
| `channel.aliases[normalizedKey]` | `rule:channel.aliases@<key>` | `rule:channel.aliases@rxx` |
| `measurementNameRules[i]` | `rule:measurementName.rules#<i>` | `rule:measurementName.rules#4` |
| `measurementTagRules[i]` | `rule:measurementTag.rules#<i>` | `rule:measurementTag.rules#1` |
| 规则未命中但有 schema 默认值 | `rule:fallback.<fieldPath>.default` | `rule:fallback.condition.temperature.default` |
| 全规则集走 `FilenameRuleSet.fallback()` | `rule:fallback.<fieldPath>.default` | （同上）|
| v1 → v2 迁移占位 | `rule:migration.v1.<fieldPath>.default` | `rule:migration.v1.conditions.temperature.default` |

#### 不变量

- ruleRef 必须可序列化、不含本地路径、不含可变文案
- 数组下标稳定基于 decode 后顺序；规则集演化导致下标越界 → Recompute 时按"未命中"处理
- 规则未命中且字段无默认值 → 字段不写入 `ruleSnapshot.fields`（不产生半值 ruleRef）
- 多值字段（如 substrateTags）每个值独立携带自己的 ruleRef
- 同字段多规则候选命中场景（tokenMap vs unitSuffix）：沿用现有优先级，ruleRef 仅记最终采用规则
- `@key` 长度上限 ≤ 160 字符；超长截断 + hash 后缀

### 1.2 ParsedFilenameHints 扩展

**方案 A**（选）：

```swift
struct ParsedFilenameHints {
    // ... 既有字段全部不动
    var hintSources: [String: String] = [:]   // key → ruleRef 字符串
}
```

**key 命名约定**：

| key | 对应 hints 字段 |
|---|---|
| `"sampleID"` | `sampleIDs[0]`（首个）|
| `"sampleID#<i>"` | 多个 sampleID 时按下标 |
| `"condition.<id>"` | `conditionValues[<id>]` |
| `"channelHints[<i>].channel"` | `channelHints[<i>]` |
| `"substrateTags[<i>]"` | `substrateTags[<i>]` |
| `"workflowID"` | `workflowID` |
| `"measurementName"` | `measurementName` |

**写入规则**：仅当对应值存在时写 `hintSources`；fallback / migration 占位也要写（让下游 sidecar 写入路径有完整 source 数据）。

**理由**：现有 30+ 调用点（hints.temperature / hints.sampleIDs / hints.substrateTags）零修改；source 信息在 sidecar 写入路径单点消费，不扩散。

### 1.3 RuleLoader 暴露面

```swift
struct RuleMetadata {
    var schemaVersion: Int          // = currentSchemaVersion (=4)，原 version 改名
    var contentHash: String         // 既有
    var sourceLabel: String          // 既有
    var sourcePath: String           // 既有
    var loadedAt: Date               // 既有

    /// 既有：保留作 RuleLoader 内部 cache 失效用
    var fingerprint: String { "v\(schemaVersion):\(contentHash)" }
}

extension RuleLoader.LoadResult {
    /// ROADMAP §5.1.7 ruleSetFingerprint：直接复用 metadata.fingerprint
    var ruleSetFingerprint: String { metadata.fingerprint }

    /// ROADMAP §5.1.7 ruleSetVersion：从 rule_set_state.json 读
    var ruleSetVersion: Int { /* 见 §1.4 */ }
}
```

- `SpinLabRuleProviding.loadResult()` 必须携带这两个访问器
- `SpinLabRuleProvider.ruleSet()`（仅返回 FilenameRuleSet）不足以支撑 Recompute；Recompute / sidecar 写路径必须基于 `loadResult()`
- stale 判定**只**用 fingerprint；version 仅用于文案展示与排序

### 1.4 ruleSetVersion 存储位点

#### 文件 + schema

`<RulesConfigPaths.configDirectoryURL>/rule_set_state.json`：

```json
{
  "version": 1,
  "ruleSetVersion": 12,
  "updatedAt": "2026-04-27T18:00:00+08:00"
}
```

- `version`（顶层）= 状态文件 schema 版本（固定 1）
- `ruleSetVersion` = 用户视角语义版本，初始 1
- `updatedAt` = 最近一次 bump 时间

#### bump 时机

- ✓ Rules Panel 单 section Save 成功 → `+1`
- ✓ Rules Panel "Save All" 多 section 全部成功 → 合并为**单次 +1**（不是每 section +1）
- ✗ Discard / 读取 / 5.1.5 RulesSyncEngine 自动同步回写 → 不触发
- ✗ section 保存失败（含 hash 冲突）→ 不触发

#### bump 原子性

1. 完成 section 写入（runtime + mirror 都成功）
2. 写 `rule_set_state.json`（runtime 路径）
3. 若 step 2 失败：section 保存仍算成功，UI 出黄条 "规则已保存，但版本号未更新"，下次保存补增（不回补丢失次数）

#### 冷启动

- 文件不存在 → 首次创建 `{version:1, ruleSetVersion:1, updatedAt:now}`
- 文件损坏 → 回退 `{ruleSetVersion:1}` + warning，不阻断规则加载

#### [HARD] 不进 contentHash

`rule_set_state.json` **不**进入 `RuleLoader.compositeHash` 计算。否则保存 → version+1 → hash 变 → 触发再保存形成自循环。

### 2.2 字段类型契约（Swift）

```swift
struct SpinLabFileSidecar: Codable, Hashable, Sendable {
    var version: Int                          // = 2
    var workflow: String
    var workflowDisplayName: String
    var channels: [String]                     // 顶层平移 v1，本期不带 source
    var sourceFilePath: String
    var appliedAt: Date
    var ruleSnapshot: SidecarRuleSnapshot
    var userOverrides: SidecarUserOverrides
}

struct SidecarRuleSnapshot: Codable, Hashable, Sendable {
    var ruleSetVersion: Int
    var ruleSetFingerprint: String
    var appliedAt: Date
    var fields: SidecarRuleFields
}

struct SidecarRuleFields: Codable, Hashable, Sendable {
    var sampleID: SourcedValue?                // 规则未填即 nil
    var conditions: [String: SourcedValue]     // condition.id → value+source
    var substrateTags: [SourcedValue]
}

struct SourcedValue: Codable, Hashable, Sendable {
    var value: String
    var source: String                          // ruleRef，见 §1.1
}

struct SidecarUserOverrides: Codable, Hashable, Sendable {
    var conditions: [String: ManualValueOverride]  // 本期唯一支持的覆盖维度

    static let empty = SidecarUserOverrides(conditions: [:])
}

struct ManualValueOverride: Codable, Hashable, Sendable {
    var value: String
    var reason: String                          // 当前固定 "manual"
    var at: Date
}
```

#### 字段必填 / 可选

- 顶层全部必填（`channels` 默认 `[]`、`workflowDisplayName` 为空时回退 `workflow`）
- `ruleSnapshot.fields.sampleID` 可选，`conditions` / `substrateTags` 必填（默认空）
- `userOverrides.conditions` 必填（默认 `{}`）
- 编码：JSON pretty + sortedKeys；日期 ISO-8601；可选字段不输出 null

#### **本期不开**（明确收紧）

- ❌ `userOverrides.sampleID`：sampleID 应 100% 来自规则；用户编辑会污染数据完整性
- ❌ `userOverrides.substrateTags / channels`（数组类）：本期场景不强需求；数组操作 op 设计复杂度高；延后到后续版本看真实需求再加
- ❌ 规则全文快照 / mtime / 自动重算标记（ROADMAP 已否决）

### 2.3 v1 → v2 迁移规则

#### 触发

- decode 检测 `version < 2` → 内存升级为 v2 → **立即原子回写 v2 文件**
- 回写失败 → 记 warning，读取流程继续，不阻断 UI

#### 字段映射

| v1 字段 | v2 落点 | 备注 |
|---|---|---|
| `version` | `version` | 强写 `2` |
| `workflow` | `workflow` | 平移 |
| `workflowDisplayName` | `workflowDisplayName` | 平移；空值回退 `workflow` |
| `channels` | `channels`（顶层）| 平移 |
| `sourceFilePath` | `sourceFilePath` | 平移 |
| `appliedAt` | `appliedAt` + `ruleSnapshot.appliedAt` | 同时写两处 |
| `conditions[k]` | `ruleSnapshot.fields.conditions[k]` | `SourcedValue(value, "rule:migration.v1.conditions.<k>.default")` |
| 无（v1 无 sampleID）| `ruleSnapshot.fields.sampleID` | `nil`（不写）|
| 无（v1 无 substrateTags）| `ruleSnapshot.fields.substrateTags` | `[]` |
| 无 | `ruleSnapshot.ruleSetVersion` | `0`（"前规则集时代"占位）|
| 无 | `ruleSnapshot.ruleSetFingerprint` | `"legacy:v1-unknown"` |
| 无 | `userOverrides.conditions` | `{}`（AG4：不可凭空伪造编辑历史）|

#### 迁移后首次 Recompute 行为

- fingerprint = `"legacy:v1-unknown"` 必定 ≠ 当前 fingerprint → 一定 stale
- 用户主动 Recompute → 旧 conditions 全部由当前规则集替换；diff 表中显示状态 "**迁移**"（来源 `migration.v1` → 真实 ruleRef）
- `userOverrides` 仍为空，除非用户手动编辑

### 2.4 effectiveConditions 暴露形态

**选 A**：`extension SpinLabFileSidecar` 计算属性。

```swift
extension SpinLabFileSidecar {
    /// userOverrides 覆盖 ruleSnapshot.fields 后的最终消费值
    var effectiveConditions: [String: String] {
        var result = ruleSnapshot.fields.conditions.mapValues(\.value)
        for (key, override) in userOverrides.conditions {
            result[key] = override.value
        }
        return result
    }

    /// "字段是否被用户锁定"（UI 标记 / Recompute "保留" 状态判定）
    func isConditionManuallyOverridden(_ id: String) -> Bool {
        userOverrides.conditions[id] != nil
    }

    /// 字段最终来源："manual" 或具体 ruleRef
    func effectiveConditionSource(_ id: String) -> String? {
        if let override = userOverrides.conditions[id] {
            return "manual"
        }
        return ruleSnapshot.fields.conditions[id]?.source
    }

    /// 规则层原值（与 effective 区分；UI 混合态 tooltip 用）
    func ruleSnapshotConditionValue(_ id: String) -> String? {
        ruleSnapshot.fields.conditions[id]?.value
    }

    /// effective sampleID 与 substrateTags 不开 override，直接读 ruleSnapshot
    var effectiveSampleID: String? { ruleSnapshot.fields.sampleID?.value }
    var effectiveSubstrateTags: [String] { ruleSnapshot.fields.substrateTags.map(\.value) }
}
```

**理由**：消费者（Workbench / Library / Tests）已持有 sidecar 实例，零迁移成本；引入 `SidecarReader` 中间类型会增加 30+ 调用点改动面，零功能收益。

### 2.5 同一条求值链（pure function）

```swift
/// 规则求值：仅看输入数据，无 I/O，无状态。Import / Backfill / Recompute 均调此函数。
func buildRuleSnapshot(
    hints: ParsedFilenameHints,           // 已含 hintSources（见 §1.2）
    ruleSet: FilenameRuleSet,
    ruleSetFingerprint: String,
    ruleSetVersion: Int,
    evaluatedAt: Date
) -> SidecarRuleSnapshot

/// sidecar 合成：唯一持有 Import / Recompute 分支差异
func composeSidecarV2(
    base: ExistingOrNewSidecarContext,    // 包含 workflow / displayName / sourceFilePath / 既有 sidecar (可空)
    snapshot: SidecarRuleSnapshot,
    preserveUserOverrides: Bool,           // ← 唯一分支差异
    now: Date
) -> SpinLabFileSidecar
```

#### Import / Recompute 统一流程

| 步骤 | 内容 |
|---|---|
| 1 | 解析文件名 → `ParsedFilenameHints`（含 `hintSources`）|
| 2 | 读 `RuleLoader.LoadResult`（拿 ruleSet + fingerprint + version）|
| 3 | `buildRuleSnapshot(...)` |
| 4 | `composeSidecarV2(..., preserveUserOverrides: <bool>)` |
| 5 | 原子写 sidecar |

#### 分支差异

| 路径 | `preserveUserOverrides` |
|---|---|
| Import（新建 sidecar）| `false` |
| Recompute（已有 sidecar 升级 ruleSnapshot）| `true` |
| Backfill 旧 sidecar 存在并需 recompute | `true` |
| Backfill 旧 sidecar 缺失 / 历史从未 import | `false`（视同 Import）|

**唯一一行差**：bool 参数。AG5 结构性满足。

#### 非差异项（必须一致）

- 同一 parser 输入
- 同一 ruleSet / fingerprint / version 来源
- 同一 snapshot 构建逻辑
- 同一 sidecar 编码 + 写盘策略

#### 当前 `LibraryStore.backfillSidecars(in:, encoder:)` 退役

s3 落地时该函数语义统一为 Recompute（按钮 UI 文案 s4 改"Recompute from Rules"，见 §3.2）。`backfillMissingMeasurementSidecars` → `recomputeAllMeasurementSidecars`（保留旧函数名一个版本作 deprecation alias，5.1.8 删）。

## 3. Recompute 交互（s4 契约源）

### 3.1 软提示条（AG1）

#### 计算口径

```
staleCount = sidecars.filter { 
  $0.ruleSnapshot.ruleSetFingerprint != currentLoader.ruleSetFingerprint
}.count
```

- **不**用 ruleSetVersion 做 stale 判定（version 只展示）
- 比较 fingerprint 反映"内容变化"，零误报

#### 出现 / 消失

| 触发 | 行为 |
|---|---|
| 进入 Library / 切换 root | 计算 staleCount，>0 显示 |
| RulesSyncEngine 同步完成 / Rules Panel 保存 | 重算 staleCount |
| 用户点 `稍后` | 当前 root 记 `dismissedFingerprint = currentFp`；只要 currentFp 不变就不重显；规则下次内容变化 fingerprint 变即重显 |
| Recompute 应用成功 | 立即重算（通常归 0）|
| staleCount == 0 / 切出 Library / 加载失败无 fingerprint | 不显示 |

#### 视觉

Library 主内容区**顶部**横向 banner，低干扰（非 modal、非红色告警）：

```
ⓘ  {X} 个测量基于旧规则（v{old} → v{new}），可重算    [稍后]  [查看重算预览]
```

#### 详情页编辑/恢复对软提示条**无影响**

详情页编辑只动 `userOverrides`，不动 `ruleSnapshot`，因此 staleCount 与详情页操作完全解耦。

### 3.2 dry-run 预览面板（AG2）

#### 入口

| 入口 | 范围 |
|---|---|
| 软提示条 "查看重算预览" | 全 root（所有 stale sidecar）|
| Library 工具栏 `Recompute from Rules`（升级版 "Backfill Sidecars"）| 全 root（含未过期，显示 0 变化也合法）|
| 单 batch / sample 详情页 "Recompute 此 batch / sample" | 受限范围 |

三入口共用同一函数 `openRecomputePreview(scope:)`、同一面板。

#### 信息架构

```
┌─ Recompute Preview – {N} measurements ─────────────────────────┐
│ 顶部摘要区                                                      │
│   当前规则集: v{currentVersion}                                 │
│   当前指纹: {fingerprintPrefix8}                                │
│   将处理测量数: {N}                                              │
│   包含手动覆盖字段: {overrideFieldCount}                        │
│ ─────────────────────────────────────────────────────────────  │
│ 中部 diff 列表区（三组分组，见 §3.3）                            │
│ ─────────────────────────────────────────────────────────────  │
│ 底部 [取消]  [仅查看 (导出 CSV)]  [确认重算并应用]               │
└────────────────────────────────────────────────────────────────┘
```

#### 操作

| 操作 | 行为 |
|---|---|
| 取消 | 不写任何 sidecar；关闭面板；回原页面 |
| 仅查看 (导出 CSV) | 导出 diff，不写盘 |
| 确认重算并应用 | 批量写；进度条；完成 toast |

#### 异常处理

- 单 sidecar 写盘失败 → 计入"失败"统计，不中断；最终 toast "X 成功 / Y 失败，详情见 Logs"
- 单 measurement 规则求值抛错 → 该行 status = "解析失败"，跳过

### 3.3 字段级 diff 列结构 + no-op

#### 列结构

| 列 | 内容 |
|---|---|
| Measurement | sampleID / workflow / sourceFileName（截断 + tooltip 全相对路径）|
| Field Key | 例 `conditions.temperature` / `substrateTags[2]` / `sampleID` |
| Old Value | 旧 ruleSnapshot 值 |
| New Value | 新规则计算值（未命中显示 `∅`）|
| Source 旧 → 新 | 例 `tokenMap#0 → unitSuffix#0` / `migration.v1 → unitSuffix#0` |
| Status | 见下表 |

#### Status 分组（dry-run 三组）

| 组 | Status 标记 | 默认 |
|---|---|---|
| **第一组：将更新** | `将更新` / `迁移`（v1 legacy 来源）/ `新增` / `规则未命中`（旧有新无）| 默认展开 |
| **第二组：仅保留手动覆盖** | `手动覆盖保留`（来源列显示 `manual @ YYYY-MM-DD`）| 默认展开 |
| **第三组：无变化** | `无变化` | 默认折叠，提供"显示无变化"开关 |

#### 排序

一级：sampleID 升序 → 二级：workflow → 三级：sourceFileName → 四级：fieldKey

#### no-op 判定

`effective 值未变 AND source 未变` → 入第三组（折叠）。

#### 手动覆盖行禁止"强制覆盖"

第二组行**不**提供"强制覆盖此字段"勾选项 —— AG3 不可违反。要强制覆盖必须先在详情页 ↩️ "恢复规则默认"删除 override 条目。

### 3.4 详情页编辑 condition + userOverrides（AG3）

#### 进入编辑

Measurement 详情页 conditions 表格中每行右侧 hover 出现 `✏️`（未锁定）或 `↩️`（已锁定）。

- 点 ✏️ → 内联编辑：value 列变文本框 + Enter 确认 / Esc 取消
- 点 ↩️ → 弹确认 → 删除 `userOverrides.conditions[<id>]`

#### 写回语义

```
若新值 == ruleSnapshot.fields.conditions[<id>]?.value:
    删除 userOverrides 条目（避免冗余）
若新值 ≠ 规则值（或规则未填该字段但用户输入值）:
    写 userOverrides.conditions[<id>] = ManualValueOverride(value, "manual", now)
若新值为空字符串:
    允许，视为"手动覆盖空值"（落 userOverrides 条目）
```

#### "已手动修改" 视觉

- Source 列改为 🔒 + `手动编辑（YYYY-MM-DD）`
- 字段值前置小蓝点
- Hover → tooltip（§3.5）

#### "恢复规则默认" 边界

| 场景 | 行为 |
|---|---|
| ruleSnapshot 有该字段（含 legacy）| 删除 userOverrides → effective 回落到 ruleSnapshot.fields.conditions[<id>].value |
| ruleSnapshot 无该字段（规则演化后字段消失）| 弹确认 "此字段在当前规则集中不存在，恢复将清除该字段" → 确认后从 effectiveConditions 消失 |

#### Recompute 后保证

- 已存在 userOverride 条目**必须保留**（AG3）
- 若新规则值变化，字段仍显示手动值；tooltip 混合态显示"规则候选值已更新但被手动覆盖"

### 3.5 字段 source tooltip（AG6）

#### 触发

- Hover 200ms 显示，移开消失（**不**用 click，避免与 ✏️ 冲突）
- 触发区：condition 值文本 + 状态标签 + Source 列

#### 文案模板

| 场景 | 模板 |
|---|---|
| 来自规则 | `来自规则 {ruleRef}（v{ruleSetVersion} 规则集）` 例 `来自规则 rule:condition.temperature.unitSuffix#0（v12 规则集）` |
| 用户手动 | `手动编辑（{YYYY-MM-DD}）` 例 `手动编辑（2026-04-27）` |
| 混合态（手动覆盖 + 规则值变化）| 第一行 `手动编辑（{YYYY-MM-DD}）` 第二行 `当前规则候选值: {ruleValue}（{ruleRef}）` |
| v1 legacy 占位（前规则集时代）| `来自旧版 sidecar（前规则集时代）；点 Library 顶部"查看预览"可由当前规则集重算` |
| fallback / builtin（5 文件全没加载）| `来自内置兜底规则；规则文件未加载成功，运行于 fallback 模式` |
| 缺失（异常）| `来源未知（旧版本 sidecar）` |

#### 文案规则

- 时间统一 `yyyy-MM-dd HH:mm`（Asia/Singapore 本地化）
- ruleRef 直接展示原字符串（设计成可读）
- 不展示 ruleSetFingerprint（机器细节）

### 3.6 三入口状态机

#### 状态

- S0：无 stale
- S1：有 stale，软提示可见
- S2：预览面板打开
- S3：重算应用中
- S4：重算完成并刷新

#### 事件

- E1：规则集变化（fingerprint 变）
- E2：用户点软提示"查看重算预览"
- E3：用户点工具栏 `Recompute from Rules`
- E4：用户点面板"确认重算并应用"
- E5：用户点面板"取消"
- E6：详情页编辑 condition 保存
- E7：详情页"恢复规则默认"

#### 决策表

| 当前 | 事件 | 条件 | 下一 | 行为 |
|---|---|---|---|---|
| S0 | E1 | staleCount > 0 | S1 | 显示软提示 |
| S1 | E2 / E3 | always | S2 | 打开预览面板 + 计算 dry-run |
| S2 | E4 | apply 全成功 | S4 | 写 sidecar；刷新计数 |
| S2 | E4 | apply 部分失败 | S4 | 成功项生效；toast 列失败数 |
| S2 | E5 | always | S1 / S0 | 关面板 |
| S4 | internal | staleCount > 0 | S1 | 继续显示软提示 |
| S4 | internal | staleCount == 0 | S0 | 隐藏软提示 |
| 任意 | E6 / E7 | details page | 原态 + 局部刷新 | 写 / 删 userOverride；不动 ruleSnapshot；不刷 staleCount |

#### 不变量

- 任何 Recompute 都不动 userOverrides
- 任何详情页编辑都不动 ruleSnapshot
- staleCount 仅看 ruleSnapshot.ruleSetFingerprint，与详情页操作解耦
- 软提示入口与工具栏入口共用 `openRecomputePreview()`
