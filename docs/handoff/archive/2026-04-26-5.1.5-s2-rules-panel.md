## 持久化接口设计

### 保存流程（按 Save 按钮触发）

1. 收集分区当前内存草稿（结构化对象）
2. 结构校验：必填字段、enum 合法值、唯一性约束（详见各分区"校验规则"）
3. 语义校验（保存门禁）：
   - filename_parse: `conditionDefinitions[*].binding` 必须满足 canonical 路径（`unit_suffix` → `conditions.extraConditions.<id>` / `token_map` → `conditions.tokenMapRules.<id>`），UI 自动维护，用户改 id/kind 时实时回写 binding
   - filename_parse: `conditionDefinitions[*].id` 全局唯一
   - workflow_match: 同 `(workflowID, scope, type)` 的 matchValues 不可在跨规则间重复（同一 token 指向多个 workflowID 视为冲突，禁止保存）
   - substrate_normalization: `materialAliases.value` 必须存在于 `materialTokens`；`orientationAliases.value` 必须存在于 `orientationTokens`
   - 任何 regex 字段：编译校验
4. 校验失败：Save 按钮 disabled + inline 字段级错误高亮，**禁止保存**
5. 校验通过：编码 JSON（pretty + 稳定 key 顺序，降低 diff 噪声）
6. **Hash precondition**：读 runtime 文件当前内容 → SHA256，与本次打开窗口时缓存的 hash 比对
   - 一致 → 继续
   - 不一致 → 弹"外部修改检测：[Reload External Changes] / [Override With My Edits]"二选
7. 写入：临时文件 `<name>.tmp-<uuid>` → fsync → atomic rename 到目标
8. 写入后 decode 校验通过 → 调 `RuleLoader.reloadCached()` 让 Inbox/Workbench 即刻看到新规则
9. 触发 `RulesPersistenceHook.didPersist(sectionID, runtimeURL, schemaVersion, checksum)`（会话 2 内默认 no-op；会话 4 接同步逻辑）
10. UI 显示 `Saved at HH:mm:ss`；保存失败显示错误详情 + 保留草稿

### Hook 形态

```swift
struct RulesPersistenceHook {
    var didPersist: ((sectionID: String, runtimeURL: URL, schemaVersion: Int, checksum: String) -> Void)?
}
```

会话 2 内 `RulesManagementStore` 持有此 hook 字段（默认 no-op）；会话 4 由 AppEnvironment 注入实际的镜像写入闭包。

## State / FeatureStore 设计

### `RulesManagementStore`

```
@MainActor @Observable final class RulesManagementStore {
    // 路由
    private(set) var currentSection: RulesPanelSection
    private(set) var isWindowOpen: Bool

    // 6 分区草稿 + 脏标记
    private(set) var filenameParseDraft: FilenameParseRulesDraft?
    private(set) var sampleIDDraft: SampleIDRulesDraft?
    private(set) var workflowMatchDraft: WorkflowMatchRulesDraft?
    private(set) var substrateDraft: SubstrateNormalizationRulesDraft?
    private(set) var dirtySections: Set<RulesPanelSection>  // 实时反映 sidebar 圆点

    // 文件 hash 缓存（hash precondition 用）
    @ObservationIgnored private var openTimeHashes: [RulesPanelSection: String]

    // 入口操作
    func present()
    func selectSection(_ section: RulesPanelSection)
    func saveCurrent() -> SaveOutcome
    func discardCurrent()
    func reloadFromDisk(_ section: RulesPanelSection)

    // 会话 4 hook 注入点
    @ObservationIgnored var persistenceHook: RulesPersistenceHook?
}

enum RulesPanelSection: String, CaseIterable {
    case filenameParse, sampleID, workflowMatch, substrate
    case measurementTag, workflowIDPolicy   // 占位
}

enum SaveOutcome {
    case saved
    case validationFailed([FieldError])
    case externalConflict(externalChecksum: String)   // 触发 reload/override 选择
    case ioError(Error)
}
```

### AppState 接入

- `SpinLabAppState.rulesPanel: RulesManagementStore`（lazy，第一次 openWindow 时构造）
- AppState 不持任何 rule editing state；所有 dirty/save/reload 内聚 store
- Inbox `InboxOperationPanel` 的 Rules 按钮调 `openWindow(id: "spin-rules")`，Window 内 view 拿 `@Environment(SpinLabAppState.self)` 取 store

### Window 生命周期

- 单实例：重复点 Rules 按钮 raise 现有窗口（`@Environment(\.openWindow)` 默认行为）
- 关闭前：若 `dirtySections.isEmpty == false` → 拦截关闭事件，弹"Discard Changes / Cancel / Save All"三选
- 窗口可与 Inbox 主窗并列、不互相阻塞、不模态

4. **保存与 RuleLoader.reloadCached() 的并发**：reload 走异步路径时若 UI 同时在编辑下一个字段，可能短时不一致。建议保存 → reload → UI 状态切回 saved，期间 disable 全分区编辑（短暂 spinner）。
