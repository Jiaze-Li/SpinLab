### Commit 1 — Adj-10 fail-soft 收口（V-001 + V-007）

**触动文件**（2 个）：
- `Features/RulesPanel/RulesManagementStore.swift`
- `App/InboxArchiveApplyService.swift`

**RulesManagementStore（V-001）3 处修改 — 统一 Adj-10 模板**：

| 位置 | 现状 | 修复后（统一模板） |
|---|---|---|
| `loadAndCacheHash<T>` L424-432 | `guard fileExists, try? Data, try? decode else nil`，error 全吞 | 见下方"统一模板" |
| `loadFromDiskOnly<T>` L550-554 | 同上模式 | 同上模板 |
| `fileHash(at:)` L561-564 | `try? Data(contentsOf:) → nil`，**无 fileExists guard** | 同上模板（**F-6**：补 `fileExists` guard，使三处对齐） |

**统一模板（[HARD]）**：

```
1. FileManager.default.fileExists(atPath: url.path) == false → return nil（不日志，预期场景）
2. 否则 do { let data = try Data(contentsOf: url) } catch { logger.error("rules read failed: \(url.lastPathComponent) \(error)"); return nil }
3. 若需 decode：do { return try decoder.decode(T.self, from: data) } catch { logger.error("rules decode failed: ..."); return nil }
4. fileHash 路径在 step 2 后直接 return sha256Hex(of: data)
```

**InboxArchiveApplyService（V-007）2 处修改**：

| 位置 | 现状 | 修复后 |
|---|---|---|
| L133（`catch let error as InboxArchiveApplyError`）| `try? transaction.rollback()` | `do { try transaction.rollback() } catch { logger.error("rollback failed after apply error: \(error)") }`，外层 `throw error` 不变 |
| L151（`catch` 通用） | 同上 | 同上 |

**logger 验收口径（F-5）**：
- **生产**：使用 `AppLogger.error`（12a Accepted Boundary 已豁免 logging singleton）；必须保证 `AppLogger.error` 写入实际可在 stderr / Console.app 见到（实施前先验一次：跑一次 corrupt fixture，肉眼确认）
- **测试**：优先用既有 `AppLogger` sink 注入接口（如有）；若 `AppLogger` 无注入点 → 退到 11b s2 F-3 决议的 stderr 捕获 helper（`captureStderr { ... }`）。**禁止**测试依赖全局 logger 状态泄漏到其他测试

**logger 来源争议**：仍走 `AppLogger.shared`（12a Accepted Boundary）；不在本轮做 logger DI（那是 14a 范畴）。如评审认为应 init 注入 → 不接受（违反 §5 Out of Scope）。

**测试**：
- `V5112RulesPersistenceFailSoftTests.swift`：corrupt JSON 写入临时文件 → 调 load*/fileHash → 断言 nil + logger sink 收到 `error`；file-not-found 路径断言无日志
- `V5112InboxArchiveRollbackFailSoftTests.swift`：注入 throwing rollback stub → 断言外层抛原 apply error + logger 收到 rollback 错误

### Commit 2 — RulesPanel View 业务逻辑下沉（V-003 + V-004 + V-006）

**触动文件**（4 个 + RulesManagementStore 接收 V-004）：

**V-003 + V-006 合并下沉（F-1 + F-2）**：

新建 `MeasuringConditionRuleProjection`（stateless struct，pure）：

```
struct MeasuringConditionRuleProjection {
    struct NormalizationOutcome {
        let normalizedRules: [MapRule]
        let standardUnit: String?
        let didInvalidateStandardUnit: Bool
    }

    static func normalize(rules: [MapRule], standardUnit: String?) -> NormalizationOutcome
    static func standardUnitOptions(from rules: [MapRule]) -> [String]
}
```

- `normalize(rules:standardUnit:)` 吞下当前 V-003 binding setter L132-148 全部业务（normalize 单条 + 检查 standardUnit 是否仍在 `.unitSuffix/.regex` 输出中 + 失效则清空并设 `didInvalidateStandardUnit=true` + 用 nil standardUnit 重 normalize）
- `standardUnitOptions(from:)` 吞下当前 V-006 `MatchRulesEditor.unitSuffixOptions()` L261-274 全部业务（过滤 `.unitSuffix/.regex` op + trim + 去重）

**MeasuringConditionSection 改动**：
- `rulesBinding(condIdx:)` setter 调 `MeasuringConditionRuleProjection.normalize(...)`，写回 `d.conditionDefinitions[condIdx].matches = outcome.normalizedRules`、`d.conditionDefinitions[condIdx].standardization.standardUnit = outcome.standardUnit`、`if outcome.didInvalidateStandardUnit { showInvalidStandardUnitAlert = true }` — 三个写回 + 一个 alert 切换，零业务判断
- `MatchRulesEditor` 调用点：先调 `MeasuringConditionRuleProjection.standardUnitOptions(from: rules)` → 把结果作为参数传给 editor

**MatchRulesEditor 改动**：
- 删 `unitSuffixOptions()` 私有方法
- init 增加 `unitOptions: [String] = []` 参数（默认空数组，避免无关调用方被迫关心）
- `let unitOptions = unitSuffixOptions()`（L164）改成直接读 init 参数

**V-004 SampleIdentificationSection（L58-65）**：

- `RulesManagementStore` 新增 `func setBatchPrefixes(from specs: [FilenameRuleSet.MatchSpec])`，内部做 `specs.filter { $0.type == .startsWith }.map(\.value)`
- `batchSpecsBinding` setter 改为调 `store.setBatchPrefixes(from: specs)`，View binding 不做过滤

**测试**：

  - normalize：5 个 case（`$MATCH` + 空 standardUnit / `$MATCH` + 有 standardUnit + identity 行 / 非 `$MATCH` op / standardUnit 失效触发 didInvalidateStandardUnit / standardUnit 仍存在）

## 4. 风险预案

| 风险 | 表现 | 处置 |
|---|---|---|
| `MeasuringConditionRuleProjection` 接收下沉逻辑后 V-003 行为细节回归 | RulesPanel 编辑测量条件时归一化 / standardUnit 失效 alert 行为变 | Commit 2 必须跑 V515RulesPanel* 全套；任何 fail 不进 merge |
