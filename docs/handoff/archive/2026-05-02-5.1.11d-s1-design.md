**Tab enum 的判定规则（默认留 Workbench/V3）**：

UI tab identity 是 workflow-private presentation state，**默认不搬到 Domain**。Domain 承载 raw / physics 实体；tab enum 是 UI 选择状态，性质上更接近 ViewModel transient state。**只有当 grep 证明被非 UI UseCase 或跨 workflow domain contract 消费时才搬**。

判定命令（执行前跑）：

```
grep -rn "ThreeOmegaWorkspaceTab" Sources/ --include="*.swift" | grep -vE "(Features/Workbench/.*View|Features/Workbench/.*Store)" | grep -v "ThreeOmegaIngestionContracts.swift"
```

- 输出为空 → tab enum 仅被 UI 消费（View / Store） → **保留在 Workbench/V3**，不搬
- 输出非空 → 检查每个非 UI 引用方：
  - 是 UseCase / Service / Domain 相关 → 搬到 Domain
  - 是 Persistence contract（如 PackPayload）或跨 workflow domain → 搬到 Domain

- 跨 region 消费 / 多 UseCase 共享 → Domain

### 3.4 git 健康检查（修订口径）

本轮不是整文件 `git mv`，而是从 `ThreeOmegaIngestionContracts.swift` 和 `AHEDataParser.swift` 抽出多个 type 到新文件——git rename detection 不会稳定显示 100% rename，**不**用 rename 比例作为健康指标。

改用以下三步人工检查：

1. **diff 范围检查**：`git log --stat -1` 看每个 commit 的 diff 文件数 + 行数；预期表现是"原文件 N 行删除 + 多个新 Domain/*.swift 文件 X 行新增"，行数总和近似对称（删除行数 ≈ 新增行数）
2. **类型定义文本一致性**：用 `git show -1 -- <原文件>` 查看被删除内容，与 `git show -1 -- <新文件>` 查看新增内容做文本对照；除文件级 `import Foundation` 头外应字面一致
3. **算法/函数体零改动**：grep 每个 commit 是否触动了非搬迁文件（如 store / view / use case），如有则失败 — 本轮禁止改业务逻辑文件

如步骤 1/2 不对称（出现意外 modify），grep 检查是否漏改 import / 漏删原定义 / 类型签名意外改了 access modifier。
