## 1. 修复目标

| AS-ID | File | 风险 | 用户可见影响 |
|---|---|---|---|
| AS-36 | `UseCases/PersistMeasurementDataUseCase.swift` | High | corrupt 的 measurement_data.json 会被静默用空 store 覆盖，用户保存的指标可能被清空 |
| AS-35 | `UseCases/PersistChartArtifactUseCase.swift` | Med | corrupt 的 results_index.json 静默 rebuild，丢失原索引信息 |
| AS-38 | `UseCases/LoadLatestChartArtifactUseCase.swift` | Low | corrupt 的 manifest/index/image 静默返回 nil，"图加载失败"无诊断 |
| AS-21 | `UseCases/ThreeOmegaPlotRenderer.swift` | Med | render 失败返回空白图，UI 无法区分"数据问题"和"渲染失败" |
| AS-32 | `UseCases/XYRotationPlotRenderer.swift` | High | 同上 |
| AS-18 #1 | `Features/Workbench/ThreeOmegaWorkspaceStore.swift` | Med | rtQuery setter 内含 UserDefaults 写副作用，违反 @Observable 不可变 setter 规则 |
| AS-19 #2 | `Features/Workbench/ThreeOmegaWorkspaceView.swift` | Low | overlay 按钮 body 内含业务 filter，违反 View 只渲染 |

**修复后的统一行为契约（Adj-10 fail-soft pattern）**：

```
load 路径：
  if 文件不存在 → return nil（不记日志，预期场景）
  if 文件存在但读/解码失败 → stderr 记录文件路径 + 错误描述 → return nil
  其他成功路径不变

persist 路径：
  if write 失败 → throw（向上传播，不静默吞）
  if read+decode 旧索引失败 → stderr 记录 + 走 rebuild 分支（仅当 rebuild 是设计意图）
  关键：禁止用空 store / 空 index 静默覆盖磁盘上原文件

render 路径：
  if pipeline 失败 → 把错误带到调用方（throws 或 Result）；调用方记 stderr 后展示空图标 + 错误提示

setter 副作用：
  禁止在 @Observable 类的 setter / didSet 内做 UserDefaults / 文件 / 网络写
  搬到显式调用的方法（如 persistRTQuery()）或 Task 内

View 业务 filter：
  禁止在 View body 内做 .filter / .sorted（业务过滤逻辑）
  搬到 Store 计算属性，View 直接消费投影结果
```

## 2. 修复方案（按 commit 拆批）

### Commit 1 — Persistence fail-soft 收口（AS-36 / AS-35 / AS-38）

**触动文件**：

- `UseCases/PersistMeasurementDataUseCase.swift`
- `UseCases/PersistChartArtifactUseCase.swift`
- `UseCases/LoadLatestChartArtifactUseCase.swift`

**改法（对每条 try? 单独决策）**：

#### AS-36（High）

将 `execute` 内 `try? Data(contentsOf: measurement_data)` + `try? decoder.decode(WorkbenchMeasurementDataStore.self, ...)` 改为：

```
do {
    let data = try Data(contentsOf: measurement_data)
    store = try decoder.decode(WorkbenchMeasurementDataStore.self, from: data)
} catch CocoaError.fileReadNoSuchFile {
    store = WorkbenchMeasurementDataStore()  // 缺文件是预期初始化路径
} catch {
    FileHandle.standardError.write(Data("[PersistMeasurementData] read/decode failed at \(measurement_data.path): \(error)\n".utf8))
    throw AppError.io(...)  // 不静默用空 store 覆盖磁盘
}
```

**关键**：corrupt 文件场景必须 throw，不允许 silently 写空 store 把磁盘上原本可恢复的数据冲掉。

#### AS-35（Med）

`results_index.json` 的 read+decode 失败可以走 rebuild 分支（设计意图允许 rebuild），但必须 stderr 记录：

```
do {
    let data = try Data(contentsOf: results_index)
    index = try decoder.decode(WorkbenchResultsIndex.self, from: data)
} catch CocoaError.fileReadNoSuchFile {
    index = .empty
} catch {
    FileHandle.standardError.write(Data("[PersistChartArtifact] results_index corrupt, rebuilding: \(error)\n".utf8))
    index = .empty  // rebuild
}
```

#### AS-38（Low）

`LoadLatestChartArtifactUseCase` 多处 `try?`（path resolve / read / decode）。**path resolve 也必须纳入 do/catch**——只对明确 file-not-found / "没有 artifact" 语义返回 nil；其他 resolver error（malformed artifact path、permission、corrupt index 派生出的非法路径）必须 stderr 记录：

```
let path: URL
do {
    path = try resolver.resolve(...)
} catch ResolverError.notFound, CocoaError.fileReadNoSuchFile {
    return nil  // 没有 artifact 是预期
} catch {
    FileHandle.standardError.write(Data("[LoadLatestChartArtifact] resolver failed: \(error)\n".utf8))
    return nil
}

do {
    let data = try Data(contentsOf: path)
    return try decoder.decode(...)
} catch CocoaError.fileReadNoSuchFile {
    return nil  // 缺文件是预期
} catch {
    FileHandle.standardError.write(Data("[LoadLatestChartArtifact] failed at \(path.path): \(error)\n".utf8))
    return nil
}
```

**验收**：

- 三个文件内无任何裸 `try?` 折叠 corrupt 错误为 nil/empty
- corrupt 场景全部有 stderr 记录
- 缺文件场景仍返回 nil/empty（不破坏 Adj-10 预期）
- AS-36 corrupt 场景必须 throw（对比 AS-35/38 的 rebuild/nil 不同处置）

**commit 粒度**：single（三文件一 commit，主题"Persistence fail-soft 收口 per Adj-10"）

### Commit 2 — Renderer 错误传播（AS-21 / AS-32）

**触动文件**：

- `UseCases/ThreeOmegaPlotRenderer.swift`
- `UseCases/XYRotationPlotRenderer.swift`

**改法（接口定调：非 throwing `RenderOutcome` enum）**：

两个 renderer 当前的 `_render` 方法签名 `(...) -> (NSImage?, RenderWarning?)`（成功返回 image + 可选 warning，失败返回 (nil, nil)）。**统一改为非 throwing 返回 enum**：

```swift
enum RenderOutcome {
    case success(image: NSImage, warnings: [RenderWarning])
    case failure(reason: RenderFailureReason)   // pipeline 异常 / 输入数据无效 / 资源不足
}

private func _render(...) -> RenderOutcome
```

**为什么选非 throwing 而不是 throws**：renderer 是 deterministic computation，错误本身是有限可枚举的（pipeline 失败、配置非法、数据空），用值传递错误比 throws 让调用链更清晰；且 SwiftUI body / @Observable 类对 throws 不友好（不能用 try await）。

**Renderer 内部统一行为**：

- `_render` 内部捕获 `WorkbenchRenderPipeline.render` 抛错 → stderr 记录原因 → 返回 `.failure(reason)`，**不**直接 throw
- collectedWarnings（已有字段）在 success 路径继续收集 warnings；failure 路径不写 collectedWarnings（避免与 reason 重复）

**Public render 方法签名（保持兼容）**：

`renderRxxVsPhi` / `renderRxyVsPhi` / 3ω 各 tab renderer 的 public 方法签名**保持** `(NSImage?, RenderWarning?)` 不变；内部转换：

```swift
func renderRxxVsPhi(...) -> (NSImage?, RenderWarning?) {
    switch _render(...) {
    case .success(let image, let warnings):
        return (image, warnings.first)
    case .failure(let reason):
        return (nil, RenderWarning.pipelineFailure(reason))   // 永不返回 (nil, nil)
    }
}
```

**关键行为契约**：caller 永不收到 `(nil, nil)`；nil image 必伴随非 nil warning 携带失败原因。

**验收**：

- 两 renderer 中无 `try? WorkbenchRenderPipeline.render`
- `_render` 返回 `RenderOutcome`，failure 路径必含 reason
- public render 方法返回值永不为 `(nil, nil)`
- render 失败有 stderr 记录 + warning 带原因
- caller 不需要改动（API 兼容）

**注意**：本 commit 仅改"错误怎么传播"，不动 stateful renderer 的字段（AS-32 #16 持有可变状态归 14a meta 收敛）

**commit 粒度**：single（两文件一 commit，主题"Renderer 错误传播 + RenderOutcome enum + 失败带原因"）

### Commit 3 — Setter / View 副作用搬位（AS-18 #1 / AS-19 #2）

**触动文件**：

- `Features/Workbench/ThreeOmegaWorkspaceStore.swift`（AS-18 #1）
- `Features/Workbench/ThreeOmegaWorkspaceView.swift`（AS-19 #2）

**改法**：

#### AS-18 #1：rtQuery setter 副作用搬位

当前实现（违规）：

```swift
var rtQuery: String = "" {
    didSet { UserDefaults.standard.set(rtQuery, forKey: "...") }
}
```

改为显式持久化方法 + setter 不动 UserDefaults：

```swift
var rtQuery: String = ""

func updateRTQuery(_ newValue: String) {
    rtQuery = newValue
    persistRTQuery()
}

private func persistRTQuery() {
    UserDefaults.standard.set(rtQuery, forKey: "...")
}
```

调用方（View 的 binding）改为调 `updateRTQuery(_:)` 不直接赋 `rtQuery`。如果有多处直接赋值，必须全部改为方法调用——pre-commit hook 不会卡这个，需要手工 grep 确认。

#### AS-19 #2：ThreeOmegaAddOverlayButton 内 .filter 搬位

当前实现（违规）：

```swift
// in ThreeOmegaAddOverlayButton.body
let candidates = vault.packs(forWorkflow: .threeOmega).filter { 
    /* 业务过滤逻辑 */ 
}
```

改为 Store 计算属性：

```swift
// in ThreeOmegaWorkspaceStore
var availableOverlayPacks: [AnalysisPack] {
    vault.packs(forWorkflow: .threeOmega).filter { /* 业务过滤逻辑 */ }
}

// in ThreeOmegaAddOverlayButton.body
let candidates = store.availableOverlayPacks
```

**验收**：

- ThreeOmegaWorkspaceStore 的 `rtQuery` 字段 setter / didSet 无 UserDefaults 写
- ThreeOmegaAddOverlayButton.body 中无 `.filter` 业务表达式
- 行为不变（手动测一遍 RT 搜索框 + overlay 添加按钮）

**commit 粒度**：single（两文件一 commit，主题"Workspace setter/View 副作用搬位"）

## 3. 测试策略

### 3.1 单元测试

#### 3.1.1 stderr 捕获 helper（前置）

新建 `Tests/SpinLabAppTests/Helpers/StderrCapture.swift`（如不存在）：

```swift
final class StderrCapture {
    private let pipe = Pipe()
    private let originalFD: Int32
    
    init() {
        originalFD = dup(STDERR_FILENO)
        dup2(pipe.fileHandleForWriting.fileDescriptor, STDERR_FILENO)
    }
    
    func stop() -> String {
        pipe.fileHandleForWriting.closeFile()
        dup2(originalFD, STDERR_FILENO)
        let data = pipe.fileHandleForReading.readDataToEndOfFile()
        return String(decoding: data, as: UTF8.self)
    }
}
```

后续 stderr 断言用 `let cap = StderrCapture(); /* run */; let captured = cap.stop(); XCTAssertTrue(captured.contains("[PersistMeasurementData]"))`。

## 4. 风险预案

| 风险 | 表现 | 处置 |
|---|---|---|
| AS-36 改 throw 后 caller 没 catch | 上层崩溃或 task 异常 | 跑前 grep 所有 PersistMeasurementDataUseCase.execute 调用点；caller 必须 do-catch 并展示 user-facing alert |
| Renderer outcome 改类型导致 caller 大面积重写 | commit 2 体量超预期 | 优先选"保持返回值 + RenderOutcome enum"低侵入方案；如确需改 throws，回头评估是否拆 c/d |
| rtQuery setter 多处直接赋值未全部改为方法调用 | 持久化时机错位 | grep `\.rtQuery\s*=` 在整 Sources/ 找所有写入点；测试覆盖"修改 → 重启 → 值还在" |
| AS-19 .filter 的业务条件复杂 | 搬到 Store 时漏条件 | diff 对照 View body 原文 vs Store 计算属性；手动测候选列表数目一致 |
| stderr 在 release build 被吞 | 失败诊断丢失 | 后续如改 release logging 体系，FileHandle.standardError 形态便于全仓 grep 升级到统一 logger，本轮不强制 |
