# v5.3.6 曲线身份存储 — 实施 Handoff

> 状态：方案已收敛（单次调研，无需对抗）。  
> 背景：原定 v5.3.7 范围，Jack 决策并入 5.3.6。

## 0. 验收契约

实施完成后：

1. 用户给曲线改名后拖拽重排，名字跟着曲线走，不会错位。
2. 用户隐藏某个点的标签后拖拽重排，隐藏状态跟着曲线走。
3. Save Pack → Load Pack 后，改名和隐藏标签状态正确恢复。
4. 旧 AnalysisPack（5.3.6 之前存的）加载时：
   - 若 series 有 sampleID（5.3.6 存的包）→ 迁移为 sampleID 键，改名/隐藏状态保留。
   - 若 series 无 sampleID（更早存的包）→ 改名/隐藏状态静默丢失，行为与旧版一致（不崩溃）。
5. AHE / XYRotation 工作流的改名行为零变化（无 sampleID，走字符串化整数键路径）。

## 1. 核心设计

### 1.1 存储键改变

`TabRenderState` 两个字段 key 类型由 `Int` 改为 `String`：

```swift
// Before
var seriesLabelOverrides: [Int: String] = [:]
var hiddenPointLabelIndicesBySeries: [Int: [Int]] = [:]

// After
var seriesLabelOverrides: [String: String] = [:]
var hiddenPointLabelIndicesBySeries: [String: [Int]] = [:]
```

**两种合法 key 格式**（在同一 `[String: *]` 里共存）：

| 格式 | 来源 | 示例 |
|---|---|---|
| sampleID 字符串 | 3ω 等有 identity 的 workflow | `"GS01_Au#300"` |
| 整数字符串 | AHE / XY 等无 identity 的 workflow | `"0"`, `"1"` |

Codable 无需额外改动——Swift 的 `[Int: String]` 在 JSON 中本来就是 `{"0": "..."}` 格式，与新的 `[String: String]` JSON 格式相同。只改 Swift 类型声明即可，旧 JSON 天然能 decode。

### 1.2 渲染时翻译（sampleID/Int-string → series index）

`WorkbenchRenderPipeline.Input` 和各 Renderer 保持 `[Int: String]` 不变。翻译发生在以下两处：

**统一翻译函数**（建议放在 `TabRenderManager` 或单独 helpers 文件）：

```swift
/// 将 sampleID-keyed 或 Int-string-keyed 覆盖翻译为 index-keyed。
/// - 若 key 能解析为 Int → 直接用作 index（兼容旧格式 / 无 sampleID workflow）
/// - 否则 → 在 series 数组中查找 sampleID 匹配的 index
static func toIndexedOverrides<V>(
    _ stringKeyed: [String: V],
    series: [WorkbenchPlotSeries]
) -> [Int: V] {
    var result: [Int: V] = [:]
    for (key, value) in stringKeyed {
        if let idx = Int(key) {
            result[idx] = value
        } else if let idx = series.firstIndex(where: { $0.sampleID == key }) {
            result[idx] = value
        }
    }
    return result
}
```

### 1.3 迁移（旧包加载时一次性翻新）

在各 store 的 `restoreFromPack` 里，加载完 `TabRenderState` 后立即迁移：

```swift
static func migrateStateIfNeeded(
    _ state: inout TabRenderState,
    series: [WorkbenchPlotSeries]
) {
    // 若所有 key 均为纯整数字符串，说明是旧格式（5.3.6 之前），尝试转为 sampleID key
    let labelsAreIntKeys = state.seriesLabelOverrides.keys.allSatisfy { Int($0) != nil }
    if labelsAreIntKeys && !state.seriesLabelOverrides.isEmpty {
        var migrated: [String: String] = [:]
        for (key, value) in state.seriesLabelOverrides {
            if let idx = Int(key), idx < series.count, let sid = series[idx].sampleID {
                migrated[sid] = value
            }
            // 无 sampleID 的 series → override 静默丢失
        }
        state.seriesLabelOverrides = migrated
    }
    let hiddenAreIntKeys = state.hiddenPointLabelIndicesBySeries.keys.allSatisfy { Int($0) != nil }
    if hiddenAreIntKeys && !state.hiddenPointLabelIndicesBySeries.isEmpty {
        var migrated: [String: [Int]] = [:]
        for (key, value) in state.hiddenPointLabelIndicesBySeries {
            if let idx = Int(key), idx < series.count, let sid = series[idx].sampleID {
                migrated[sid] = value
            }
        }
        state.hiddenPointLabelIndicesBySeries = migrated
    }
}
```

## 5. 注意事项

- `WorkbenchPlotSeries` 的 `safe` subscript：Canvas 需要 `series[safe: idx]`，检查是否已有；若无，在 `WorkbenchResultContracts.swift` 里加 Array extension。
- `_rerenderActiveTab` 里的 detached Task 不能直接访问 `@MainActor` 的 `tabs`。和 5.3.6 的 seriesOrder 一样，需要在进 Task 前 capture `tabState.seriesLabelOverrides` 和 `hiddenPointLabelsBySampleID`，再在 Task 内用 fieldSweeps sampleID 顺序翻译。
- `buildPipelineInput` 已接受 `payload`，翻译点就在那里，最干净。各 store 里直接调用 `tabs.buildPipelineInput(payload:...)` 的路径只需改 TabRenderManager，其余不用动。
- 只有在 store 直接给 renderer 赋 `seriesLabelOverrides` / `hiddenPointLabelsBySeries` 的路径（即绕过 buildPipelineInput 直接 snapshot 的地方），才需要单独翻译。
