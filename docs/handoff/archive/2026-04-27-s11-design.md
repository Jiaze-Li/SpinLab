## 1. 范围

### 1.a UI 层

- 一个**统一匹配编辑器组件**（替代当前并存的 `MatchRuleEditor` + `WorkflowMatchRuleEditor`）。
  - 内核：type 选 + matchValues 编辑 + type 切换 matchValues 归一化。
  - 输出列：开关式插槽。Workflow.matchRules 关闭，Workflow.measurementTagRules / MeasuringCondition.tokenMapRules 开启。
  - regex 作为 type 选项之一保留（满足 AG5）。
  - **scope picker 删除**（详见 §1.b 的 scope 处置策略）。
- 三本子列表头折叠态显 id；展开后第一行 displayName，第二行起匹配区（满足 AG1）。

### 1.b 字段命名层

- **MeasuringCondition `label` → `displayName`** 的**完整闭环**（修 review blocker 2）：
  1. RulesPanel `MeasuringConditionFileDraft` 字段 rename。
  2. `FilenameRuleSet.ConditionDefinition` 的 `label?` 改为 `displayName?`，CodingKeys 兼容旧 `label` decode（双向兼容解码 + 单字段写出）。
  3. `ConditionFieldCatalog.labelMap` 的 `definition.label` 读取改为 `definition.displayName`（s11 后 RuleLoader 已解码出 displayName）。
  4. 内置 `builtInConditionLabels` 不动（与 schema 无关）。
  5. RulesBootstrapper 加 v2→v3 atomic + .bak backup 迁移（label → displayName）。
  6. 写出文件单字段（仅 displayName）；首启遇旧 label 容忍解码 → 迁移写出 displayName。

- **scope 删除**（修 review blocker 1）：
  - **求值算法**侧 `FilenameRuleSet` 的 `stringMatches` / `tokenMatches` / `compileMapRules` 路径**零行改动**。
  - **解码层**对 `MatchSpec.scope` 缺省容错：当前 `decode(..., forKey: .scope)` 必填，s11 改为 `decodeIfPresent(..., forKey: .scope) ?? .tokens`。这是 AG6 重新定义里的"最小兼容性扩展"——属解码扩容，不是求值改动。
  - 所有匹配区 schema（Workflow.matchRules、Workflow.measurementTagRules、MeasuringCondition.tokenMapRules）写出**不含 scope**。
  - 旧 runtime 文件（含 `"scope":"tokens"`）解码时静默忽略；MatchScope enum 暂留（仅老 decode 路径触达），不再被任何 UI / persistence 写出。
  - 范围扩展点已经过 review C1 证据验证：rg `"scope":"joined"` 在 Features/RulesPanel + Import/Rules + Tests 三目录 0 命中，扩展不撞真实使用。

### 1.c Store 流程骨架抽象

抽 `SectionPersistenceStrategy` per-section 策略接口。**契约必须显式覆盖以下能力**（修 review major C2）：

- `draft` 读写绑定。
- `runtime file URL`。
- `validate(draft, storeContext) -> [RulesPanelFieldError]`：保留各本业务校验差异。
- `postLoad(draft, storeContext)`：MeasuringCondition 用——刷新 conditionFieldIDs 列表。
- `postPersist(draft, storeContext)`：MeasuringCondition 用——dangling warning。

`storeContext` **必须**暴露以下能力（contract 化，非自由 API）：
- `dirtyDraft(section: RulesPanelSection) -> SectionDraft?`：跨 section dirty draft 视图，Workflow.validate 用它读 dirty 的 MeasuringCondition draft 拿 conditionFieldIDs。
- `persistedDraft(section: RulesPanelSection) -> SectionDraft?`：dirty 不在时回退磁盘读取。Workflow.validate 在 MeasuringCondition 没 dirty 时仍可校验 conditionFieldIDs。
- `crossSectionView() -> CrossSectionContext`：postPersist 钩子用，看 MeasuringCondition dangling 时拿 Workflow draft 视图。

Store 公共骨架接管：load + open hash 缓存 / external conflict compare / persist + RuleLoader reload + dirty 清理。三本各自的 saveX 方法退化为对应策略对象的 validate 实现。

### 1.d Section Shell 容器

抽 `RulesSectionShell<Content>`，承载：

- saveBar(top) + Divider + fallback ContentUnavailableView + Divider + saveBar(bottom)。
- onAppear syncFromStore 连线。
- 外部冲突 alert（Reload / Override / Cancel）。
- handleOutcome 分支（saved / validation / conflict / ioError）。
- **`saveErrors` 状态容器**（修 review major C3）：Shell 持有 `[RulesPanelFieldError]`，通过 `@Bindable` / `@Binding` 注入内容层。内容层既用它驱动 saveBar badge，也用它驱动 `.errorHighlight(...)`。这一条契约必须明示，避免重构后 badge / 行高亮不同步。

Section 内容层只需：
- section id（RulesPanelSection enum 值）。
- draft 类型 + scrollContent builder。
- section-specific 弹窗（Workflow add/delete sheet、MeasuringCondition delete confirm 留在内容层，不进 Shell）。

`RulesPanelView` 现有 switch 实例化分派**保持不变**——不引入 section descriptor 注入（属 5.1.6+ could 档）。

### 1.e 引擎层

- 求值算法零改动：`stringMatches` / `tokenMatches` / `compileMapRules` 不动一行。
- 解码层最小兼容性扩展：`MatchSpec.scope` 改 `decodeIfPresent ?? .tokens`；`ConditionDefinition.label` 改 `displayName?` + CodingKeys 兼容旧 label。
- **R1（review 提的）**："引擎零改动"原口径不可同时满足"删 scope 写出 + 求值不变"，因此 AG6 重新定义为"求值算法零改动 + 解码层最小兼容性扩展"。这一改动写入 handoff 是因为 **handoff 是合同**——s11-exec 不能因为这个口径变化在归档时被打回。

## 2. Schema 迁移 before/after

### 2.a Measuring Condition：v2→v3，label → displayName + tokenMap 删 scope

**before**：
```json
{
  "version": 2,
  "conditionDefinitions": [
    { "id": "device", "label": "Device", "kind": "token_map",
      "tokenMap": [
        { "match": { "scope": "tokens", "type": "equals", "matchValues": ["wafer"] }, "value": "wafer" }
      ] },
    { "id": "temperature", "label": "Temperature", "kind": "unit_suffix",
      "unitPattern": "^-?\\d+(?:\\.\\d+)?(?:K|k|C)$" }
  ]
}
```

**after**：
```json
{
  "version": 3,
  "conditionDefinitions": [
    { "id": "device", "displayName": "Device", "kind": "token_map",
      "tokenMap": [
        { "match": { "type": "equals", "matchValues": ["wafer"] }, "value": "wafer" }
      ] },
    { "id": "temperature", "displayName": "Temperature", "kind": "unit_suffix",
      "unitPattern": "^-?\\d+(?:\\.\\d+)?(?:K|k|C)$" }
  ]
}
```

### 2.b Workflow：v1→v2，matchRules + measurementTagRules 删 scope

**before**：
```json
{
  "version": 1,
  "workflows": [
    { "id": "MR", "displayName": "MR",
      "matchRules": [ { "scope": "tokens", "type": "equals", "matchValues": ["MR"] } ],
      "conditionFieldIDs": ["temperature", "field"] }
  ],
  "measurementTagRules": [
    { "match": { "scope": "tokens", "type": "equals", "matchValues": ["AMR"] }, "value": "AMR" }
  ]
}
```

**after**：
```json
{
  "version": 2,
  "workflows": [
    { "id": "MR", "displayName": "MR",
      "matchRules": [ { "type": "equals", "matchValues": ["MR"] } ],
      "conditionFieldIDs": ["temperature", "field"] }
  ],
  "measurementTagRules": [
    { "match": { "type": "equals", "matchValues": ["AMR"] }, "value": "AMR" }
  ]
}
```

### 2.c 迁移机制（共用）

- 解码：双向兼容（label / displayName 同时认；scope 缺失视为 tokens）。
- 写出：单字段（displayName）+ 不含 scope。
- RulesBootstrapper 增 step：atomic write + .bak backup + idempotent rerun（与 s9 RulesBootstrapper v1→v2 同款架构）。

## 5. 红线与边界

**红线（s11-exec 不许越界）**：
- 不动 FilenameRuleSet 求值算法（stringMatches / tokenMatches / compileMapRules）。
- 不抽第六本子，不动 ImportFilters / FilenameTokenization。
- 不引入 label / displayName **长期**双名共存（仅 exec.A 过渡期容忍，exec.B 必须清理）。

**真风险**：
- R1（已收）：AG6 口径调整需在 handoff 写明，否则 exec 归档会被打回——本 handoff §1.e 已写。
- R2（已收）：strategy contract 不够具体会让 exec 走偏——§1.c 已 contract 化。
- R3（已收）：Shell saveErrors 归属未定义会让 badge / highlight 不同步——§1.d 已写明 Shell 持有。

**已知非风险**：
- runtime 不存在 `scope:"joined"`（review C1 证据）。
- 三本 load/save/conflict 90% 同构（scout Q2）。
- 三 Section 顶层 body 完全同构（scout Q3）。
