## 4. RuleLoader 加载链改造方向

### 4.1 assembleRuleSet（5 文件装配）

旧 7 文件改 5 文件：

```
load(import_filters.json)  → ImportFiltersFile         → ruleSet.importRules
load(filename_tokenization.json) → FilenameTokenizationFile → ruleSet.tokenization + sources + channel
load(sample_identification.json) → SampleIdentificationFile → ruleSet.sampleId + substrateTagRules + sharedSubstrate
load(workflow.json) → WorkflowFile → ruleSet.measurementNameRules（构造）+ measurementTagRules + workflows 元数据
load(measuring_condition.json) → MeasuringConditionFile → ruleSet.conditions + conditionDefinitions + batch
```

`measurementNameRules` 在内存 ruleSet 中**仍存在**（向下游消费方暴露的字段），但来源是从 workflow.json 内 `workflows[].matchRules` 转换而成（每条 matchRule 转一条 MapRule with value=workflowID）。这保证 SpinLabRuleProvider 等下游消费侧 API 不变。

### 4.2 compositeHash（5 文件 + fail-fast）

- hash 输入按 5 本子侧栏顺序：import_filters → filename_tokenization → sample_identification → workflow → measuring_condition
- 算法不变（hashHex 累加 lastPathComponent + 文件内容）
- **缺文件统一处理**（D11）：缺任一本子文件 = fail-fast，落 RuleLoader fallback ruleSet + warning（warning 内容含"缺哪一本子"）；不允许"5 文件中 4 文件能加载就用部分"的隐式 fallback 分叉

### 4.3 Bundle fallback

`tryLoadFromBundle` 同步改 5 文件装配。Bundle.module 资源名同步改新 5 个名（旧名作为兼容期 grace 不再加载）。

## 5. 一次性迁移设计

### 5.1 迁移流程

`targetSchemaVersion: 2 → 3`。`RulesMigration.runIfNeeded()` 触发条件：

```
guard 已有 migration_state.rules_schema_version >= 3 + 5 新本子全在 → 跳过
否则执行迁移
```

迁移步骤：

1. 备份所有旧 7 + workflow_registry.json 到 `.backup-<ts>` 副本（库 import_rules 也备份；registry 段不会改但备份保险）
2. assembleNewSchema 读旧 → 转写 5 新本子内存对象（按 §2 映射；含 v1→v2 已支持的 substrate_rules.json 双步迁移）
3. 写 `.migration-tmp/` 5 新本子文件 → 逐文件 decode-verify
4. **任一 verify 失败**：中止，写 `migration_failed.json` 标记防止再次自动覆盖；备份保留；下次启动落 RuleLoader fallback；告知用户人工确认重试（D5 数据回滚优先）
5. 全部 verify 成功 → atomic rename 5 新本子到 final 位置
6. 写 `migration_state.json`（rules_schema_version: 3 + migratedAt + sourceFileSHA256）
7. 删旧 7 obsoleteFilenames（**不删** library_import_rules.json，registry 段保留）
8. 删 workflow_registry.json 历史 parentID 字段：读 → strip parentID → 重写（一次性净化；与 D4 显式 decode 兼容呼应）
9. 清理 `.migration-tmp`

### 5.2 "用完即抛"具体落点（D8）

**运行时加载链**（s4 必删）：
- `RuleLoader.swift` 内不再 decode 旧 7 文件名（assembleRuleSet 重写为 5 文件装配）
- 旧 Decodable types（SampleIDRulesFile / SubstrateNormalizationRulesFile / MeasurementTagRulesFile / WorkflowMatchRulesFile / 旧 LibraryImportRulesFile.import 部分）从代码删

**迁移模块 decoder**（s4 保留至下一次 schema 升级窗口）：
- `RulesMigration.assembleNewSchema` 内仍需读旧 7 文件 + workflow_registry.json 旧 parentID 字段
- 这些 decoder 在 `RulesMigration.swift` 内为内部使用，不暴露给 RuleLoader
- 删除时点：下一次 schema 升级（v4）或独立技术债清理任务（不在本期）

### 5.3 跨级迁移（v1 → v3）

如果 runtime 含 v1 旧名（filename_rules / substrate_rules / conditions_rules）：
- assembleNewSchema 内先用现有 v1→v2 逻辑（substrate_rules.json 内嵌 sharedSubstrate 检测）转换为 v2 内存对象
- 再用 v2→v3 逻辑（按 §2 映射）转换为 v3 5 文件
- 一次启动内串行完成
