## 7 文件新 schema

> 所有文件 bundle 与 runtime 字节级一致。每个文件顶层加 `version` 字段（从 `1` 起），用于将来 schema 演进判定。

### 1. `filename_parse_rules.json`（文件名解析）

顶层：`version` / `tokenization` / `sources` / `batch` / `channel` / `rotationHintRules` / `conditions` / `conditionDefinitions` / `measurementNameRules`

- `tokenization` = `{ separators, caseFold }`
- `batch` = `{ preferSampleId, fallbackPatterns }`
- `channel` = `{ aliases }`（如 `{"c1": "ch1", ...}`）
- `conditions` = `{ extraConditions, tokenMapRules, displayLabels }`
- `conditionDefinitions[]` = `{ id, label, kind ∈ {unit_suffix, token_map}, binding }`
- `measurementNameRules[]` = `{ match: {scope, type, value/values}, value }`

### 2. `sample_id_rules.json`（样品 ID）

顶层：`version` / `patterns: [string]`

### 3. `workflow_match_rules.json`（工作流匹配）

顶层：`version` / `rules`

- `rules[]` = `{ workflowID, scope, type, matchValues }`

### 4. `substrate_normalization_rules.json`（衬底归一化）

顶层：`version` / `substrateTagRules` / `sharedSubstrate`

- `substrateTagRules[]` = `{ match, value }`
- `sharedSubstrate` = `{ tokenSeparators, originStandaloneTokens, originContainsTokens, treatmentKeywords, materialTokens, materialAliases, materialDisplayNames, orientationTokens, orientationAliases, orientationPattern }`（10 子字段必须全保留，不可压缩）

### 5. `measurement_tag_rules.json`（测量标签）

顶层：`version` / `rules`

- `rules[]` = `{ match, value }`

### 6. `workflow_id_policy.json`（工作流 ID 策略）

顶层：`version` / `preferredAlphabet` / `fallbackPrefix`

### 7. `library_import_rules.json`（Library / Excel 导入规则）— 新

顶层：`version` / `registry` / `import`

- `registry` = `{ sampleHeaderAliases, excludedSheetNames, sampleCellSeparators, batchHeaderAliases, substrateHeaderAliases, numericKeyAliases, substrateMaterialTokens, substrateProcessingKeywords, metadataLookupAliases }`
- `import` = `{ supportedFileExtensions, ignoredFileExtensions }`

## 一次性迁移机制

### 触发时机
应用启动期 `App.init` 阶段，先于 `RuleLoader` 首次访问。

### 已迁移判定（双判定，AND 关系）
- 判定 A：`~/Library/Application Support/SpinLab/config/migration_state.json` 存在且 `rules_schema_version == 2`
- 判定 B：runtime 目录下 7 个新 schema 文件全部存在且能 decode 成对应类型

### 迁移输入源优先级
1. runtime 旧文件（若存在）
2. bundle 旧文件（含本次 git status 里 3 个未提交 bundle 改动）
3. 旧 sidecar 叠加语义（仅迁移窗口内临时使用）

### 执行步骤（原子化）
1. 在 runtime config 目录创建临时目录 `.migration-tmp/`
2. 对所有将被覆盖/删除的旧文件创建 `.backup-<ts>`（单次迁移快照）
3. 用旧 decoder 读取旧文件 + 应用旧 separated-override 叠加，组装成内存中的统一规则对象
4. 把统一对象按新 schema 拆成 7 个 JSON 落到 `.migration-tmp/`
5. 每个新文件写入后立即回读 + decode 校验
6. 7 个全部 OK → 原子 `rename` 到正式文件名
7. 写 `migration_state.json`（含 `rules_schema_version=2` / 迁移时间戳 / 源文件 SHA256 摘要）
8. 删除旧文件（`filename_rules.json` + 4 个旧 sidecar；`workflow_id_policy.json` 已是新结构只补 `version` 字段）
9. 启动后续 `RuleLoader` 走新路径

### 失败回滚
- 任何步骤失败立即中止，**不进入删旧步骤**
- 若正式文件已被部分替换 → 用 `.backup-<ts>` 恢复 + 删除 `migration_state.json` + 清残片 → 应用按旧路径继续启动（仅本次）
- 下次启动可再次尝试迁移

### 迁移后清理
- 同 commit 内删除旧 decoder 路径（FilenameRuleSet 的 nested-shared / inbox / library 兼容 decode）
- 同 commit 内删除 `SeparatedOverrideReader.swift` + `applySeparatedOverrides` + `conditions_rules.json` 半成品分支
- 旧路径不在运行期保留任何 alive code

### C2 — 原子提交：新 schema + 一次性迁移 + 新 loader + WorkflowID 路径统一

**标题**：`feat(rules-runtime): switch to canonical 7-file schema with one-shot migration and unified workflow-id policy path`

**scope（必须原子，禁止拆）**：
- 落 7 个新 schema bundle 文件
- 添加 `RulesMigration.swift` + `RulesMigrationState.swift` 一次性迁移器

- 删 `SeparatedOverrideReader.swift`
- 改 `WorkflowIDAllocator.swift`：`WorkflowIDPolicyLoader` 改走 `RulesConfigPaths.workflowIDPolicyURL`，迁移时 seed 一份到 runtime
- 改 `RulesConfigPaths.swift`：删 `conditionsRulesURL`；加 7 文件 URL + `migrationStateURL`

**为什么必须原子**：如果先删 `applySeparatedOverrides`、后落新 schema → 中间 commit 启动后，runtime 还是旧分文件但 loader 不读 sidecar → override 全丢，bisect 中间态崩溃。

**验收**：

- 已有 4·25 状态机器启动 → 触发迁移 → 7 文件落地 → backup-ts 文件存在 → 旧文件被删 → 二次启动跳过迁移

- `sharedSubstrate` 全 10 子字段在迁移后逐一对账（迁移代码里加 assertion / log）
