## 拍板要点（对抗收敛后）

### 1. v4 Schema（双方一致 + Codex 略调整）

```json
{
  "version": 4,
  "sampleId": { "batchPrefixes": [String] },
  "substrate": {
    "materials":    [SubstrateEntry],
    "treatments":   [SubstrateEntry],
    "orientations": [SubstrateEntry]
  }
}

SubstrateEntry := {
  "displayName": String,
  "matches":     [{ "type": "equals" | "contains", "value": String }]
}
```

- displayName 自匹配 = compile 阶段 inject implicit `equals(normalize(displayName))` probe，运行时不再特判
- matches[] OR 关系
- 默认 token-scope（每条 match 在切碎后 token 列表上逐块匹配）
- 同一列表内 displayName 唯一约束，跨列表允许重复

### 2. Swift 类型设计

- **draft model**：`SampleIdentificationFileDraft.SubstrateConfig` 改 v4 形态；`SubstrateEntry: Codable, Identifiable`，`id: String { displayName }`（仅给 ForEach 用，不持久化）
- **compiled model**：`FilenameRuleSet.SubstrateConfig` 同形态；`CompiledRules` 删除 `substrateTagRules / materialByToken / treatmentByKeyword / orientationCanonical`，新增 `substrateMaterialEntries / substrateTreatmentEntries / substrateOrientationEntries: [CompiledSubstrateEntry]`（命名沿用既有 CompiledRules 字段无 `compiled` 前缀风格）
- **MatchSpec 复用决策**：不复用。新建独立 `SubstrateEntry.Match` 类型仅 substrate 域用。`FilenameRuleSet.MatchScope / MatchType / MatchSpec / MapRule` 保留不动（measurementTagRules / channel / conditions 仍用）
- **`FilenameRuleSet` 顶层 `substrateTagRules: [MapRule]` 字段直接删除**（不留 deprecated；v3 JSON decode 走 decodeIfPresent，schema 删字段不影响）

### 3. Origin treatment 识别（采 Codex 方案，脱离硬编码）

不再依赖 `treatment.id == "o"`。

- compile 阶段判定 origin treatment：`SampleSemanticDescriptor.normalizedProcessingTokenForRules(entry.displayName) == "o"`，或任一 `matches[].value` 经同函数映射后为 `"o"`
- 命中则把 `displayName` 加进 `compiled.originTreatmentDisplayNames: Set<String>`
- `RegistrySubstrateRuleBook.init` 改读这个集合，不读 `treatment.id`

### 4. Normalize 规则（统一）

`normalizeForSubstrate(token)` = `uppercase + 删空格/_/-/(/)/（/）`，与 FileRoutingSemanticRules.normalizeToken 一致。所有 substrate 比对前先归一化（解决 v3 中部分 lowercased 部分 uppercased 的不一致）。

### 5. v4 shipped sample_identification.json 重写（13 条旧 substrateTagRules 去向）

```json
{
  "version": 4,
  "sampleId": { "batchPrefixes": ["PN", "PT", "SL"] },
  "substrate": {
    "materials": [
      {"displayName": "STO",   "matches": [{"type":"contains","value":"STO111"}, {"type":"contains","value":"STO001"}]},
      {"displayName": "NGO",   "matches": []},
      {"displayName": "MAO",   "matches": []},
      {"displayName": "MgO",   "matches": [{"type":"equals","value":"MGO"}]},
      {"displayName": "Al2O3", "matches": [{"type":"equals","value":"AL2O3"}]},
      {"displayName": "Si",    "matches": [{"type":"equals","value":"SI"}, {"type":"equals","value":"ONSI"}]},
      {"displayName": "poly-SiO2 on Si", "matches": [{"type":"equals","value":"POLY-SIO2"}, {"type":"equals","value":"POLY-SIO2 ON SI"}]}
    ],
    "treatments": [
      {"displayName": "HF",    "matches": [{"type":"contains","value":"hf"}]},
      {"displayName": "baked", "matches": [{"type":"contains","value":"bake"}]},
      {"displayName": "b",     "matches": [{"type":"equals","value":"b"}]},
      {"displayName": "o",     "matches": [{"type":"contains","value":"origin"}, {"type":"contains","value":"original"}]}
    ],
    "orientations": [
      {"displayName": "001",  "matches": [{"type":"equals","value":"100"}, {"type":"contains","value":"STO001"}]},
      {"displayName": "111",  "matches": [{"type":"contains","value":"STO111"}]},
      {"displayName": "110",  "matches": []},
      {"displayName": "0001", "matches": []}
    ]
  }
}
```

13 条对照（最终拍板版）：

| 旧 rule | 新表 / 行 / match |
|---|---|
| #1 HF | Treatments/HF + contains "hf"（含 displayName 自匹配） |
| #2 BAKE/BAKED | Treatments/baked + contains "bake"（覆盖 BAKED） |
| #3 ORIGIN/ORIGINAL | Treatments/o + contains "origin"/"original" |
| #4 STO111 → "STO 111" | Materials/STO contains "STO111" + Orientations/111 contains "STO111"（**接受拆分双 tag**：["STO","111"]，已在 ROADMAP 设计纪要明确接受） |
| #5 STO001 → "STO 001" | 同 #4 |
| #6–#10 | displayName 自匹配（STO/NGO/111/001/o） |
| #11 equals [O] → "o" | normalize 后等价 displayName 自匹配，省略 |
| #12 MgO | Materials/MgO 自匹配 + equals "MGO" |
| #13 b → "b" | **保留独立 Treatments/b 行 + equals "b"**（保真旧 tag 输出，不合并进 baked；防 Library 库存数据漂移） |

### 6. v3 → v4 迁移规则

- **B.1 sampleId.patterns → batchPrefixes**：正则识别 `^(p1|p2|...)\d+$` 形态（含 `^(?:...)` 非捕获），prefix 必须 `^[A-Za-z0-9_-]+$`；非法 pattern + 非法 prefix 各写 warning + 丢弃；去重（稳定顺序）
- **B.2 materials**：tokens + aliases 转 equals matches；displayName 空则 fallback id + warning；`(type, value)` 大小写不敏感去重；丢弃 id
- **B.3 treatments**：standaloneTokens → equals；containsTokens → contains；**keywords → contains（保守宽松，避免漏命中）**；displayName 空则 fallback id + warning；去重；丢弃 id
- **B.4 orientations**：每行 `displayName = row.id`，tokens + aliases 转 equals（除与 row.id 同值者跳过）；丢弃 `pattern` 字段 + warning
- **B.5 substrateTagRules**：全量丢弃；逐条写 warning + 摘要 warning（"removed; equivalent behavior now comes from treatments/materials/orientations matches"）
- **B.6 migration_state gate**：从 `rules_schema_version >= 3` 升到 `>= 4`；写回 4；幂等三态
  - state<4 且 sample_identification.version<4 → 执行迁移
  - state<4 但 sample_identification 已 v4 → 写 state=4，跳过内容改写
  - state≥4 → no-op
- **备份**：原文件备份到 `~/Library/Application Support/SpinLab/config.backup.<timestamp>/`

### 7. 替代 substrateTags(from:) 新生成器

```text
substrateTags(from tokens) = 
    遍历 [materials, treatments, orientations] in 顺序
        每 entry 检查 anyTokenHits(entry.probes ∪ implicitDisplayNameEquals)
        命中 → append entry.displayName
    return （由调用方 uniquePreservingOrder 去重）

probe matches:
    equals:   normalize(token) == probe
    contains: normalize(token).contains(probe)
```

- compile 阶段为每个 entry 注入 `implicit equals(normalize(displayName))` 进 `equalsKeysNormalized: Set<String>`
- 每条 contains match 进 `containsNeedlesNormalized: [String]`
- 顺序固定：materials → treatments → orientations，表内按 JSON 顺序
- 不复用 `collectMatchValues / firstMatchValue / matches(rule:)`（旧 MapRule 形态，留给 measurement/workflow/condition 用）

## 风险点 watchlist

### H.1 复合 token 拆 tag（**接受的行为变化**）

旧 `STO111 → ["STO 111"]`（单 tag），新 `STO111 → ["STO", "111"]`（双 tag）。
- 已在 ROADMAP 设计纪要明确接受
- LibraryModels.substrateTags 持久化值变化（旧库存不动，下次 import / sample edit 后刷新）
- LibraryView 详情页显示从 "STO 111" 变 "STO, 111"

### H.2 Treatment "b" 保真（采 Codex 方案）

保留独立 Treatments/b 行（equals "b"），不合并进 baked。防 Library 库存里旧 "b" tag 与新算法漂移。

### H.3 origin treatment 识别脱耦（采 Codex 方案）

用 SampleSemanticDescriptor.normalizedProcessingTokenForRules 语义识别。displayName 改名后只要语义不变（仍能映射到 "o"）则识别仍生效。
- 长期改进（s10 之外）：origin token 检测从 substrate 模块独立出来，作单独配置
- MVP 缓解：迁移完成后给 migration_state 写一条 hint warning（"如修改 Treatments 表中 origin 行的 displayName，origin token 检测可能失效"）

### H.4 mirror / reverse-sync 启动顺序（采 Codex 发现）

s6 落地的 RulesSyncEngine 做 dual-write + reverseSyncOnStartup。如果用户已有 v3 mirror，启动时 reverse-sync 把 v3 mirror 写回 source，而 RulesBootstrapper 期望 source 是 v4 → 冲突。

**规避**：
- RulesBootstrapper 必须在 RulesSyncEngine 启动**之前**完成 v3→v4 迁移
- 或在 reverse-sync 路径加 v4 decode gate（mirror 是 v3 形态时 → 标记 degraded + warning，不写回 source）
- 实施时确认 startup 顺序：app 启动 → RulesBootstrapper.runMigrations() → RulesSyncEngine.start()

### H.5 keywords 字段消费路径

v3 `treatment.keywords` 在 compileSubstrateConfigNeedles 编译进 `treatmentByKeyword: [String: TreatmentDefinition]`，但 dict 消费方需 grep 验证。当前**采保守 contains 策略**（H.5 keywords → contains），如 grep 验证后发现 dict 消费方期望 token equals 严格匹配 → 实施时调整为 equals。

### H.6 V210 / V214 / V223 等历史回归

历史 fixture 用 v1/v2 形态，理论 RulesBootstrapper 串联迁移自动升 v4。但 .swift inline fixture 可能没走 bootstrapper，需 sweep。**实施时第一步**：grep 旧 schema 字段 (`substrateTagRules / orientations.pattern / sampleId.patterns / standaloneTokens`) 在 Tests/ 内 inline 出现的位置，手动升 v4。

### H.7 swift test 全跑成本

每 commit 用 `--filter V515` + `--filter "V210|V215"`；最后整体 ship 前一次完整 run（360s+），不重复跑全套。

### H.8 specs/06 Separation Rules 合规

C1+C2+C3 合并属 logic/storage 域内，未跨 UI；C4 独立 UI ✓。如果 C1 完成后 build 绿（FilenameRuleSet.substrateTags 仍存在但读不到 substrateTagRules 字段——可能挂），合并不可避免。**实施时第一步**：跑 swift build 确认 C1 完成后是否 build 绿，决定 C1+C2+C3 合并还是串行。

### H.9 RegistrySubstrateRuleBook.materialTokens 消费方式

新逻辑下 materialTokens 含 displayName + 所有 match.value（lowercased），旧仅含 v3 material.tokens。如 hasStandaloneOriginToken / resolvedSubstrate 假设 materialTokens 仅"标准材料 token"，可能行为漂移。已列入实施前 grep #3。
