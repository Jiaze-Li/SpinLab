## 3. K1 / K2 / K3 决策

### K1 — UI 路径选择
**(a) 退役 Workbench 老路径**（Jack 拍板：方向 1）：删除 `WorkflowRegistryView` 编辑能力 + 退役 `WorkflowRegistryStore`，唯一编辑入口收到 Inbox 旁的规则面板「工作流」section。

**Workbench 配置页（`.registry` 路由）保留并改造为只读形态**（方向 1，非 Codex 原建议的"删配置页直接落首个 workspace"方向 2，理由：用户跳转链太长、"看见所有工作流"是 Workbench 的合理职能）：

- **左侧**：工作流列表（同现状），点击切到该工作流的 workspace
- **右侧**：选中工作流的只读摘要 — 显示 id / displayName / 条件字段清单 / 匹配规则清单 / 子标签规则清单
- **右侧底部**：一个文字按钮「在规则面板编辑此工作流」，点击切到 Inbox 主区 + 规则面板 + 工作流 section + 自动选中当前工作流行（如果跨区联动复杂，第一版可降级为"切到规则面板 + 工作流 section"，不强制定位行）
- **删除**：Add Workflow / Remove / 显示名输入框 / Parent ID 输入框 / 条件字段编辑器（FlowLayout 改条件标签 + 增删 chip）
- **保留**：左侧列表的选中态、点击切 workspace 路由

### K2 — RulesMigration 退役范围
**部分保留**：删除 migration_state 状态机 / oldFilenames 扫描清理 / enrichedWorkflowData / stripParentIDFromRegistry；新建 `RulesBootstrapper` 提供 `seedMissingRuntimeFilesFromBundleIfNeeded()`，仅在 5 文件缺失时按单文件原子写补齐。

### K3 — outer registry 升级路径
1. 启动时检测 `~/Library/Application Support/SpinLab/workflow_registry.json` 存在
2. decode `[WorkflowDefinition]`（失败 → 备份 + 跳过合并 + log error，不阻断）
3. 合并到 `config/workflow.json` 的 `WorkflowFileDraft`：
   - **同 ID（caseInsensitive）**：仅覆盖 `displayName` + `conditionFieldIDs`；**保留** `matchRules` + `measurementTagRules`
   - **registry-only ID**：append 新 entry，强制 `matchRules = []`、`measurementTagRules = []`，避免引入路由副作用；`displayName` + `conditionFieldIDs` 取 registry 值
4. 先写 `config/workflow.json.backup-<ts>` → 原子写新内容
5. 重命名 outer registry 为 `workflow_registry.json.backup-<ts>` 并 log 退役
6. 失败兜底：任一步失败不覆盖 `config/workflow.json`，保留原 outer 文件，写 error log，app 继续启动

## 5. 启动顺序硬约束

```
SpinLabApp.init()
  ├─ RulesBootstrapper.seedMissingRuntimeFilesFromBundleIfNeeded()  ← C4 新增
  ├─ WorkflowRegistryRetirementService.runIfNeeded()                 ← C2 新增（一次性）
  ├─ RulesSyncEngine.reverseSyncOnStartup() (existing s6)
  ├─ RuleLoader.reloadCached()
  └─ stores 初始化（含 WorkbenchFeatureStore 用 WorkflowDefinitionStore.load()）
```

顺序错位风险：
- bootstrap 在 reverseSync 之后 → 反向同步可能写空文件
- retirement 在 RuleLoader 之后 → RuleLoader 缓存的 workflow.json 是合并前的，需要 invalidate
