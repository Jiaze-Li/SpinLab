## 一、Registry Rules 结构现状

### 1.1 数据格式

`FilenameRuleSetSchema.RegistryRules`（Codable，7 个字段）：

| 字段 | 类型 | 消费方 |
|------|------|--------|
| `sampleHeaderAliases` | `[String]` | `RegistryLookupRuleBook` |
| `excludedSheetNames` | `[String]` | `RegistrySheetFilter.shouldSkipSheet()` |
| `sampleCellSeparators` | `String` | `RegistryLookupRuleBook`（与 tokenization.separators 合并）|
| `batchHeaderAliases` | `[String]` | `LibraryRegistryParser` |
| `substrateHeaderAliases` | `[String]` | `LibraryRegistryParser` |
| `numericKeyAliases` | `[String: [String]]` | `LibraryRegistryParser` 数值标签提取 |
| `metadataLookupAliases` | `[String: [String]]` | `ExtensionPoints.RegistryMetadataAliasBook` |

### 1.2 加载路径

```
Sources/SpinLabApp/config/library_import_rules.json
    → RuleLoader.swift:256-260 (LibraryImportRulesFile decode)
    → ruleSet.registry = file.registry
    → SpinLabRuleProvider.registryRules()
    → LibraryRegistryParser / RegistryLookupRuleBook / ExtensionPoints
```

`library_import_rules.json` 是 `registry` 段的**唯一 JSON 来源**。

### 1.3 死代码字段（JSON 存在但从未解码）

`library_import_rules.json` 的 `registry` 段包含两个字段，不在 `RegistryRules` struct 中，JSON decoder 静默忽略：

- `substrateMaterialTokens: [String]` — 旧格式 token 列表，已被 `SubstrateConfig.materials` 取代
- `substrateProcessingKeywords: [String: [String]]` — 旧格式处理关键词，已被 `SubstrateConfig.treatments` 取代

**5.4.1c 动作**：从 `library_import_rules.json` 中删除这两个字段。

## 二、Fallback 清单（全部需要退役）

### 2.1 SpinLabRuleProvider — registry nil fallback

**位置**：`Sources/SpinLabApp/Import/Rules/SpinLabRuleProvider.swift`

```swift
// SpinLabRuleProvider.registryRules()（约第 36 行）
ruleSet().registry ?? fallback.registry!

// InlineRuleProvider.registryRules()（约第 68 行）
cachedLoadResult.ruleSet.registry ?? FilenameRuleSet.fallback().registry!
```

**触发条件**：`library_import_rules.json` 文件不存在或 decode 失败时，`ruleSet.registry` 为 nil，静默返回 hardcoded 默认值。

**退役方案**（5.4.1c）：
- `library_import_rules.json` 已在 bundle 中，RulesSyncEngine 保证 app support dir 也有拷贝
- 若 `ruleSet.registry == nil`，返回可观测的 `.incomplete` 状态或 throw，不再 fallback
- 协议 `SpinLabRuleProviding.registryRules()` 改为 `registryRules() -> FilenameRuleSet.RegistryRules?`，调用方改为处理 nil

### 2.2 RegistryMetadataAliasBook — metadataLookupAliases fallback

**位置**：`Sources/SpinLabApp/Extensions/ExtensionPoints.swift`（约第 15-31 行）

```swift
private static let fallbackAliases: [RegistryMetadataField: [String]] = [
    .batch: ["Batch", "BatchID", "Batch Name", "编号"],
    .sample: ["Sample", "SampleID", "Sample Name", "样品"],
    ...
]

static func aliases(for field: RegistryMetadataField) -> [String] {
    if let configured = ruleProvider.ruleSet().registry?.metadataLookupAliases[field.rawValue],
       !configured.isEmpty {
        return configured
    }
    return fallbackAliases[field] ?? []  // ← 退役目标
}
```

**触发条件**：`metadataLookupAliases` 缺 key 或空数组时静默返回 hardcoded 别名，用户不知道。

**退役方案**（5.4.1c）：
- 删除 `fallbackAliases` 静态属性
- `aliases(for:)` 改为：若 configured 为空，返回 `[]`（不填充）
- 调用方 `AMRPHEMetadataExtension.applyRegistryMetadata()` 在 `[]` 时跳过字段赋值（已有逻辑兼容）

## 三、Substrate 单一真相

### 3.1 现状（三条漂移路径）

| 来源 | 格式 | 状态 |
|------|------|------|
| `sample_identification.json` §substrate | `SubstrateConfig`（SubstrateEntry + matches[]）| **运行时真相**，RuleLoader 解码 |
| `FilenameRuleSet.fallback().substrateConfig` | `SubstrateConfig`（同格式）| **hardcoded 副本**，已与 JSON 漂移（已登记 TASK_BOARD）|
| `library_import_rules.json` §registry.substrateMaterialTokens/substrateProcessingKeywords | 旧 token 格式 | **死代码**，从未被解码 |

### 3.2 漂移具体内容

`sample_identification.json` 现有 materials：STO / NGO / MgO / + 其他  
`FilenameRuleSet.fallback().substrateConfig.materials`：STO / NGO / MAO / MgO / Al2O3 / Si / poly-SiO2 on Si（含 STO001/STO111 方向感知 match）

两者 materials 列表结构和 match 规则已不同步。

### 3.3 修复方案（5.4.1c）

1. 以 `sample_identification.json` 为单一真相
2. 将 `FilenameRuleSet.fallback().substrateConfig` 改为 `nil`（不再提供 substrate fallback）
3. `SpinLabRuleProvider.substrateConfig()` 若 nil 即 nil，调用方已处理 optional
4. 从 `library_import_rules.json` 删除 `substrateMaterialTokens` / `substrateProcessingKeywords`
5. 补 parity test：`sample_identification.json` decode → substrate materials 名称集合 与 运行时消费方预期一致
