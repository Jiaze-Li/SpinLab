# 5.7.3 s1-design — Swift 代码登记 workflow

## 0. 目标 & 边界（不可被后续重新论证）

> 新增 `Sources/**/*.swift` 走 SOP 主路径登记到对应区/层 `## Code Map` 段；pre-commit hook 是 SOP 漏掉时的可诊断兜底。

- **主角是 SOP（CLAUDE.md 4 步 + 判定树 + 注释体例），hook 是兜底**。错误信息形态必须能把卡住的人弹回 SOP 第 2-3 步。
- **机制实质未变**：升级现有 `verify_architecture_code_coverage.sh` + 接 pre-commit + `scripts/install_git_hooks.sh` 自举 + 双向集合差（unmapped / missing）+ 动态 `actual_total` + INDEX 分子分母自动写回。
- **不动**：Claude Code PreToolUse hook 主拦截 / Codex 服务端评审 / AI 自动登记 / PR 自动生成 Code Map 候选条目 / 全局 `~/.claude/docs/workflow.md` 升级或占位 / 豁免清单引入。
- **rename 不写专用业务**：双向集合差天然覆盖（旧路径 dangling + 新路径 orphan）。
- **机器锚点统一**：`## Code Map`。文案/规则/脚本禁用 "Source of truth" 作段名或锚点。
- **acceptance 诚实**：hook 拦截语义 = "已安装 hook 的本地提交"；`--no-verify` / 远端兜底 / Jack 手动 commit 已知边界。

## 2. 七个设计交付物

### 2.a `verify_architecture_code_coverage.sh` 升级后接口

**输入**：无参（默认全仓 sweep）。
**逻辑**：
1. 扫 `docs/architecture/**/*.md`（排除 `REGION_MAP.md`），从每份文件 `## Code Map` 段提取反引号 `Sources/...swift` 路径，构建 `mapped_set`。
2. `find Sources -name '*.swift' -type f` → `actual_set`。
3. 集合差：
   - `unmapped = actual_set − mapped_set`：代码存在但没文档登记 → 主要兜底信号
   - `missing  = mapped_set − actual_set`：文档登记但代码不存在 → rename 旧路径 dangling / 删除遗漏
4. 体例校验：每条 Code Map 行必须严格匹配 `^- \`Sources/[^\`]+\.swift\` — [^[:space:]].+$`（**无缩进顶层 bullet** + 反引号路径 + 单空格 + **U+2014 em dash** + 单空格 + 非空首字符 + 至少 1 字符正文 + **行尾锚定**）。ASCII `--` / hyphen-minus / 全角空格 / 多空格 / 缩进列表均视为 `format_violations`。s1-exec sweep 阶段统一无缩进顶层 bullet 形态。
5. 重复登记（同一路径出现在 ≥2 份 doc）记入 `dup_paths`（warning，不 fail，除非显式开关）。
6. **INDEX 行处理（双模式）**：
   - **`--check-only` 默认（hook/CI 路径）**：只校验 INDEX 顶部 `Code coverage: <N>/<M>` 是否等于当前 `<mapped>/<actual_total>`；不一致报 `[architecture-coverage][stale-index] index=125/218 actual=149/218` 并 fail。**绝不写文件**。
   - **`--write-index` 显式（s1-exec 收尾 + 人工修复后路径）**：把当前 `<mapped>/<actual_total>` 和 `Last verified: <YYYY-MM-DD>` 写回 INDEX 顶部 coverage 行，再校验全套通过。

**输出形态**（stdout）：
```
[architecture-coverage] mapped=149 total=218 unmapped=69 missing=0 format_violations=0 dup=0
[architecture-coverage][unmapped] Sources/SpinLabApp/Foo/Bar.swift
  candidate region: workbench (path prefix Workflow/) | inbox (path prefix Import/)
  candidate layer: SHELL_AND_LIFECYCLE.md | EXTENSION_BOUNDARIES.md
  next: 在对应 md 的 `## Code Map` 段加一行 `- \`Sources/SpinLabApp/Foo/Bar.swift\` — <一句职责>`（主动短句；不写条件从句/临时实现/测试结论/调用方）
[architecture-coverage][missing] Sources/SpinLabApp/Old/Path.swift（registered in inbox/CONFIRM_AND_APPLY.md:42 但代码不存在）
  next: 删除该行；如系 rename 旧路径，新路径会以 unmapped 形式同时报出
[architecture-coverage][format] inbox/OUTPUT_CONTRACTS.md:55 不匹配 `- \`...\` — <注释>` 体例
```

**退出码**：
- `0` = `unmapped == ∅ && missing == ∅ && format_violations == ∅`（dup 仅 warn）
- `1` = 任一非空

**候选区/层提示算法**（轻量，不引入新规则源）：
- 路径前缀 → region 候选表（在脚本 hardcode）：
  - `Sources/SpinLabApp/Import/` → inbox
  - `Sources/SpinLabApp/Library/` `Sources/SpinLabApp/Features/Library/` → library
  - `Sources/SpinLabApp/Features/Workbench/` `Sources/SpinLabApp/Workflow/` `Sources/SpinLabApp/UseCases/` → workbench（多候选时全列）
  - `Sources/SpinLabApp/Features/RulesPanel/` `Sources/SpinLabApp/Import/Rules/` → inbox（rules authoring 子层）
  - `Sources/SpinLabApp/App/` `Sources/SpinLabApp/Domain/` `Sources/SpinLabApp/Registry/` `Sources/SpinLabApp/Storage/` `Sources/SpinLabApp/UI/` → 多区候选（cross-cutting，提示需手动判定）
- 层候选：从该 region 下所有 `*.md` 取文件名作为候选清单（不做更细推断，避免脚本卷入语义判断）。

> 候选提示是"指路牌"不是"判决"，写代码者按 CLAUDE.md SOP 第 2 步判定树拍板。

**标志位语义（与 §6 一致）**：
- 无标志 = `--check-only`（默认；hook/CI 调用形态）：只读校验，绝不修改任何文件。
- `--write-index`（s1-exec 收尾或人工修复后才显式打开）：写回 INDEX coverage 行 + 日期。
- `--no-format-check`（debug 用，acceptance 必须不带此标志通过 `--check-only`）。

### 2.b pre-commit hook 形态

**位置**：`.git/hooks/pre-commit`（由 `install_git_hooks.sh` 自举写入）。
**逻辑**（伪代码）：
```sh
#!/bin/sh
# spinlab-architecture-coverage:start
staged=$(git diff --cached --name-status --find-renames --find-copies)
# 只在 staged 涉及 Sources/**/*.swift 增删/重命名/复制（A/R/C/D）时调脚本；纯修改不触发
hits=$(echo "$staged" | awk '
  $1 ~ /^[ADC]/ && $2 ~ /^Sources\/.+\.swift$/ { print; next }
  $1 ~ /^R/    && ($2 ~ /^Sources\/.+\.swift$/ || $3 ~ /^Sources\/.+\.swift$/) { print }
')
[ -z "$hits" ] && exit 0
ts=$(date -u +%Y-%m-%dT%H:%M:%SZ)
./scripts/verify_architecture_code_coverage.sh --check-only
rc=$?
# 持久 trigger log（git-ignored，60 天验证窗口的唯一可靠数据源）
mkdir -p tmp
{
  printf '%s\trc=%d\tstaged=%s\n' "$ts" "$rc" "$(echo "$hits" | tr '\n' ';')"
} >> tmp/architecture-coverage-hook.log
[ $rc -eq 0 ] && exit 0
echo "[pre-commit] 已安装 hook 的本地提交：Code Map 与 Sources 不齐。按上述 unmapped/missing 提示修复后重 commit。"
echo "[pre-commit] 紧急绕过：git commit --no-verify（已知边界，自行担保；绕过不进 trigger log，60 天回顾会从 git log 反查识别）"
exit 1
# spinlab-architecture-coverage:end
```

**`tmp/architecture-coverage-hook.log` 形态**：每行 `<UTC ts>\trc=<0|1>\tstaged=<A\tFoo.swift;R100\told.swift\tnew.swift;...>`；`tmp/` 已在 `.gitignore`。`/schedule` 60 天回顾 agent 直接 grep 该 log 统计触发次数与拦截次数（rc=1）。`--no-verify` 绕过不留痕，由 60 天 agent 用 `git log --since` + diff Sources/*.swift 反查识别（见 §2.g）。

**关键约束**：
- 不含 rename 专用分支；A/R/D 一并塞集合差。
- 不验证"修改是否仍准确"——注释漂移概率低，强加变成走过场（已否决方案）。
- 错误尾巴必须包含"按 SOP 第 3 步注释体例提示"——具体由 verify 脚本输出，hook 透传不重复。

### 2.d `smoke_architecture_code_coverage.sh` 4 场景接口

**位置**：`scripts/smoke_architecture_code_coverage.sh`（新建）。
**形态**：在 `mktemp -d` 临时 worktree（`git worktree add`）模拟，每个场景独立子目录，跑完 cleanup。
**4 场景**：
1. **新增未登记**：在 fixture worktree `Sources/Test/Foo.swift` 新增空 swift，期望 verify 报 `unmapped: Sources/Test/Foo.swift`，exit 1。
2. **rename 旧路径未删 + 新路径未加**：`git mv` 一份已登记的 swift 到新路径；不动 docs；期望 verify 同时报 `missing: <旧路径>` + `unmapped: <新路径>`，exit 1。
3. **删除 swift 但文档行未删**：`git rm` 一份已登记的 swift；不动 docs；期望 verify 报 `missing: <旧路径>`，exit 1。
4. **同 commit 多类一次报全部**：A + R + D 在同一 staged 状态混合；期望 verify 一次性输出 unmapped/missing/format 全部信号，exit 1，不在第一个错误就 short-circuit。

**输出**：每场景 `[smoke][N/4] PASS|FAIL` + 失败时 dump verify 输出。
**退出码**：4 场景全 PASS → 0；任一 FAIL → 1。
**约束**：临时 worktree 路径不污染主工作树（`git worktree add ../tmp-spinlab-smoke-<pid>` + `git worktree remove --force` cleanup）；不在主仓库 commit。

### 2.g `/schedule` 远程 agent prompt（60 天验证窗口）

**触发**：5.7.3 s1-exec 最后 commit 落地当天，调用 `/schedule` 排一个 60 天后的远程 agent。
**数据源**（由 §2.b hook 持久写入）：`tmp/architecture-coverage-hook.log`（git-ignored；每次 hook 触发追加一行 `<UTC ts>\trc=<0|1>\tstaged=...`）。这是回顾任务的**唯一可审计数据源**；不再依赖 reflog / shell history 估计。
**Prompt 模板**：
```
你是 SpinLab 5.7.3 验证窗口回顾远程 agent。任务：扫 5.7.3 s1-exec 落地以来 60 天的 Swift 代码登记 workflow 体感数据，输出 ≤ 100 行报告 + 单行升级建议。

执行步骤：
1. cd 到 SpinLab 仓库主分支；git log --since='60 days ago' --all --oneline | head -200
2. 确认 hook 仍安装：grep -q "spinlab-architecture-coverage" .git/hooks/pre-commit
3. 触发统计（精确，数据源 tmp/architecture-coverage-hook.log）：
   - 总触发次数 = wc -l tmp/architecture-coverage-hook.log
   - 拦截次数 = grep -c '\trc=1\t' tmp/architecture-coverage-hook.log
   - 通过次数 = grep -c '\trc=0\t' tmp/architecture-coverage-hook.log
4. --no-verify 绕过反查：
   git log --since='60 days ago' --format='%H' --all | while read sha; do
     git show --name-status --format= "$sha" | awk '
       $1 ~ /^[ADC]/ && $2 ~ /^Sources\/.+\.swift$/ { print sha; exit }
       $1 ~ /^R/    && ($2 ~ /^Sources\/.+\.swift$/ || $3 ~ /^Sources\/.+\.swift$/) { print sha; exit }
     '
   done > /tmp/swift-touch-commits.txt
   对每个 commit 在 hook log 找其前后 5 分钟内是否有 entry；缺失 → 标可疑绕过（含 commit author / message head）
5. 漏报案例：跑 scripts/verify_architecture_code_coverage.sh --check-only；任一 unmapped/missing 即漏报（hook 放行但事后 Code Map 与代码偏离）
6. SOP 体感（定性，从 commit message + handoff/archive 文档摘要观察）：CLAUDE.md SOP 是否被 cite 过 / 判定树是否够用 / 注释体例约束是否阻碍写作 / 错误信息是否真把人弹回 SOP

- rework-and-extend-window：任一漏报 OR 可疑绕过 ≥ 1 OR SOP 体感负面 → 开 5.7.x 任务返工 + 延长窗口 60 天
```
