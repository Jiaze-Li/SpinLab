# Temporary Agent Handoffs

`docs/handoff/` 用于 SpinLab 跨主控对话、独立 Reviewer 或 Worker 的**短期交接**，不是新的项目状态、技术债或设计合同权威。首先复用现有 Issue、PR、冻结合同和固定版本引用；只有这些不足以让接收者恢复必要上下文时，才新增一份简短 handoff。每个进行中的任务尽量只保留一份有效交接，不复制长篇讨论。

## 交接内容（按需）

- 任务 ID/冻结合同版本；原任务的完整 `policy_sha`（历史未记录则明示未知，不能补造）。新聊天继续同一任务不得自动换用当前 `main` 的 Skill。
- 原始合同与审查材料的**准确引用**；必要时附不可变 `design_ref`、Gate 状态及独立审查依据。不能仅凭作者自述认定 DESIGN PASS。
- 仓库、基线提交、分支/PR 以及必要证据；如涉及 ReviewLoop/PR bot，标明已知状态的来源、HEAD 与读取时点，提醒接收者**执行前重新核实**，不把快照视为当前授权。
- 明确本任务的读写、commit、push、PR、merge、删除和权限授权边界；已完成、阻塞、尚待确认的事项，以及下一接收者应做的**一件事**。
- 交给独立 Reviewer 的材料以确切合同与原始证据为主，不把主控的预期结论当作审查依据。

单次使用的启动/执行 Prompt **直接在主控回复中提供完整可复制文本**，不为了 Prompt 单独生成文件。建议的操作顺序是“新建对话 → 粘贴 Prompt → 接收者按固定 commit SHA + 路径读取 → 核实状态后继续”，不用用户下载、上传 ZIP。固定 SHA 与文件路径必须来自已成功写入的真实提交，不能指向尚未存在的文件或只写 `main`。

## 清理：消费后删除，不默认归档

接收方已确认按固定引用读取成功、后续不再需要该临时文件，且所有**仍有约束力**的合同、设计批准/审查证据、未解决事项及任务状态已有持久、可访问的正式载体（如 Issue/PR/正式文档）时，这份临时交接即可提出删除。仍在等待审查、修复或其他任务依赖，或它本身是唯一可核验的合同/设计原文/证据时，**不得删除**。

清理是一项明确的仓库写入/删除操作：需获得适用授权并通过通常的 commit/PR 机制；不可因过期时间、切换会话或任务表面关闭而自动删除。删除前检查是否有活跃文档或任务只引用了该临时路径，先修复引用；保留必要正式证据，勿另建平行真相。已删除的提交内容可能仍存在 Git 历史，删除不等于安全擦除。

`docs/handoff/archive/` 是**既有历史材料**，不由此流程继续写入；当前改动不迁移、不删除旧档案。

> SpinLab 为公开仓库。不要把私人聊天、凭据、未公开科研数据或其他敏感内容写入 handoff；这些情况使用合适的私有渠道，而非以事后删除作为保护。
