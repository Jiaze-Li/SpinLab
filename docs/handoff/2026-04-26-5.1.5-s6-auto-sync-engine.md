### 1.2 现有 persist 通路（s5 已落）
```swift
// RulesManagementStore.persist (Sources/SpinLabApp/Features/RulesPanel/RulesManagementStore.swift:504)
private func persist<T: Encodable>(section: RulesPanelSection, url: URL, value: T) -> RulesPanelSaveOutcome {
    let data = try Self.jsonEncoder.encode(value)
    if let openHash = openTimeHashes[section] {
        let currentHash = fileHash(at: url)
        if currentHash != openHash { return .externalConflict(...) }
    }
    try atomicWriter.write(data, to: url)        // <-- 这里只写 runtime
    let newHash = sha256Hex(of: data)
    openTimeHashes[section] = newHash
    _ = RuleLoader.shared.reloadCached()
    onRulesSaved()
    return .saved
}
```
缺口：runtime 写完后**没有镜像到 bundle**；启动时也**没有反向同步**。

### 1.3 AtomicFileWriter 能力（已有，复用）
- `commit(_ entries: [AtomicWriteEntry])`：多 entry 一次性提交
- 准备阶段：每个 entry 写到 `.spinlab-tmp-<UUID>` 临时文件 + fsync
- 提交阶段：依次 `replaceItemAt` → `moveItem` → `syncDirectory`
- 准备阶段任一失败 → 清理所有临时文件后抛 `AppError.io`
- **限制**：提交阶段（rename 已开始）任一失败，不可回滚到全部成功前状态。本期接受该语义，靠回退副本兜底（§4.5）

### 1.4 RuleLoader 现状
- `loadCached()` / `reloadCached()` 已暴露，缓存命中策略基于 fingerprint
- `load()` 内部已是 runtime → bundle fallback 顺序读取

## 3. 仓库指针机制（核心决策）

### 3.1 文件位置与格式（**Codex Fix-1 修订**：加身份校验 + canonicalization + 必填明确）
- **位置**：`<runtime config>/.repo_pointer.json`（与 5 本子同目录，dot-prefix 避免和 schema 文件混）
- **格式**：
  ```json
  {
    "version": 1,
    "repository_config_dir": "/Users/jack/Downloads/scripts/Codex SpinLab/SpinLab-5.1.5/Sources/SpinLabApp/config",
    "repo_root": "/Users/jack/Downloads/scripts/Codex SpinLab/SpinLab-5.1.5",
    "set_at": "2026-04-26T12:34:56+08:00"
  }
  ```
- **必填字段**：`version`（Int，当前固定 1）/ `repository_config_dir`（String，绝对路径）/ `repo_root`（String，绝对路径，需含 `.git` 子目录用于身份校验）
- **可选字段**：`set_at`（ISO8601 含 offset 字符串，仅供日志追踪；解析失败仅告警不阻断）
- **路径规范化**：写入前与读取后都执行 `URL.standardizedFileURL.resolvingSymlinksInPath()`，再做等价比较（H2 修订）
- **版本不兼容**：`version != 1` 视为指针无效 → skip mirror（H8 修订）
- **身份校验**：`repo_root` 指向的目录必须存在且含 `.git` 子目录（文件或目录），否则视为漂移指针 → skip mirror（C2/Fix-1 修订）
- **职责边界**（M1 修订）：`RepositoryPointer` 类型负责 parse + validate + canonicalize；`RulesSyncEngine` 仅消费校验后的 `ResolvedPointer`，不重复校验

### 3.2 何时写入
- App 启动时若 `repo_root` 指针不存在 + 当前 bundle 路径含 `Sources/SpinLabApp/config` 启发式可识别 → **首次自动写入**指针（记当前 bundle 绝对路径 + 反推 repo_root）
- 已存在指针且与当前启发式结果不一致 → **不覆写**，仅 logger.warning 提示需手动 reset（H1 修订；UI reset 入口本期不做）
- 用户切换仓库 → 后续版本提供 UI（本期 out of scope）
- 指针写入失败 → 不阻塞，下次启动再试

### 3.3 何时跳过镜像写入（**ROADMAP 硬要求**："找不到 / 为空就跳过镜像写入不报错"）
**预检查阶段 skip → outcome `.runtimeOnly` + warning logged**（H3 修订统一）：
- 指针文件不存在
- 指针文件存在但 `repository_config_dir` / `repo_root` 任一为空 / null
- 指针 JSON 损坏 / 字段缺失 / `version` 不兼容
- 指针校验失败：`repo_root` 不存在 / 不含 `.git` 标识 / canonicalization 后的 mirror 路径不在 `repo_root` 之下
- 指针指向的 mirror 目录不存在
- 测试环境（`RulesConfigPaths.isRunningTests()`）默认 skip，除非 `RulesSyncEngine` init 参数 `testOverrideMirrorURL` 显式传入（M3 修订：注入位置在 Engine init，不改 `RulesConfigPaths` 行为）

**写入阶段失败 → outcome `.mirrorFailedRuntimeOk` + error logged**（H3 修订）：
- mirror 目录可读但不可写（permission denied）
- mirror parent 自动 `createDirectory` 失败（M5 修订）
- mirror atomic write 自身失败

### 3.4 指针 vs 启发式
**否决方案**：用 `Bundle.main.bundleURL` + 反推 `Sources/SpinLabApp/config` 路径作为 bundle 镜像地址。
- **理由**：发布构建后 bundle 是 `.app` 内的 resources，不指向仓库。指针文件显式声明"我知道仓库在哪"，发布构建天然找不到指针 → 自动 skip mirror。

## 4. 双写引擎语义

### 4.1 dualWrite 接口
```swift
struct RulesSyncEngine {
    let pointer: RepositoryPointer
    let atomicWriter: AtomicFileWritingCapability  // protocol，便于测试替身（H7 修订）
    let logger: AppLogger
    let testOverrideMirrorURL: URL?  // 测试注入点（M3 修订）

    func dualWrite(
        runtimeURL: URL,
        data: Data,
        sectionLabel: String  // 取值固定为 RulesPanelSection.rawValue（L3 修订）
    ) throws -> DualWriteOutcome
}

enum DualWriteOutcome: Sendable, Equatable {
    case runtimeOnly                     // mirror 跳过（指针不可用 / 测试环境 / 预检失败）
    case mirrored                        // 双写成功
    case mirrorFailedRuntimeOk(reason: String)  // mirror 写入阶段失败但 runtime 已提交
}
```

### 4.2 写入顺序（**runtime 优先**）
1. **回退副本阶段**：`<runtime>.json.backup` 覆盖式更新（如 runtime 文件存在；命名规则 L4 修订：保留原扩展名 + `.backup` 后缀）
   - backup 写失败 → **error 级日志**（H4 修订，从 warning 提升）+ 继续主写入路径，不阻塞
2. **runtime 写入**：`atomicWriter.write(data, to: runtimeURL)` —— 失败直接抛 `AppError.io`，整体失败
3. **镜像预检**：解析 `pointer` + canonicalize + 身份校验 + 目录可写检查（§3.3 预检阶段）→ 任一失败返回 `.runtimeOnly`
4. **镜像 parent 目录**：`createDirectory(withIntermediateDirectories: true)` —— 失败按 `.mirrorFailedRuntimeOk(reason: "create parent failed")` 处理（M5 修订）
5. **镜像回退副本**：`<mirror>.json.backup` 覆盖式（如 mirror 文件存在）
6. **镜像写入**：`atomicWriter.write(data, to: mirrorURL)` —— 失败**不抛**，记 error log + 返回 `.mirrorFailedRuntimeOk(reason: ...)`，runtime 已成功提交

### 4.3 调用方处置（**Codex Fix-3 修订**：加可观测通道）
- `.runtimeOnly` → `persist()` 返回 `.saved`
- `.mirrored` → `persist()` 返回 `.saved`
- `.mirrorFailedRuntimeOk(reason)` → `persist()` 返回新 case `.savedWithMirrorWarning(reason: String)`（C3/Fix-3 修订）
  - UI 层（`RulesPanelView`）按 `.savedWithMirrorWarning` 显示**侧栏轻量小图标**（不是 toast、不阻塞、不弹窗），鼠标 hover 显示 reason 文本
  - 测试断言可基于该 case 直接验证 mirror 失败链路
  - `persistenceHook.didPersist` payload 增加 `outcome: DualWriteOutcome` 字段（M4 修订）
- runtime 阶段抛 `AppError.io` → `persist()` 走原 `.ioError` 通路

### 4.4 失败/回滚策略
- runtime 阶段失败 → `AtomicFileWriter` 自身已清理临时文件；磁盘上 runtime 仍是旧内容（`replaceItemAt` 没发生）；不动 mirror
- runtime 阶段成功 + mirror 失败 → mirror 文件可能残留旧内容或部分新内容（取决于 `replaceItemAt` 哪步崩）；不主动恢复 mirror（mirror 是镜像，下次保存或下次启动反向同步会矫正）
- runtime 阶段成功 + mirror 成功 → 完成

### 4.5 单份回退副本语义
- **位置**：`<file>.backup`（与原文件同目录，同前缀）
- **覆盖策略**：每次写入前用旧内容覆盖之前的 backup（不累积时间戳历史，与 ROADMAP 一致）
- **写入实现**：`copyItem`（不是 `moveItem`，原文件还在）→ 失败仅记 warning，不阻塞主写入
- **何时清理**：永远保留最近一份。卸载时一并删（不在本期范围）
- **何时回滚使用**：本期**不实现自动回滚**——backup 是给用户/Jack 出事时手动恢复的安全网。代码不主动读 backup

## 5. 反向同步引擎

### 5.1 触发时机
- **App 启动一次**（`SpinLabAppState.init()` 早期，在 `RuleLoader.shared.load()` 之前）
- 不做 FSEvents 监听 / 定时轮询（本期）

### 5.2 比对算法（**Codex H5 修订**：mirror 解码校验前置）
对 5 本子每个文件：
```
mirror_data = read(mirror_file)
if mirror_data is nil OR pointer invalid:
    skip  # 指针不可用或镜像缺失
    error_taxonomy: pointer_invalid OR read_failed
    continue

# H5 修订：mirror schema 解码校验前置（防把损坏 mirror 当权威）
if try_decode_schema(mirror_data, file_kind) fails:
    skip + error log
    error_taxonomy: decode_failed
    mark file as degraded
    continue

mirror_hash = sha256(mirror_data)
runtime_hash = sha256(runtime_file) if exists else nil

if runtime_hash == mirror_hash:
    skip  # 一致
elif runtime_hash == nil:
    write mirror_data -> runtime (atomic)  # 首次启动，runtime 缺失
else:
    # 不一致 + mirror 通过身份校验 + 通过 schema 解码 → 条件权威成立（C4 修订）
    backup runtime -> <runtime>.json.backup
    write mirror_data -> runtime (atomic)
    log info "reverse sync: <file> updated from repository mirror"
```

**错误分类 taxonomy**（M8 修订，统一日志聚合）：
- `pointer_invalid` —— 指针不存在 / 损坏 / 身份校验失败
- `read_failed` —— mirror 文件 IO 错误
- `decode_failed` —— mirror 文件 JSON 解码或 schema 校验失败
- `write_failed` —— runtime 写入阶段失败
- `validation_failed` —— 反向同步完成后 RuleLoader 校验失败

### 5.3 决策方向（**核心拍板** + **Codex C4/Fix-4 修订**：条件权威）
**仓库镜像为条件权威源**。前提条件（任一不满足 → 不覆盖 runtime，仅记告警）：
1. 指针 canonicalize + 身份校验（`repo_root` 含 `.git`）通过
2. mirror 文件可读
3. mirror 内容 JSON 解码 + schema 最小校验通过

理由：
1. ROADMAP 否决"分文件赢" / "时间戳赢" → 必须有明确权威方
2. UI 保存会双写两边一致；runtime 单方面比 mirror 新意味着用户绕过 UI 直接改了 runtime —— 非预期路径，但前提条件不满足时不强制覆盖（C4 修订防漂移指针误回灌）
3. git pull 是预期路径，mirror 变新很正常 —— 此时前提条件全满足，覆盖生效

**不接受的对称策略**："让用户选" / "弹窗问方向" —— ROADMAP 否决手动按钮，启动反向同步必须无人值守。

### 5.4 启动时顺序（**Codex H6/M12 修订**：明确依赖注入顺序 + reloadCached 时序）
```
1. let env = AppEnvironment(...)                        // 构造环境
2. let pointer = RepositoryPointer.load(paths: ...)     // 解析+校验+canonicalize
3. let syncEngine = RulesSyncEngine(pointer: pointer, ...)
4. let degraded = syncEngine.reverseSyncOnStartup()     // 反向同步
5. RuleLoader.shared.reloadCached()                     // 唯一入口，确保缓存与同步后磁盘一致
6. let stores = construct stores using env + syncEngine
7. （应用主流程续）
```
- 仅 App process **cold start** 触发一次（L5 修订）；前台激活不触发
- reverse sync 完成后**统一**调用 `reloadCached()`，避免缓存持有旧 fingerprint
- App run 期间 RulesPanel 保存路径不再触发反向同步（保存即双写已覆盖）

### 5.5 反向同步失败模式 + 全量校验（**Codex C1/C5/Fix-5 修订**：加 RuleLoader 全量校验）
- 指针不可用 → 整体 skip，logger.info "no repo pointer, skipping reverse sync"
- 单文件 hash / decode / write 失败 → 该文件标记 `degraded`，其他继续，**不阻塞 App 启动**
- **同步完成后强制全量校验**（Fix-5 / C1）：
  - 调用 `RuleLoader.load()` 跑一次 + 校验返回 `LoadResult` 是否 warnings 为空、ruleSet 不为 fallback
  - 校验失败 → `RulesSyncEngine.startupOutcome` 标记 `.degraded(failedFiles: Set<URL>, reason: String)`
  - degraded 状态通过 `AppLogger.error` 记录 + 暴露给 UI（启动后规则面板侧栏顶部显示一次性 banner，可由用户 dismiss）
- App 仍可启动 → 走 RuleLoader fallback 路径（现有逻辑，未改）
