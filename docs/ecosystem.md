# SpinLab Ecosystem

SpinLab is split into three repositories with deliberately different responsibilities.

## Repositories

### 1. SpinLab

This repository is the primary product and source of truth for the native macOS application.

Responsibilities include:

- experiment ingestion and organization
- Library and archival workflows
- Workbench analysis and plotting
- workflow authoring and desktop-side scientific logic
- source templates and exporters for the private Web Library

### 2. SpinLab-Web-Library

`SpinLab-Web-Library` is the publication target for selected SpinLab Library data.

It is not the source of truth for the Web Library UI. The source templates live in this `SpinLab` repository under `Resources/WebLibraryTemplate/`.

Publication flow:

```text
SpinLab Library
      |
      | export_static_library.py
      v
SpinLab-Web-Library/public
      |
      | git push
      v
Cloudflare Pages
```

The normal entry point is:

```bash
./scripts/publish_web_library.sh
```

That script exports the current static snapshot, validates it, commits the generated `public/` output in `SpinLab-Web-Library`, and pushes it for Cloudflare Pages deployment.

The Web Library is intended for publishing the owner's experimental data. Access control is handled separately at the Cloudflare layer.

### 3. SpinLab-Web-Tools

`SpinLab-Web-Tools` is an independent browser-based analysis product.

Its purpose is to let users analyze their own experimental data using web implementations of mature SpinLab workflows, without installing the macOS app.

Unlike `SpinLab-Web-Library`, this repository is **not generated by SpinLab** and is **not a publication target** of the desktop app.

The relationship is conceptual and algorithmic:

```text
SpinLab Workbench
      |
      | mature workflow concepts / algorithms
      v
SpinLab-Web-Tools
      |
      | browser-side parsing, analysis, plotting
      v
User's own data
```

`SpinLab-Web-Tools` is developed, versioned, deployed, and authorized independently. It must not depend on access to the private SpinLab Web Library.

## Product Boundaries

The three repositories should remain separable:

| Repository | Primary role | Data ownership | Deployment relationship |
|---|---|---|---|
| `SpinLab` | Native macOS research app | Local experiment data and workflow state | Primary development repository |
| `SpinLab-Web-Library` | Publish selected owner data | Generated static publication snapshot | Generated/pushed from `SpinLab`, then deployed by Cloudflare Pages |
| `SpinLab-Web-Tools` | Browser analysis tools | User-supplied data processed in the browser | Independent deployment |

## Design Rule

Use the following rule when deciding where new work belongs:

- If it manages local experiments, Library state, Workbench authoring, or desktop workflows, it belongs in `SpinLab`.
- If it changes how the owner's published experimental data is presented, edit the Web Library source in `SpinLab` and publish to `SpinLab-Web-Library`.
- If it lets another user run a reusable analysis workflow on their own files in a browser, it belongs in `SpinLab-Web-Tools`.

## Current Web-Tools Direction

The first planned workflow for `SpinLab-Web-Tools` is RT analysis for PPMS `.dat` files.

The initial vertical slice is intentionally small:

```text
select RT workflow
      -> upload/drag .dat
      -> choose ch1/ch2/ch3
      -> map channel to Bridge 1/2/3
      -> parse Temperature + Bridge Resistance
      -> sort by temperature
      -> one result/channel = one plot series
      -> render in browser
      -> download figure
```

The Web Tools project should preserve the scientific behavior of mature SpinLab workflows while reimplementing browser-specific UI, file access, and plotting independently.
