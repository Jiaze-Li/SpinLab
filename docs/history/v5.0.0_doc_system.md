# v5.0.0 — Knowledge Accumulation System

## Thinking

As features grow, each new AI conversation starts nearly from scratch. CLAUDE.md provides
architecture rules and the memory system captures fragments, but there is no structured,
continuous knowledge base that tracks: what every feature does, why design decisions were
made, and what the developer's philosophy is.

Jack identified this gap: without systematic accumulation, AI assistants cannot reliably
check impact scope when modifying code, and the developer cannot avoid manually testing
every feature after every change.

## Solution

Introduced a three-file documentation accumulation system (plus CLAUDE.md rules):

1. **`docs/philosophy.md`** — Jack's development philosophy and collaboration preferences.
   Helps AI understand *how Jack thinks*, not just what the rules are.

2. **`docs/features.md`** — Consolidated feature invariant catalog for all areas
   (Inbox/Library/Workbench/Shared). Records business invariants that are not obvious
   from code, plus test coverage status. Points to specs for full behavior details.

3. **`docs/known_issues.md`** — Intentional behaviors that look like bugs, documentation
   inconsistencies, and deliberately deferred items. Prevents AI from "helpfully" fixing
   intentional designs. Tech debt details stay in `TECH_DEBT_BACKLOG.md` (no duplication).

Event-driven development logs (like this file) live in `docs/history/` and are indexed
in the Development Log table in `docs/README.md`.

Added CLAUDE.md rules:
- **Startup rule**: Load philosophy.md + features.md on every session.
- **Closeout rule**: Judgment-tree for updating docs after substantive changes.
- **Change rule**: Check features.md invariants before modifying code.
- **Codex review gate**: Non-trivial plans require multi-round Claude + Codex co-review.

## Design Decisions

- **Single features.md** instead of per-area files. ~120 lines total, AI reads once.
  Initially designed as 4 separate files, consolidated after reviewing maintenance cost.

- **Invariants-only** in features.md, not full behavior descriptions. Behavior details
  already live in specs/. Invariants are the knowledge that specs don't capture and that
  code doesn't make obvious.

- **Devlog merged into history/** instead of a separate directory. Avoids directory
  proliferation; history/ already serves the same purpose.

- **Codex review gate** with explicit trigger criteria (2+ modules, new patterns,
  persistence changes, CLAUDE.md rule changes). Multiple adversarial rounds encouraged.

## Architecture Impact

- No code changes. Documentation-only addition.
- CLAUDE.md updated with session lifecycle rules and Codex review gate.
- docs/README.md updated with new files and Development Log index.

## Follow-up

- Populate philosophy.md with more detailed preferences as they emerge in future sessions.
- Update features.md invariants as new features are added.
