### 2.2 209 与 201 历史差异的严密数学归因

此前报告提出疑点：“若 7 张多 Sample 图均关联多个样品，则冗余引用至少为 11，但 209 - 201 仅为 8”。

**真实数据核实结论：**
1. 共享目录 `_spinlab/multi-sample/charts/` 下确实存在 7 个 PNG 与 7 个 Manifest。
2. 但在这 7 张图中，**只有 3 张图被多个样品引用**：
   - 图 1（RT 工作流）：跨 **6 个样品**（LNO 系列），贡献冗余引用数：`6 - 1 = 5`。
   - 图 2（xy 工作流）：跨 **3 个样品**（PN 系列），贡献冗余引用数：`3 - 1 = 2`。
   - 图 3（AHE 工作流）：跨 **2 个样品**（PN 系列），贡献冗余引用数：`2 - 1 = 1`。
3. 其余 4 张图均为单样品图：
   - 4 张 IV 工作流图在历史保存时被写入了 multi-sample 共享目录，但仅被单个样品引用，贡献冗余引用数：`4 × 0 = 0`。
4. **数学恒等式验证：**
   $$\text{冗余引用总数} = (6 - 1) + (3 - 1) + (2 - 1) = 5 + 2 + 1 = 8$$
   $$\text{独立图数} = \text{总引用数 (209)} - \text{冗余引用数 (8)} = \mathbf{201}$$
   数学关系 100% 严密吻合。

## 3. 异常关联核实与分类清单

### 3.1 异常类型 A：缺失 PNG 文件（14 / 16 张）
- **现象描述：** `results_index.json` 中存在活跃引用，`charts/*.manifest.json` 文件完整无损，但对应的 `.png` 图像文件在磁盘上缺失。
- **根本归因：**
  - 所有 16 张图均生成于 2026 年 8 月至 9 月，Manifest 记录的 `appVersion` 均为 `v5.5.7`。
  - 全部为 `3w` 工作流（涉及 PN 系列样品）。
  - 这些图并未经过归档备份，推测为历史实验导出中断、磁盘空间清理或同步不完整导致。
- **风险等级：低（Low）**
- **对 P1/P2 影响：无阻塞。** `WorkflowGalleryQueryService` 与 Gallery 卡片已对 `imageStatus == .missingFile` 做了显式占位与降级展示，点击卡片仍能正常查看 Manifest 来源参数与样品跳转。
- **处理建议：** 严禁自动从索引中删除！保留记录，在 P3 中提供只读异常诊断，若用户具备原始测量数据，可在 P3 考虑提供“根据 Manifest 参数一键重新生成图表”的无损恢复工具。

### 3.2 异常类型 B：Dangling Measurement → Plot 引用（25 处）
- **现象描述：** `_spinlab/measurement_plot_index.json` 中记录的 rawFile 关联了 `chartIdentityKey`，但该 key 在该样品的 `results_index.json`（甚至全库所有样品的 `results_index.json`）中均不存在。
- **根本归因：**
  - 25 处失效关联仅涉及 3 个特定的历史图哈希键，分布在 6 个早期样品中。
  - 这些 key 对应的图在早期已被用户删除或覆盖，但在早期版本中仅清理了 `results_index.json`，未同步清理反向映射 `measurement_plot_index.json`。
- **风险等级：低（Low）**
- **对 P1/P2 影响：无阻塞。** Gallery 的图表发现完全依赖 `results_index.json`（真源），绝不把反向索引作为图存在的凭据。
- **处理建议：** 建议列入 P3 计划。在 P3 编写只读校验与可回滚的事务性清理工具，将这 25 处孤立反向键安全剔除。

### 3.3 异常类型 C：无 Measurement 关联但有 Index 记录的图（7 张）
- **现象描述：** 图表存在于 `results_index.json`，磁盘 PNG 与 Manifest 均完好，但 `measurement_plot_index.json` 中没有引用它。
- **根本归因：** 早期通过批量画图或脚本导入时，直接写入了结果与图表，但未调用 Measurement 绑定接口。
- **风险等级：中（Medium，仅针对旧 Sample UI；对 Gallery 为无）**
- **对 P1/P2 影响：** 旧 Sample Detail 依赖 Measurement 行 hover 查图，会导致这 7 张图被漏看；**但这恰恰是 P1 和 P2 必须解决的核心痛点！** Gallery 和 P2（图优先）从 `results_index.json` 读取，确保这 7 张图能第一眼呈现，标注 `Measurement unlinked`。
- **处理建议：** P1 已覆盖；P2 中在 Sample Detail 顶部 Plots 区域正常展示，无需人工干预修改历史文件。

### 3.4 异常类型 D：历史 Manifest 中的路径与分号格式
- **现象描述：**
  - **分号拼接：** 3 个 Manifest 的 `inputFiles` 数组仅包含 1 个长字符串，内部以 `;` 分隔数十个 `.lvm` 原始测量文件。
  - **绝对路径：** 1,083 处 `inputFiles` 使用了生成机器的绝对路径。
- **风险等级：低（Low）**
- **对 P1/P2 影响：无阻塞。** Gallery 仅显示来源文件名，不依赖 `inputFiles` 路径直接加载物理文件。
- **处理建议：** P3 在需要跨设备反查原始数据时，提供路径前缀重定位解析器。

### 3.5 异常类型 E：嵌套 Sample 目录（3 个样品）
- **现象描述：** 3 个样品的 `sampleKey` 自身含有斜杠 `/`（来源于多层 Batch 命名或历史导入格式）。在写入 `samples/\(sampleKey)/_spinlab/results_index.json` 时被文件系统自然切分为两层目录。
- **对 Gallery 的影响：** 当前 `WorkflowGalleryQueryService.findSampleDirectories` 仅列出 `samples/` 下的第 1 层目录，导致这 3 个样品的 3 张图在当前 Gallery MVP 中未被扫描进入。
- **风险等级：中（Medium）**
- **处理建议：** 在 P1 维护补丁（Stage B）中将 `findSampleDirectories` 升级为递归查找包含 `_spinlab/results_index.json` 的目录，以实现全量 204 张图的完整发现。

## 4. Git 历史暴露评估与安全补救建议

针对此前分支 `audit/p0-library-closeout`（PR #185）：
1. **暴露事实：** 提交 `bec9a8e3` 包含了 `P0_RECONCILIATION_TABLE.json`，其中包含 204 条图表的相对路径与原始测量文件名。由于目标仓库为公开仓库，推送到远程分支后已产生远程 Git 引用。
2. **Git 机制关键原理：** 在 Git 中，后续提交中通过 `git rm` 删除文件**并不能**消除已推送到远程仓库的历史提交对象。
3. **安全处置与补救方案：**
   - **第一步：** 废弃并关闭 PR #185，不予合入。
   - **第二步：** 彻底删除远程分支 `origin/audit/p0-library-closeout`（`git push origin --delete audit/p0-library-closeout`）。
   - **第三步：** 由全新的干净分支 `docs/p0-audit-closeout` 提供完全脱敏的审计报告，不包含任何 JSON 数据集。
   - **高灵敏度处置评估：** 若相关原始测量文件名被认定为高敏感隐私，因 GitHub 对 PR 引用（`refs/pull/185/head`）可能存在缓存，可在用户明确授权后，由仓库管理员联系 GitHub Support 或执行仓库垃圾回收以彻底清除该缓存引用。
