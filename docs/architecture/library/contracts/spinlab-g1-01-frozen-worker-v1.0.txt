Goal
Protect existing SpinLab Library mutation and deletion paths before G2 identity work. In the affected legacy Registry diff/apply and manual Sample/Batch/Drawer deletion paths, a missing Registry row, derived-key change, corrupted/unknown data, or an unrecognized dependency must never cause an unauthorized delete, new-plus-old replacement, detached workbench artifact, or old artifact rebound to a newly created object. Preserve safe reads and non-destructive updates. Prefer bounded, fail-closed protection over creating a complete deletion or migration product.

Behavioral invariants
S1. Complete relevant read-only safety judgment precedes **all** writes from a potentially dangerous plan, including batch-key reconciliation and library index sync. Do not allow `create-new` to commit before detecting forbidden `delete-old` in the same Registry diff; either reject the entire dangerous plan or only a proven independent safe subplan.
S2. Missing/rekeyed Registry row is not deletion authorization. Damaged/unknown/ambiguous/cross-namespace references cannot be treated as empty or as permission to delete. A Preview/Read operation does not assign UIDs or mutate records.
S3. Evaluate affected Sample drawers, measurement files and sidecars, Workbench per-sample result/measurement indexes and charts, and multi-sample/shared-figure references. Do not delete an asset shared by other Samples; do not allow a new object with a reused legacy key to inherit an old metric or plot.
S4. In deletion-policy-unresolved cases, fail closed **before** the first write with actionable reason; do not add a general-purpose Trash/Purge implementation or a confirm dialog that bypasses missing referential guarantees. Keep unaffected legal read/update paths functioning.
S5. Distinguish refused-before-write, committed, partially committed, and unknown-after-failure outcomes accurately; do not claim global transactionality because one file uses atomic replacement. For permitted operations, verify restart/retry and old-data preservation, or block the risky operation if correctness cannot be shown.
S6. No UID backfill, newly invented Source/Result/Plot entities, data migration, new Parameter authority, scientific dedup, deletion of real user data, or change to existing experimental algorithms. Do not silently override manual facts.

Acceptance criteria — evidence must reach the relevant branch/path, not an earlier unrelated guard
AC1: Read-only audit/preview has zero file/mtime/content changes and no UID assignment. Corrupt `sample.json`, index, batch layout and one reference index independently; assert targeted errors and the exact filesystem remains unchanged.
AC2: Registry missing-row and key-change cases involving a real legacy Sample plus measurement+plot are rejected before any new object, delete, index rewrite or batch-key reconciliation is committed. Exercise both `applyBatch` and `applyAll`; ordinary safe updates still work.
AC3: Explicit Sample/Batch/Drawer delete entrypoints safely reject dependency ambiguity, shared plot references, unrecognized cross-namespace assets and corrupted dependencies; tests verify no writes occurred at any reached entrypoint and originals remain readable.
AC4: If only an orphan `samples/<sampleKey>/_spinlab` artifact remains, re-creation of same legacy locator cannot attach it to a new Sample. Block if identity separation is not yet available. No automatic assignment, reparenting, or cleanup of legacy artifacts.
AC5: Inject faults at actual post-validation write phases for any permitted mutation and establish precise committed/partial/failed outcome with restart/retry recovery, preserving protected existing records. Tests that only hit a preflight guard do not count as proof of the failure phase.
AC6: Regression: no broken old read, legitimate non-destructive Registry update, approved index recovery or compatible existing UI workflow; no second identity/authority or broad disabling of unrelated Library functions.
