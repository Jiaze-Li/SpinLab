## 1. 不变量

| ID | 必须成立的约束 |
|---|---|
| I01 唯一身份 [C/R] | 一个正式、独立管理的科研对象在同一身份域内有一个权威身份；UID 分配后不可因重启、改显示名、移动、同步、重建或重试而改变。身份分配由数据核心约束，不要求未来所有设备必须在线向一台服务器申请。 |
| I02 关系可解析 [C/R] | 新正式关系使用权威身份，旧关系通过单一受治理解析边界映射。名称、路径、可重算 key 或内容哈希不能独自承担对象身份。多对象关系有明确范围和端点。 |
| I03 权威单一 [C] | D3 管正式记录、修订、采用、关联和清理。Notebook、Workbench、Inbox、自动化及未来手机端不各建一份可独立修改的当前事实。 |
| I04 来源与派生分离 [C] | Source、Measurement 语境、标准 Dataset、Observation、Result、Plot、Run 责任不同；物理文件副本不自动成为新科研对象。 |
| I05 人工决定有效 [C] | 同一对象、量、角色、条件和用途范围的明确人工修改/采用生效；后台保存、重算或同步到达时间不能越权替换它。 |
| I06 正式提交可信 [C/R] | 仅在本次承诺的记录、数值与必要关系已可靠提交后报告成功/Ready。损坏不是不存在；失败、回执丢失、重试及部分完成必须可判定。 |
| I07 删除不误绑 [C/R] | 删除有范围和依赖保护；恢复保留原身份，重新创建是新对象。同名/同旧 key 不能把历史成果吸附到新对象；重复事件/扫描不得复活已明确删除成果。 |
| I08 渐进兼容 [C] | 未切换消费者可以继续受控旧路径；切换时完成必要映射、读回与失败保护。大规模历史整理后做，运行必需的兼容不能后补。 |
| I09 创建与来源去重分离 [C/R] | 明确的不同新建意图可生成同属性的不同 Sample；同一创建操作的重复提交必须幂等；同一外部来源记录再导入通过有身份域的持久映射解析，歧义不能凭科研属性补全。 |
| I10 资产与关联分离 [C/R] | 一个正式 Source、Dataset、Plot 或附件的身份与指向它的 Sample 关联不是一回事；删除某一关联不等于删除资产，不得破坏其他有效引用。 |

这些是不变量，不是要求创建八个框架。具体存储、接口名称和目录由后续任务在已知事实下选择。

## 2. Sample 身份、业务辨认与兼容解析

### 2.1 四种标识不得混用 [R]

| 类型 | 用途 | 不能替代什么 |
|---|---|---|
| 永久对象 ID，如 sampleUID | 指向同一个正式科研对象 | 不能仅由名称/衬底/路径每次重新计算 |
| 科研属性/来源线索 | Batch、Substrate、Recipe、Display Name 等用于呈现、搜索、协助用户选择；外部来源记录的稳定标识用于已有记录对账 | 不能凭属性相同决定两个记录是同一 Sample，也不能把属性不同当作强制新建依据 |
| 外部/旧别名，如 sample.id、sampleKey、旧 Domain UUID | 兼容旧来源、索引、目录与读写者 | 不自动等于同一身份域；相同字符串在不同上下文可指不同对象 |
| 技术定位及内容指纹 | 查找某个载体、核对内容、发现候选重复 | 路径变了不应换对象；字节相同不充分证明同一实验 |

**身份由 App 中明确的新建意图建立，而非科研属性推断。** 用户每次明确创建一个新的 Sample，系统就分配一个独立、不可变的 sampleUID；用户明确创建两个就是两个，即使 Batch、Substrate、Recipe、Display Name 全部相同。App 不推断现实世界的切割、生长或物理同一性，也不要求用户提供任意序号来“绕过”材料去重。修改上述属性不改变已有 Sample 的 UID。

**创建幂等与来源对账是不同问题。** 同一创建请求的重试、回执丢失或重复触发不能产生意外副本；两次独立、明确的新建请求应得到两个不同 Sample。旧 XLSX 同一来源记录再次导入，以及未来手机/桌面同步已有记录，应以受治理的来源记录身份/已保存映射与操作意图确认是更新还是新建，不通过材料、衬底、名称或容易变化的行号猜测。映射缺失或存在歧义时保留待确认，不能自动合并或删除。具体机制见 §2.4。

显示名是人类标签；机器 UID 不作为常规必填项。旧定位 key 可以保留用于旧目录与读写兼容，但新建对象的唯一技术定位不得依赖 Batch+Substrate 等科研属性组合；两个属性相同的新对象也必须能共存且互不覆盖。修改显示名不能重算身份；旧业务 key 变化必须通过正式映射与兼容边界处理，不能自动删旧建新。

### 2.2 解析合同 [R]

解析使用足以区分旧系统的身份域、命名空间、外部/旧键和必要上下文。身份域是逻辑范围，不要求现在新增一个同名数据库实体。跨 Library 或跨设备的范围策略在相关任务确定，不把一个本地唯一路径误当全局唯一。

解析必须区分至少这些语义结果：**已解析、未映射、存在歧义、已删除/已停用的历史对象、证据损坏/无法完整读取**。不指定 enum 名称。

1. 明确的权威 ID 命中时检查对象类型、存在性和状态；同时携带的旧引用若指向另一对象，报告冲突，不能静默忽略。
2. 旧引用只能经已登记且作用范围明确的映射得到 UID。一个确切的现行别名映射不能同时选出两个活跃对象。历史复用必须能消除代际歧义，否则拒绝自动解析。
3. 未映射或歧义不能在普通读取中“顺手创建”一个新 Sample，也不能以扫描顺序、最近修改时间或最相似名称选一个。
4. 碰撞、空/损坏 UID、同一 UID 对应不一致对象记录必须报错或隔离，不允许生成新 UID 掩盖冲突。
5. 写入同一对象时，缺少 UID 的旧调用可由受控兼容边界保留已有 UID；携带不同非空 UID 必须拒绝或进入单独获批迁移流程，不能用普通 Update 改身份。
6. 旧 `legacy:<batch>:<key>` 可作为暂存引用/定位线索；在没有持久映射前，不得宣称它已经是能承受 rekey 的永久机器身份。

### 2.3 旧数据分配与别名保管 [R/O]

只读打开、搜索、预览、诊断和只读索引扫描不分配永久身份、不回写正式关系。UID 回填是明确的正式修改，需要受控范围、可重复执行、并发防重和失败恢复。

映射可以附着在正式对象记录或一个受治理的登记结构中，不预选存储方案。**不可重建的历史别名/人工对账决定不能只存在于易丢索引。** 一个已映射对象再次导入应继续指向它；别名变化是修订，不是新身份。

全量回填或按需回填仍是 O-ID2。G2 可以先在隔离夹具验证两类输入与同一映射合同，不能把这当作已批准在真实 Library 选择某种回填策略。

### 2.4 创建请求与外部来源映射的最低合同 [C/R]

**创建请求**：正式写入包含能够区分“本次独立创建意图”的操作标识/等效持久幂等证据及请求语义；一个操作标识只能对应一个确定的已提交结果。同一请求跨进程重试、回执丢失或并发重复应回到已存在的 UID；对同一标识提交不同实体内容应拒绝或进入明确冲突处理，不能猜测。两次用户明确发起的新建是两个独立操作，不能因为同 Batch/同衬底属性相同就合并。实现不预设 UUID 字段名称或通用消息平台，但**操作与 Sample 分配结果必须同提交或可确定恢复**。

**来源映射**：受治理的映射至少能定位来源系统/身份域、外部稳定记录标识、当前对应的 Sample UID，以及必要的历史/状态。这里的“外部记录 ID”（例如一条可信的 Obsidian 记录身份）**不同于**仪器原始文件的 `sourceID`；不能用一个名称相似的字段混同这两个身份域。**一个确切外部记录在相同有效映射范围内不得无声指向两个活跃 Sample**；多个来源记录经明确对账可指向同一 Sample。更新、来源改名、重导出、重新打开、迁移与重试不得依据行号/文件名/科研属性重新推断归属。

**历史入口与能力边界**：现有 XLSX、Obsidian → XLSX 链路若确有稳定记录 ID，可透传并登记；不可把文档标题、表格行号、衬底名当作已验证 ID。历史记录无可靠身份时，先只读呈现候选，用户可选“关联已有 / 明确新建 / 暂不处理”。**确认一次不意味着以后能自动识别这条记录**：只有在外部原始来源和后续导出中可持久保留一个受治理、唯一且可验证的记录 token（既有或经明确授权写回），才允许未来无歧义地自动复用该确认映射。若外部不能携带 token，本次确认仅对已核对的来源快照/范围有效；后续重导出、换行、改名或内容变化若无法精确证明同一记录，必须重新由用户明确对账，且绝不能自动新建、合并、覆盖或删除。指纹/旧 sampleKey 只能提示候选，不能冒充永久记录 ID。待确认不改正式 Sample，前台可集中显示待决项。新 Mobile 采用共同记录身份与操作幂等协议，但不预设手机、服务端或云同步实现。

**事务与恢复**：在允许的写入范围内，Sample 创建、操作结果、来源映射及必要关联须在一个正式业务提交边界中可靠一致；外部文件与元数据不能天然视为单库原子。失败后必须能判别“未发生 / 已提交 / 结果不明待核对”，不能把回执丢失当新建请求。

**旧别名碰撞**：同一字符串的旧 key 在不同身份域、Batch、代际或存储命名空间出现时，必须用已确认范围进行解析。两个活跃或历史对象若无法由足够上下文唯一定位，返回歧义/已删除历史对象，不得把旧测量或旧图指到最新创建的同名 Sample。相同属性的两次独立新建必须产生可独立定位的技术载体/关联键，即使原始 `Batch + Substrate` 组合相同；旧目录路径只作为经受控解析可抵达的兼容定位。

## 3. 最小对象与关系合同

### 3.1 对象何时需要独立身份

| 对象 | 合同及实现时点 |
|---|---|
| Sample | 永久身份、独立新建意图、重复请求幂等、外部来源映射、别名与实际消费者解析是 G2 的当前基础；T01 只消费这些能力。 |
| Batch | Sample 必须引用确定批次；编号更正/改名是否要求独立机器身份按 O-ID1 裁定。未裁定时不新增自动 Batch rekey/合并能力，不宣称编号永远不变。 |
| Device | 一旦正式区分器件、记录其几何或归档其测量，就要有稳定身份与 Sample 关系；角度字符串不是 Device ID。G2 按对象扩展，在首个需要 Device 的功能前完成，不强迫 T01 建全器件系统。 |
| Source | 每个正式登记的原始来源有 sourceID。文件副本/换位置不自动新建来源；同名不同内容不静默复用。新字节如何登记为新来源或源修订须在 G4 明确，所有已引用版本可核验。 |
| Standard Dataset | 独立可读资产有 datasetID；内容/解释修订可被精确引用。源段、信号、对象范围和配对关系明确。G4 首次实施，T03 按共同合同接入 AFM。 |
| Measurement | 针对一个明确 Sample 或其一个 Device 的测量语境；一个测量可含多信号、多段、多来源。**不把同源多 Sample 汇集成一个目标不明的 Measurement。** 是否需要独立持久实体按 O-ID4 的真实消费者决定。 |
| Observation / 人工属性声明 | 需独立修订和引用的人工记录具有稳定记录身份与修订；无需虚构仪器 Measurement。具体沿用哪种已有类型由 G3 定案。 |
| Current Parameter | 按对象、量/角色与适用语境定位当前采用引用；不是把每次显示数值再造一个科研实体。引用明确的 Observation/Result/人工修正版本。 |
| Result | 正式、可独立引用的数值/曲线/矩阵成果有身份，且能定位固定输入、方法、配置和作用范围。G5 的成果部分先于 T04/T07 正式保存。 |
| Plot Artifact | 正式图有可独立管理身份；可以引用 Dataset 或 Result。一图多 Sample 不复制多份图实体。已有 manifestID/chartIdentityKey 能否复用须核查，不机械添加 UUID。 |
| Attachment / 笔记 | 独立管理的照片、附件、笔记有对应正式记录与关联；文件、缩略图、副本不是各一个科研对象。G3b 随 T02 附件功能前置落实。 |
| Run / Notebook | Run 标识执行及重试关系；Notebook 是视图。两者都不因页面/按钮出现而新造科研对象。 |

### 3.2 关系及作用范围 [C/R]

- **Batch → Sample：** 一个 Sample 当前归属一个明确 Batch，Batch 可以有多个 Sample。更正归属是有影响范围的人工修订，不默认换 Sample UID。
- **Sample → Device：** Device 归属一个 Sample；不能仅凭 60deg/150deg 为其全局定身份。
- **Source ⇄ 对象：** 一个 Source 可含多个对象；关系须细化到源段、通道/信号及所需条件，不能只记录“整个文件属于这几个 Sample”就把所有信号暴露为各自的测量。
- **Source → Dataset：** 默认标准 Dataset 表达一个明确对象范围的一项可独立使用信号/必要分量集合，保留源段与原始顺序。暂未归属可存在；未确认前不向猜测 Sample 发布。多来源派生组合通常是 Result，不伪装成新的原始标准数据。
- **Measurement → Source/Dataset：** 可把同一个对象的多个来源/信号联系起来；跨对象的同期采集由 Source、共同时间/段/采样证据关联。不强制先建 Acquisition/Session 实体。
- **Dataset/Observation/Result → 分析 → Result：** 输入可以有多个，引用明确修订与作用范围。一个样品的几何或电阻作为计算输入，也必须带实际采用修订，不能事后读“最新值”冒充原输入。
- **Dataset/Result → Plot：** Plot 可直接画标准数据，也可画派生结果；一张图可关联多个对象。归属链接与资产本身的删除是不同操作。

**同源不等于同步。** sourceID 不能替代时间戳、源行/段与配对证据；联合计算必须满足 D4 的对齐要求。H/T 等共同列可以重复保存，重复部分仍是同一来源表达；修正通过受控解释/资产修订完成，不能任意编辑其中一个副本而不表达差异。

### 3.3 Measurement 暂不物化时的最低承诺 [R]

Source/Dataset 仍要保留现有证据足以说明的采集时间、源段、对象、信号和重复实验区别；不知道的保留未知。当前可用明确的受治理关系表达测量语境，不因没有 measurementID 就退回“文件名就是实验”。

出现跨文件同次测量管理、独立测量备注/状态/版本、联合采集组织或其他真实消费者时，先细化独立 Measurement 的合同与旧关系映射，再启用对应功能。原始文件是否一份不决定实体时机。

### 3.4 正式资产登记与关联边界 [C/R]

**Asset Registry 是逻辑能力，不是预先增加一张总表或第二套 ID。** 正式 Source、Standard Dataset、Plot、Attachment 等在各自身份域登记一次权威资产记录；一个资产可以有零个、一个或多个受确认的 Sample 关联。原文件/PNG/Sidecar/缩略图/缓存可以是载体或副本，不因数量而产生相同数量的科研实体。已有 `chartIdentityKey`、`manifestID`、路径或内容哈希能否承担某一角色，按首次消费者审计决定，不能机械叠加 UUID。

**关联是正式可更新的关系**：至少有稳定且类型明确的端点、适用范围/用途及相关来源修订；对 Source/Dataset 还要注明源段、通道或实际需要的信号映射，不能以文件整体归属推导每个信号归属。未确认归属可以保留为待确认，不编造默认 Sample。关系可经明确用户指令或经过授权且证据足够的规则建立；纠错只更新/修订关系，不改写原始 Source、随机换资产 UID 或重建 Sample。无需为每个关系自动创建全新 UUID，除非它确实需要独立生命周期/引用。

**视图与载体**：Sample/Notebook 可以显示同一图或附件的多个关联，显示复用不必强制物理去重；是否复制实际文件属于存储与备份策略。移动文件/改文件名/改显示名称不应静默改变已确认关联。已被其他对象引用的资产不能因一个 Sample 取消关联而物理删除。清理须覆盖全部相关引用和历史删除决定，见 §6.3。

**权威实现保持开放**：元数据数据库（例如 SQLite）加独立文件仓库是可评估候选，不是本次已批准的强制迁移；现有 JSON、sidecar、App Support 及 Workbench 索引哪些仍含不可重建事实须先审查。一个数据库事务不能替代外部大文件可靠提交及恢复。

## 4. 人工观测、算法结果与当前采用

### 4.1 四种动作 [C/R]

| 用户意图 | 正式含义 | 不允许 |
|---|---|---|
| 更正既有手工观测，如 520 Ω → 500 Ω | 同一人工记录的新修订；按明确操作更新该范围的当前采用 | 虚构新 Measurement；偷偷丢掉仍被成果引用的旧修订 |
| 从算法结果出发手工改值 | 形成与算法原结果相关的人工修正/声明及其采用，不要求新增一种数据库表 | 覆盖算法原输出，声称算法自然算出了人工值 |
| 新条件或新的实际测量得到同值 | 新独立观测，保留条件与来源 | 因数值相同合并；因晚写覆盖另一条件 |
| 明确选用另一个已有 Result | 更新采用引用，保留所选 Result 自身身份/方法 | 复制成无来源的新事实；第二次强制确认 |

Parameter 编辑仍是一项简单用户操作，Enter/Save 等明确提交即可生效，不让用户先手动构造底层记录。G3a 负责将操作映射到正确动作；算法值的人工修正可以复用现有 override 表达，只要来源与作用范围清楚。

### 4.2 采用范围 [R]

定位至少使用当前用途真正需要的对象身份、Quantity/Role、Device/局部范围、条件和用途；未知条件不自动等于任意条件，也不默认为 0。**算法方法属于结果来源，不必然作为当前值的分组键**：用户可以在同一用途内比较并更换不同方法的结果，避免“每种方法各有一个当前值”让采用失去意义。需要并列方法视图时明确其用途。

`latestIndex` 可以是缓存，但其指向应由正式采用记录或可确定的修订制度派生。新 Result 保存、运行时间较晚、UI 重绘或同步到达不能自行移动人工采用。一次明示 Save 可以在 D6-A 已允许范围内保存并采用，不按任务分裂成两套政策。

## 5. 权威、修订与提交

### 5.1 每类记录必须有唯一写入责任 [R]

各首次正式写入任务都要明确：权威记录在哪里、谁提交、哪些是派生读模型、哪些旧系统仍保存独有信息、失败如何报告、恢复靠什么。D3 是逻辑责任，不要求将所有代码/数据搬到同一目录或新建一个巨型 Repository。

现有 Library 文件、App Support 的 ArchivedRecord、Sidecar、索引、Analysis Pack 和未来远端不能因名字被认定为废弃/缓存。**旧索引中无法从其他记录重建的信息，在安全迁移之前仍需保管。** 不可变恢复快照可合法存在，不是另一份可独立修改的当前真相。

### 5.2 ID、修订、等价键与运行键 [R]

- 永久 ID 回答“哪个对象”；修订回答“当时哪版内容/解释/归属”。形式可用版本号、不可变记录 ID 或等效机制，但必须能精确读回已声明版本。
- 处理输出固定输入与解释修订、方法和有效配置。新输入或科学配置不能覆盖旧结果内容、使旧引用悄悄指向新科学结果；可新建 Result 或形成明确的新结果修订。
- 内容哈希用于完整性/相同字节证据；等价键用于识别同目的同输入的重复产物；Run ID 用于运行追踪；提交操作标识用于重试辨认。它们不可互相替代，也不要求全部新增字段，可复用已有机制。
- 纯样式变化可以更新图修订或另存图，不生成新物理观测；数据来源与绘图配置仍可核对。
- 原始 Source 的已引用内容不得被后台覆写成另一份字节而沿用同一未区分的引用；源变化需新的可引用版本或新来源。旧来源不可取得时如实标记，不伪造完整重现。

### 5.3 提交与 Ready [C/R]

一次正式提交有明确业务边界：对象、必要引用、所承诺数值及对应状态保持一致。可使用原子提交或有确定恢复规则的分步提交，不宣称现有单文件 atomic 就提供全库/云端事务。

必须区分：未提交、已提交、部分成果已提交、提交结果未知需核对、失败待修复。提交成功但回执丢失时，重试先辨认本次操作及已有成果，不能另造 Sample/Result；相同内容的真实独立观测仍可保留。

Ready 只在该 Dataset 的必要内容及来源关系稳定可读后发布；允许某些 Role 尚未知，不保证任何分析均可运行。更新已就绪数据的解释/归属是新修订事件，不冒充首次采集；重复通知不是新实验。通知失败后的重发/对账机制由 G4/G5 选择，但不能让已提交的数据永远漏处理或无限重复处理。

分析开始固定请求；正式提交前检查当前授权、被删除对象和与结果相关的纠错。输入已被纠正时不得把旧快照结果当成基于新事实的当前结果。保留为历史/待复核还是取消提交，在当次合同明确，不临时猜测。

检查覆盖的是**受影响写入边界和完整依赖范围**，不是要求每次点击都扫描全库。若现有实现只能用全库检查证明安全，可先保留；优化不能以局部读取掩盖实际歧义或漏依赖。

## 6. 删除、改键、恢复与旧数据共存

### 6.1 立即适用的最低保护 [C/R]

1. Registry 记录缺失、编号变化、索引丢失或文件暂不可读，不等于用户授权删除科研对象。疑似 rekey 先解释/对账，不自动删旧建新。
2. 删除/改归属需清点本次会影响的存储命名空间、测量/图/指标/附件/采用引用；清点不完整就拒绝破坏性提交，不能只检查 Sample 抽屉。
3. 删除一个 Sample 的图关联不等于删除共享 Plot；共享资产仍被其他对象引用时保留其他有效关系。删除 Sample 的政策若未确定，不默认级联删除来源/成果。
4. 显式删除的对象/图必须留下足以在索引重建、同步/重试中识别该决定的依据；可用 tombstone 或等价机制，不预选格式，不要求无限保存所有旧文件。
5. 恢复同一对象使用原身份并恢复/验证关系；删除后“新建同名对象”分配新身份。历史别名和旧孤立产物不能自动改指新对象；无法消歧时保留未决或阻止受影响创建，待用户裁决。
6. 取消/回退迁移不能复活用户已明确删除的成果或撤销迁移后新增的有效人工修改。新路径已接受写入后，不得把“换回旧二进制”直接当数据回退方案。

完整默认删除模式、硬删除窗口和保留策略仍是 O-ID3。**在它未裁定的范围，允许先实现预览、依赖检查和安全拒绝；不把“以后可问用户”当作当前已经安全可删除。** 用户明确清理权不取消，只是危险动作不能绕过未建立的保护。

### 6.2 渐进切换 [R]

每次切换记录覆盖的对象/来源/消费者，以及仍使用旧引用的范围。先让相关旧引用经过统一解析，再逐步把新正式写入改为权威身份；不要求一次改完全部 Workbench。

在同一已切换范围中，旧直接写入仍然可以活动时，必须接入共同保护或明确阻断，不能只让新 UI 守规而保留绕过它的危险入口。只读旧路径可以保留，但不得伪装成新标准已完成。

T11 负责后续大批历史转换。G1/G2 的最小兼容与风险保护是今天的新消费者前置，不属于可无限延期的全库迁移。

### 6.3 清理操作词汇与未决定的默认政策 [C/R/O]

- **解除关联（Unlink）**：仅取消一个明确的 Sample—Asset 归属关系；不删除资产实体、原文件或其他有效引用。误归属更正应优先使用这一操作。
- **归档（Archive）**：候选的非日常展示状态；不等于删除，也不改变身份或科学结果。默认隐藏/自动化触发的确切规则仍待首次正式功能决定。
- **待删除/废纸篓（Trash）**：候选的可恢复删除流程；恢复窗口、保留证据、哪些对象允许恢复尚未获产品批准，不能因为设计列出名称就宣称已经实现。
- **永久删除（Purge）**：实际清除正式资产或载体；必须清点其仍然有效的共享引用、来源/派生依赖、备份和删除后防复活状态，在已授权的清理范围内执行。未获明确授权不能操作真实科研文件。

G1 可以先完成影响预览、依赖清点和危险路径安全拒绝，不需要先实现 Archive/Trash/Purge UI。真正启用其中一种状态转换前，须在 O-ID3 解决其权限、冲突、恢复、硬删除和空间释放承诺。**不预先选择 30 天恢复期，也不默认永远保存所有文件。** 物理删除已无人引用的重复载体可成为未来清理策略，但不能未经对账当作不会伤及独立科研证据。
