# SpinLab D4 — 共享分析能力与 Workbench 边界决策稿

**版本**：v0.1（首份可交接架构决策稿，非实现规范）  
**日期**：2026-11-08  
**范围**：科研分析能力的定义与契约、人工/自动调用、Workbench 职责、计算与保存及采用的边界、分析活动与成果语义、最小验证路径。  
**状态**：继承 D1/D2/D3 已确认决定；D4 新提出的规则标明“建议”或“开放”，未经用户逐项确认不得宣称冻结。未修改任何代码、真实数据、Library 或 PR；未构建、运行应用或测试。

## 0. 结论与建议

**把“一个有科研意义的分析能力”定义为：以明确且可追溯的科学输入、解释版本、方法版本及有效配置，执行有适用性约束的计算，产生独立于页面的有类型科研成果，并报告质量、警告与不可用原因。**

- **共享的是科学计算及一次分析的明确编排契约，不是 Workbench Store。** Workbench 与独立自动化可以用相同能力；两者不能各自重新解释文件列、使用另一套算法默认值或读取上次 UI 控件状态。
- **Workbench 是人工实验探索的操作面**：选数据、定范围、调整方法参数、比较、诊断、试算、制图；会影响数值的选择须在请求分析时固化为显式输入。字体、颜色、图例等只是渲染设置，不因重绘而改变科研数值。
- **计算不决定发表或采用。** D4 计算产生候选/可保存 Result；D3 是正式写入与 Parameter 当前采用关系的权威，D5 负责自动化触发、生效版本和授权。候选试运行不得改正式记录。一项明确的人工 Save 操作可在 D3 允许范围内同时“保存并采用”，但后台不能据“新结果”推翻人工值。
- **结果不等于 PNG**。AHE 要有带单位及条件的 Hc、R_AHE 和必要的数值曲线；AFM 要能表达处理后的二维矩阵、坐标与通道/单位，热图 PNG 只是映射。可以保留报告、图像等成果，但不能让它们成为唯一的科研数值表达。
- **最小验证必须成对**：AFM 验证脱离页面的显式计算与矩阵输出；AHE 验证 D2 表格语义、数值成果、条件作用范围及 D3 保存/采用。单独通过任何一条均不足以证明整个统一科研数据体系和自动化体系成立。

## 1. 继承的既定原则与 D4 责任

### 1.1 已确认（D1–D3 / V2 / 本次委托）

1. Sample 是科研知识中心；Batch、Sample、Device、Measurement 的身份、来源、量、单位、Role、条件、解释由 D1/D2/D3 在多个入口共享；D4 不因用户从某个 Workbench 进入而另造科研事实。
2. D2 负责来源结构、通道角色与物理解释，允许未知但不可伪造。解释确认或规则更新必须可定位版本及受影响来源。D4 只要求满足**当前能力实际需要**的输入，不让不相关的未知列阻塞分析。
3. D3 负责 Source ID、Standard Dataset、Sample/Device/Measurement 关系、正式 Result、清理/纠正/恢复以及 Parameter 当前采用。D3 当前确认的方向是将独立信号物化为带身份与来源关系的真实标准数据文件；文件格式未决定。D4 按**语义资产**消费，不要求所有能力读同一种物理格式。
4. 人工 Parameter 编辑确认立即成为同范围当前值；新计算与正式保存不无声推翻它。AHE 的明确人工 Save 可按 D3 规则一次保存并在适当范围采用；无授权的机器运行不能这样做。
5. 人工 Workbench 与独立自动化共享分析能力，独立执行不依赖页面打开或曾经的控件值；新增计算能力不必强制增加同名 Workbench 页面。
6. 候选试运行与正式执行相隔离；图像、数值、解释和决策的保留要有信息治理，不能把每次点击或重复计算都永久保存。

### 1.2 D4 负责 / 不负责

| 责任主体 | 应负责 | 不应负责 |
|---|---|---|
| **D1 共同语义** | 科研对象、Quantity、Role、条件及可比较性语义 | 编排某一具体算法 |
| **D2 数据接入** | 保留来源，解释轴、通道、单位、分量、Sample/Device 归属；提供版本化标准数据信号 | AHE 背景校正、AFM flatten、科研拟合；为 D4 猜测未知 Role |
| **D4 共享能力** | 声明适用性及输入契约；解析有效配置；执行科学计算；产出数值/曲线/矩阵及诊断；记录方法依赖 | 持久化科研当前事实、静默采用、运行调度、依赖页面状态 |
| **Workbench** | 人工选择、探索、调参、试算、比较、可视化、清楚地发起 Save/Adopt | 成为自动执行引擎或唯一配置来源 |
| **D3 成果治理** | Result 身份、正式保存、当前采用、版本/纠错/清理/恢复、对象归属 | 决定某算法如何拟合 |
| **D5 自动化** | 触发、步骤依赖、作用范围、能力/配置的生效版本、运行授权、候选隔离、失败策略 | 私有拷贝分析算法、改写 D3 正式规则 |
| **Library / Notebook** | 展示并组织上述正式记录与成果引用 | 复制另一套可修改的结果/Parameter 权威 |

上述概念是**逻辑职责与接口**，不是要求建立七个同名程序模块或一套统一的数据库 schema。

## 2. 什么算一项独立分析能力

一项能力至少回答：**研究什么、为什么这些输入适用、怎么算、何时不能算、得到什么可检验的科研结果**。例如“对带已知通道语义的 AFM 高度矩阵进行平面去倾斜”或“从已确认的 AHE Rxy–H 回线估算 Hc/R_AHE”。“打开某个页面”“画一张热图”“导入一个 DAT”本身不是完整的科研分析能力；渲染可以作为单独的展示能力。

### 2.1 最小能力契约（建议，不指定 API/schema）

| 必须声明的项 | 语义承诺 |
|---|---|
| **能力身份与适用目的** | 稳定能力标识、可理解的科研任务、输入/输出种类与适用范围；能力不必有独立 Workbench 页面 |
| **输入槽位** | 数值、曲线、矩阵或其他数据形状；明确哪些是 Source/Standard Dataset ID、哪条信号/通道/测量段/对象/Device；是否需联合采样对齐 |
| **解释需求** | Quantity、Role、谐波/分量、坐标/扫描轴、实际单位、符号与几何条件；必须有 D2 确认的来源或解释版本，不能由列位置重新猜测 |
| **科学前置条件** | 所需字段、有效数值与单位、数据形状、采样及扫描方向、条件与方法适用的最小要求；区分计算不可行与科学解释未充分确认 |
| **方法与有效配置** | 方法名称/版本、数据处理顺序、算法参数、阈值、拟合窗口、单位转换规则、随机种子（若适用）；调用前解析所有默认值，并保留有效值快照及重要来源 |
| **输出合同** | Result 类型、Quantity/单位、维度/坐标/分量、作用范围、误差/质量（若有）、warning/fallback、不适用/失败原因；支持无需渲染读取 |
| **依赖与重复性** | 记录输入/解释/方法/有效配置版本以及结果来源；同一科学请求不因入口不同改变结果语义。数值一致性由后续测试定义容差，不承诺跨平台逐 bit 相同 |
| **副作用边界** | 核心能力不写正式 Sample、Parameter、Library 或启用自动流程；候选计算在隔离范围运行；保存/采用通过 D3 的受控入口 |
| **失败行为** | 缺必需角色或单位、空数据、维度不一致等要返回明确状态，不能用 0、上次参数或空 PNG 伪装成功 |

**“有效配置”指执行当时解析完默认值、方法预设和明确覆盖后的实际计算配置。** 用户改了全局默认值或重开 Workbench，不得改变历史运行的解释。选择通道的自动默认也应在启动前解析、记录最终被选通道及选择依据。能力声明可以包含各自真实的方法差异（AFM plane level 与 AHE 高场背景处理不会因共同接口而强行共用一份参数表）。

### 2.2 缺失条件不是一个布尔状态

建议按三层分开报告：

- **不能计算（blocked）**：缺少矩阵、没有与信号配对的有效扫描轴、必要单位不兼容、所选 Channel 不存在、必需解释冲突、拟合所需数据点不足等；没有有效数值 Result。
- **能计算但解释受限（provisional / needs review）**：能产生数值，但是必要的物理适用性证据不充分，例如不完整回线、未达到饱和却使用替代估计、AFM 通道物理类型未确认但对其做了通用矩阵处理。保留输出、限制自动采用及科学表述，不假装“确定 AHE Hc”或“确定高度”。
- **能计算且具备已声明条件（valid for stated method）**：满足所声明的数据与方法前置条件，仍不自动等于科学结论普适成立；不同方法可存在真实差异。

未关联 Sample、未知温度等，**不一定阻止数值计算**，但会限制结果被归档到哪个对象/条件及是否能成为特定 Parameter 的当前值。未知不相关 Channel 不阻止其他信号分析。正式结果应至少有清楚的用途与归属范围；尚无法归属的试算可保持候选。

## 3. Result 与显示图的边界

| 形式 | 科研内容是什么 | 什么只是显示映射 |
|---|---|---|
| **Scalar / Quantity** | 数值、物理量、规范单位、对象、温度/Device/方法条件、来源与质量，如 `Hc`（T）、`R_AHE`（Ω） | 小数位、显示成 Oe 或 T、表格排序、色彩标记 |
| **Curve / Series** | 有顺序的 x/y 数值、各轴物理量/单位、Trace/Retrace、处理状态、分段、有效范围和来源 | 线宽、点型、纵向视觉错开、坐标轴显示范围、图例位置 |
| **Matrix / Multichannel** | 二维数据、像素/实坐标系、单位、Channel/Role、处理参数与矩阵的数值内容；例如 AFM flatten 后高度 | 伪彩色、色标、屏幕插值、热图缩放、标题 |
| **Scientific image / photo** | 原始有意义的图片本身可以是 Observation；有标尺/标定的科研图像也可成为数据资产 | 从同一数值矩阵渲染的 PNG/JPEG 不自动成为新的独立观测 |
| **Report / Comparative result** | 文字结论、引用的各项 Result、使用的比较范围/方法及重要限制 | 排版 PDF/HTML、封面、图版布局 |

结果至少要能通过**有类型的数据或可可靠读取的数值资产**使用，不能只有 PNG。对已正式保存的、有长期科研意义的派生曲线/矩阵，建议默认保留可独立访问的数值成果；具体是持久化完整数值还是保留可校验的标准数据引用、格式/缓存策略，由 D3/D6 在实施时决定。临时显示重绘不产生新的 Result。

**重要界限**：视觉上裁剪坐标轴范围、隐藏某条线、改变颜色标度通常只是显示；若选取 ROI、剔除点、改变拟合窗口、平滑后参与计算，或选择哪些分支参与 Hc 提取，就属于**科学输入/方法配置**，必须显式记录。相同 PNG 外观不能证明科学结果相同，图片变化也不等于数值变动。

## 4. Workbench：探索状态与显式分析输入

### 4.1 保留在 Workbench 的职责

人工检索、选择与预览 Sample/Device/Measurement，组装分析请求，尝试不同方法/窗口、比较多个结果，显示 warning/诊断、展示多图层和图例；可将当次探索中有效的科研选择明确固化成配置并发起正式分析。Workbench 也承担方便的 Save/Adopt 人机交互，但不拥有写入政策或“当前真相”。

### 4.2 哪些 UI 状态必须成为显式输入

- **AFM**：选中的数据集/源 Channel 与明确的 Trace/Retrace/Height/Phase 角色、实际坐标与单位；Plane/Robust Plane、Line Flatten 阶数、Zero Reference；若先裁剪/遮罩再处理，ROI、mask 或有效像素也属于输入。新的文件是否沿用旧配置必须是**明示的当次选择或预设**，自动化不可取 Store 中的 `carriedConfiguration`。
- **AHE**：所用 Sample/Device/Measurement/信号，H 扫描轴及其单位，已确认的 Rxy/Hall 角色或合法电压到电阻转换；电流（若转换需要）、温度/器件几何与测量方向；用于计算的扫描分支、背景方法和高场窗口、阈值、Hc/R_AHE 定义、数据点排除规则、聚合/对应关系。用户对指标的手工改值是后续明确的**修正/采用动作**，不是静默替代算法输出。
- **显示专用**：AFM 色图/色标范围/屏幕插值/标题、AHE 图例/配色/纵向 stacking gap/字体/显示单位/画布轴限（不影响数据处理时），保存为绘图方案即可。若某设置真正改变参与数值计算的数据，就不能继续称作显示专用。

建议每次调用先形成固定的“**分析请求快照**”（身份引用、解释、有效配置、方法、对象及作用范围），再调用 D4。人工调整控件只改变下一次请求，不回头修改已经完成分析的科学含义；后台任务启动时即冻结快照，途中界面变化不静默改变任务。

## 5. 计算、候选、正式保存与采用

| 动作 | 责任 | 可产生/修改 | 禁止 |
|---|---|---|---|
| **分析请求验证** | D4，使用 D2/D3 的语义与正式身份 | 明确 blocked/provisional/valid、缺失项和适用性诊断 | 擅自补 0、猜 Role 或以文件名替换已确认解释 |
| **科学计算** | D4 的可独立调用能力 | 数值、曲线、矩阵、方法与诊断、运行输出 | 修改原始 Observation、Parameter 当前值、正式 Sample |
| **人工探索** | Workbench 提供 UI，D4 执行 | 内存预览、比较、拟议配置 | 把 UI 控件及上次状态变为自动执行的隐形依赖 |
| **候选试运行** | D5/用户发起，D4 计算，候选区管理 | 临时或可清理的候选 Result 与验证记录 | 写正式 Library、触发正式下游写入或改变采用 |
| **正式保存** | D3 的统一写入/成果治理（WorkBench 或自动化可请求） | 新建/复用正式 Analysis Result、引用、历史与当前展示索引 | 以 PNG 代替结果、无保护追加或吞掉局部失败 |
| **当前采用 / 人工修订** | D3 按人工确认与授权规则裁决 | 明确对象、Quantity、条件、Device/用途范围下当前被使用的 Result/Parameter | 依据最新时间戳或机器重算推翻人工已确定的值 |
| **任务触发/授权** | D5 | 哪些数据/何时/用何能力版本执行及是否允许请求正式提交 | 自行定义第二份分析算法或 D3 权威 |

一个结果可以**已正式保存但没有被当前采用**；候选运行可以有数值但没有进入正式科研档案。经人工确认的单次 Save 可同时表达保存与适用范围内的采用——继承 D3 已确定的 AHE 行为，不要求两次普通点击。自动化只能依据**事先明确授予的作用范围和决策权限**请求保存或采用；默认后台重算不改变人工值。

**人工校正**建议记录“算法原值 → 人工修正值”的关系及修改时间、作用范围、必要的解释/方法背景；理由可选，且不把修改值伪装成算法自然输出。若后来解释或输入被纠正，D3 标记相关 Result 待复核，由用户决定是否重算或清理，不自动重新诠释旧结果。

**重复与清理**：相同来源资产/解释版本/方法/有效科学配置/分析作用范围下的等价重算可复用已有成果或刷新必要缓存，而不反复新增同一正式数值；但不同真实测量、不同分支、不同方法版本或不同解释版本，即使数值恰巧相同，也不应被误去重。渲染风格变化不增加新科学 Result。任何清理需尊重被引用证据及人工已采用结果。

## 6. 分析活动与成果：未来可复用、可纠正、可理解的证据

建议区别以下概念（**不是强制表名**）：

**Analysis Activity（分析活动）**是一项有确定输入、解释和计算目的的执行事件，可包括：

- 运行时间、发起者类型（人/已授权自动化/候选）、目标科研对象与意图；开始时冻结的 Source/Standard Dataset ID、所选信号、段、条件、角色/单位及解释版本。
- Capability/Method 标识及版本、解析后的有效科学配置及其来源、关键软件/校准版本（仅在影响结果时记录）；重要的处理/选择顺序、共同采样/对齐依据。
- 运行状态（成功、部分成功、blocked、provisional、失败）、适用性与质量诊断、明确的 fallback、结果引用及必要错误；多输出/多样品按各自范围记录，不以整批“成功”掩盖个别失败。
- 重要用户判断：主动校正、接受/拒绝候选、选择哪个结果用于何种目的及其作用范围；理由用户可填、不强制、不由 AI 猜测。候选试算的无价值重复日志可治理/清理，普通点击不记录成科研经验。

**Analysis Result（科研成果）**是该活动产生的独立可引用数值资产：量/单位、维度、坐标、对象/测量/Device/温度/信号/方法作用范围、质量和生成它的 Activity。一个活动可产出多条 Result；AHE 的 Hc 与 R_AHE 是两个可引用结果，曲线可另为结果；AFM 一个处理矩阵是一份 Result，不必与一张 PNG 一一对应。

**Visualization Artifact（显示成果）**引用既有 Result 或数据及绘图配置，承载 PNG/PDF/热图等，而不是另一份科研真相。**Adoption/Correction（采用/修订决定）**独立记录当前选用的结果或人工值、适用范围和必要修订线索。**Reusable Experience（经验/规则候选）**是从有背景的成功或失败及人工判断中提出的假设，不能因一次手工调整自动成为对未来所有数据有效的规则。

## 7. AFM 与 AHE 对照走查

| 项 | AFM | AHE（表格） |
|---|---|---|
| **科研任务** | 将特定 AFM 通道的二维观测按指定去倾斜/逐行 flatten/零点处理，得到可解释的处理矩阵 | 将已确认的 Hall 信号对 H 的扫描进行必要背景处理，提取有定义与适用范围的 Hc、R_AHE 与校正后的 Rxy–H 数值序列 |
| **输入** | 标准 AFM 矩阵、物理坐标、源通道身份和角色/单位、源文件及解释版本 | 标准信号/场轴配对数据、Sample/Device、H 单位、Rxy/Hall 角色、温度与方向/扫描段、解释版本 |
| **计算配置** | 所选 Channel、surface level、line flatten 阶数、zero reference；涉及 ROI 时须纳入 | 背景扣除方法/窗口、分支与排序、饱和/过零判定与拟合规则、转换所需电流、输出量定义与阈值 |
| **数值成果** | 与源对应的二维矩阵和 x/y 坐标、单位、warning、处理关系 | Hc（T）、R_AHE（Ω）、校正后的带序扫描曲线、诊断及失败/fallback 标记；不误写成 ρxy 或 σxy |
| **只属于显示** | 色表、标题、标尺绘制、图像插值、色域映射 | 色彩、legend、视觉堆叠、可见坐标窗、绘图轴采用 Oe/T 哪个显示 |
| **不可缺** | 可用矩阵、维度匹配、选定通道、处理所需坐标及单位；不能把 Phase 擅自称 Height | 可用并配对的 H 与信号、有效单位与物理角色、满足对应方法的扫描与质量门槛；仅有 Bridge 编号不证明 Rxy |
| **检验重点** | Store 脱钩、显式默认值、矩阵成为结果、图与数值分离 | D2 解释、单位/条件、数值结果、按 Device/通道/测量段归属、保存与人工保护 |

### 7.1 AFM 一次完整分析不是“已有纯函数”

已有 `CanonicalAFMDataset` 记录 `sourceIndex/sourceLabel/semanticTypeRaw`、单位、坐标和矩阵；`AFMProcessingPipeline.process` 从不可变源矩阵做 Surface Level → Line Flatten → Zero Reference，算法边界较清晰。但 `AFMWorkspaceStore._runAnalysis` 仍负责文件与默认通道选择、继承 `carriedConfiguration`、捕获显示状态、执行热图渲染与并发取消等。`renderHeatmap` 还读取显示状态和 `globalPlotDefaults`。因此**独立调用处理函数不等于“AFM 端到端无 UI 依赖已通过”**。现有图表正式保存为 PNG/manifest/索引；含完整标准矩阵的数据集放在恢复用 Analysis Pack，不能据此声称派生矩阵已经作为长期 Result 正式保存。

针对 D4 的建议是把“明确输入与配置 → 处理矩阵和诊断”的**科学分析单元**与“处理结果 → heatmap/PDF”的**显示单元**分开。允许用户当次在 Workbench 一键执行这两步，但独立执行只需第一步也必须有效。若自动保存图像，渲染配置也要显式传入，不能偷用全局显示偏好。选不到请求的通道时，应告知并按**预先明确**的默认策略处理；不得偷偷继承其他分析对象的通道状态。

### 7.2 AHE 应当作科研能力与数据治理的关键反例

目前 AHE 的读取层在 `IngestAHESelectionsUseCase` 中按 `Bridge N Resistance (Ohms)` 和 `Magnetic Field (Oe)` 的原始名称查找并配对，再将 Oe 转为 T；它不证明 Bridge N 就是 Rxy。背景扣除在 `AHEBackgroundCorrectionUseCase`；指标由 `ExtractAHEMetricsUseCase` 从背景校正后的、未视觉堆叠的曲线计算，`AHEWorkspaceStore` 将结果挂在最近一次渲染状态并负责写指标。这证明**部分计算已独立封装，但整次分析和来源语义仍未完全解耦**。

需要明确的科研问题，不在本轮修改算法：

1. **结果作用范围不足**：现有指标聚合按 `sampleID/sampleKey`，同一 Sample 的多 Device/多通道/多温度/多段可能需要多个互不覆盖的结果。不能以“一张图含多个系列”自动等价为“一个 Sample 只有一个 Hc”。应保留每个实际信号与条件的身份，再由用户指定是否汇总。
2. **退化数值不能伪装成有效结论**：当前单曲线提取在点数不足时会返回 `(0,0)`；无过零或双侧高场平台时存在替代估计分支。新契约必须区分物理真值 0、缺失、fallback 估算和科学适用性未获验证。是否采用某个高场比例、过零方式、对噪声/回线不闭合如何处理，交后续科学方法专题。
3. **单位与方法需绑定**：当前存储 Hc（T）和 R_AHE（Ω），但是否有充足饱和、如何判分支与背景、是否为电阻而非电阻率、设备条件如何影响有效范围，均应可追溯；**图片和 `sampleKey` 单独都不够**。
4. **写入仍需保护**：指标写入口会追加记录并更新 `latestIndex`；这是可静态观察的实现。不能推导现在已有自动化覆盖人工值的运行事故，但未来若自动写指标，必须由 D3 显式决策是否移动当前采用指针。新的 Result 可以保存到历史而不自动采用。
5. **显示不应影响 Hc/R_AHE**：是否只改变色彩、图例或视觉 stacking，不得改变数值。若手动点选窗口改变了高场拟合与提取，它就变成有效科学配置，而不是显示偏好。

可用一份**已确认 Hall 角色的 PPMS 测量**做有条件的小闭环，而不要求先支持所有 DAT/LVM 版本，也不提前把 3ω AHE 与 1ω AHE 算法混成一种能力。若加入 3ω，需额外声明电流 RMS/峰值、谐波与锁相分量、V/I 关系、方法公式和输出量身份；D2 已确认的 `3w` 文件名规则只能作为其限定范围内的解释依据。

## 8. 最小验证路径比较与推荐

| 候选 | 能证明 | 不能证明 | 必要前置 |
|---|---|---|---|
| **A. AFM 独立分析薄切片** | 明确矩阵+通道+科学配置在无 Workbench 的情形执行；人工/自动共用计算；处理矩阵和热图分离；显示状态不污染数值 | DAT/LVM 通道语义、AHE Hc/R_AHE、Parameter 当前采用与规则前台管理、完整调度系统 | 可信 AFM 样例；稳定通道身份、有效配置/默认策略；离开 Store 的一次分析编排；matrix Result 契约。若验证正式保存，需有 D3 对象关联及保存合同 |
| **B. AHE 表格语义—数值薄切片** | D2 已解释的 H/Rxy 信号可被 D4 消费；单位与 Device/条件不混；结果包含曲线/标量而非 PNG；无效输入能被拒绝/标注 | AFM 矩阵、渲染独立、D5 前台启动/停用、全类型 DAT/LVM 支持 | 单 Sample、单 Device、单 Channel 的可靠样例与解释版本；明确方法定义及质量判据；最小数据映射/单位/结果类型 |
| **C. AHE + D3 Save/Adopt 小闭环** | 正式 Result 与当前 Parameter 区别、人工优先、不同条件互不覆盖、纠正/重算/去重 | 独立后台调度已可运行；全部 Workbench 已完成共享化 | B 成立；D3 当前值/身份治理入口；人工已有值与后台新值的冲突案例；保存失败路径 |
| **D. 先重构全部 Workbench** | 可以一次性处理更多旧耦合（若做成功） | 不能以“改了架构”代替科学与运行验收；成本及回归风险过大 | 大量额外前置，**不建议作为最小验证** |
| **E. 简单 RT/IV 表格辅助试点** | 可较便宜地验证表格轴、单位、曲线与 Standard Dataset 的复用 | 不能替代 AHE 的高场方法、Hc/R_AHE 数值及人工采用 | 一组角色清晰的标准数据；可与 B 共享底层读取/解释，不必成为正式首选 |

**推荐路线：A 与 B 是相互补充的最小“双切片”，先各自证明不同的事；C 是必须追加的治理验证；D5 再用同一已完成能力合同驱动独立执行。**

- **阶段 1（契约/隔离验证）**：给一个 AFM 的明确输入/配置/处理矩阵结果，以及一个 AHE 的 H/Rxy/条件/方法→数值成果，分别形成可独立调用边界。可以复用现有读取器与科学函数，不提前移植所有 Workbench。
- **阶段 2（治理验证）**：在已确认的少量真实/隔离样例上核查一源多信号、不同 Device 与温度、结果与图分离、修正解释标记待复核、正式保存/采用、重复运行不膨胀。D3 写入口正式保护是自动保存指标前的门槛。
- **阶段 3（自动化验证）**：D5 前台建立、修改、停用一个真实流程，以明确生效配置调用 A 或 B。无需打开对应 Workbench；执行中的请求版本固定；候选不写正式；授权保存遵守 D3。
- **阶段 4（交叉等价检验）**：人工和自动对同一 Source/Standard Dataset、解释版本、方法和有效配置调用，核对数值/矩阵及质量状态在约定容差与语义上相同。不同绘图样式不影响科学输出；不把 PNG 像素一致作为核心判据。

**三个不同的验收证据**必须单独汇报：①科研方法是否适用于所选实验（需要专家/样例判断）；②算法代码是否按契约运行且结果可信（后续单元、对照与回归测试）；③UI、自动化、D3 保存/采用链路是否连通且权限正确（后续集成与真实用户场景）。只读源码审计对后两项均不是运行通过的证明。
