## 0. 一页结论

**D2 的任务不是把 DAT、LVM 统一成一种文件格式，而是把来源数据解释成带有科研含义、依据和未知状态的可复用数据。**

推荐逻辑：**来源/手工输入 → 结构读取（必要时）→ 来源规范识别 → 实验含义与归属解释 → 标准数据及未决项 → D3 正式管理 / D4 科学分析**。

- **同一来源可服务多个科研对象**：一份三通道 DAT 可向三个 Sample 提供三个逻辑标准数据视图；这些视图共享原始采集关系，不因此变成三次独立实验。一个 Sample/Device 的同次测量也可包含多个 Channel。
- **Channel 与科研角色分开**：PPMS `Bridge 3`、Zurich LVM `2nd` 是来源通道；`Rxx/Rxy`、`1ω/2ω/3ω`、测量方向、归属 Sample/Device 均需独立依据。
- **不知道的先保留**：未知一列不阻塞文件接收和其他分析；只有特定分析确实需要该含义时才请求补充。用户可主动管理解释。
- **人工裁定不自动推广**：本次文件的确认立即生效；用户主动保存规则后，匹配的**新**文件才自动复用。历史文件由用户选择是否批量应用。
- **重解释不偷偷改成果**：修正后向 D3/D4 提供解释版本与影响范围，旧成果保留并提示复核；不自动覆盖、重算或删除。
- **不预设存储实现**：D2 交付逻辑标准数据及对象关联候选，不规定必须生成三个物理文件、采用 JSON/数据库、建立新 `Acquisition` 或 `Channel` 表。

## 1. 负责范围及边界

**D2 负责**：不同入口的数据接入语义；文件结构和原始列保留；来源命名规范；可证实的物理量与单位识别/规范转换；Channel 分组、分量、扫描轴、固定条件和实验角色的解释；从文件/规则/人工输入得到 Sample/Device 归属线索；解释规则的使用逻辑；未知与冲突；交付可被多个分析复用的标准数据；重解释的变化和影响线索。

**D2 不负责**：正式对象身份和权威数据的读写、目录/物理文件格式、恢复/清理、采集去重裁决、Parameter 当前值；拟合、背景扣除、V/I 等科研计算；自动化触发和 AI 训练。这些分别由 D3、D4、D5 及主架构负责。

边界原则：**D2 可以提出“这个信号应归属于 PN55 的 Device A”的解释，但不能私自创建另一套 Sample/Device 权威；D3 确定正式身份和关联。D4 不能再根据原列号/文件名重复猜解释。**

## 2. 上游已确认约束

来自 D1/V2，不由 D2 重新决定：

1. Sample 是知识中心；Batch、Sample、Device、Measurement 使用共同科研语义。Device 是 Sample 上独立加工器件；Measurement 可以针对 Sample 或 Device，并可包含多路信号。
2. 物理量、单位、来源通道、科研角色、扫描条件、固定器件角度、扫描角度等是不同含义；同名、同值、同单位不证明同一观测。
3. 手工定量记录可不依赖 Measurement 独立存在。用户修改 Parameter 并明确确认，即成为当前值；新分析结果不自动覆盖它。
4. 观测、标准数据、分析结果、当前采用值、解释规则分开；人工明确判断优先；信息允许未知；必要历史可追溯、重复信息可治理。
5. 同一 Sample 切块的局部语境暂不定，不预设 Piece 实体；持久身份机制、权威映射和物理格式留给 D3。

## 4. 输入工作流：同一科研语义，不强制同一种入口

| DAT/LVM/以后新来源 | 读取完整来源、列/Channel/轴/单位线索；解释来源规范和已确认的实验约定；交付标准数据及未知状态 | 每个 Workbench 分别适配文件格式；缺的字段默认写 0 |

## 5. 最小科研解释结构：各维度分离

**概念关系（不是强制表名）**：

- **Source / 原始来源**：原始字节、表头、原列名、单位文字、文件名、导入信息、来源证据；路径仅作线索。内容指纹帮助识别相同字节，不单独决定是否同一次科研采集。
- **Measurement / 采集语境**：一次采集及其共同扫描轴、固定条件、时间等；跨 Sample 共用原始采集的关联必须可表达。是否建立专名 `Acquisition` 的持久实体由 D3 协商，不与 D1 Measurement 平行另立权威。
- **Channel / 来源通道**：来源内一组相关信号列。DAT 的 Bridge N 含 Resistance、Resistivity、Excitation 等；LVM 的 `1st/2nd` 各含 X/Y/R/Theta。原始列及分量也须保留。
- **Quantity / 单位**：Voltage、Resistance、Temperature、Magnetic Field 等，与其合法单位；LVM 表头无单位时不能单凭直觉标成 V、Oe 或 A。`Resistivity (Ohm)` 与 `(Ohm-m)` 有冲突，不能用 Resistance 直接替代。
- **Role / 实验角色**：纵向/横向、AHE/AMR/PHE 用途、1ω/2ω/3ω、锁相 X/Y 分量等；每个角色需有独立解释依据。**锁相 X/Y 不等于测量几何 xx/xy**。
- **Conditions / 角度语境**：区分扫描轴、固定器件角度、仪器位置以及温度/磁场等固定或变化的条件；保留正负号、原始单位、来源。
- **Object Binding / 归属解释**：某 Channel/信号关联哪个 Sample/Device、依据何在、是否未决；正式对象关联由 D3 裁决。
- **Projection / 标准数据视图**：面向一个 Sample/Device 或一次测量用途，组合必要信号、共享扫描轴、条件、来源和角色。一个视图可含多个 Channel；一个 Source 也可有多个视图。**Projection 是逻辑契约，不预选新物理文件。**

## 6. 来源规范、人工裁定与可复用规则

### 已经用户确认的行为

- **D2-01**：首次人工解释（如当前 DAT 的 Bridge 3 = Rxx）**仅对当前数据立即生效**；以后再打开同一数据不必重复确认。
- **D2-02**：仅在用户主动将解释保存成规则后，才按规则明确匹配范围自动用于**未来新数据**。不引入强制的“实验配置”实体；不要求每次重新证明接线没有变。
- **D2-03**：新规则发现匹配的历史文件时，只展示可选应用范围/数量；**是否应用由用户决定**。不能越过既有人工裁定。
- **D2-04**：人工针对当前数据的明确解释优先于自动规则。多条规则对同一含义冲突且无法确定优先关系时，不擅自择一，提示处理。
- **D2-05**：错误解释修正后，旧分析成果**保留并标记需要复核**；用户决定重算、删除或继续检查，系统不自动覆盖。
- **D2-06**：导入时允许未知角色；不需要该角色的流程继续运行。只有某项分析确实需要它时才请求补充；用户始终能主动管理。

### 对这批 LVM 的已知实验约定

用户说明：在当前使用的 LVM 命名语境中，文件名带有独立 `3w` 标记（`w` 表示 ω）时，**第二个 Channel 在相应 3w AHE 测量中承担三阶 AHE 信号角色**。这是用户确认的**实验命名约定**，不是 LVM/Zurich 的硬件通则，也不能把 `2nd` 本身解释为二阶谐波。

该约定可以作为 D2 的规则依据；正式保存为可自动匹配的生效规则仍遵守上述“主动创建/适用范围”原则。碰到 `IV_3w`，**Current 扫描轴**与 **3ω 信号角色**可以同时成立，不强迫归为互斥的单一工作流类别；具体分析由 D4 判定。

### 建议的规则原则（尚未由用户逐项确认）

1. 将**来源规范**（如当前 PPMS `Temperature (K)`、Bridge 列组）与**用户实验解释**（如 Bridge 3 = Rxx）分开。前者在证据充分时自动识别；后者遵守人工确认和规则生命周期。
2. 规则的匹配条件由用户管理，可依据来源类型、原列/通道、文件名 token、实验范围等组合；匹配条件之外不生效。不能因为当前数据都同版就推广为所有 PPMS 或 LVM。
3. 每项解释记录依据：原始声明、来源规范、用户规则、针对当前数据的人工裁定或 Spin Cat 候选；保留规则版本/生效范围。AI 建议不直接成为正式事实。
4. 正在使用的数据应依赖确定的一版解释；规则变更不暗中改变已完成分析所依赖的解释。

## 7. 未知、冲突、异常与重解释

**建议把三件事独立描述，避免一个笼统的“未完成”状态**：

- **数据存在性**：有数值 / 原列缺失 / 无有效数值 / 被截断或无法解析。
- **解释状态**：有来源依据的已知或人工确认 / 待验证候选 / 未知 / 冲突。
- **分析适用性**：由 D4 的能力契约说明所需条件；“存在未知”不等于“整份数据不可用”。

反例和必须保留的诊断：

- Bridge 3 有 Resistance，却未知 Rxx/Rxy：照常接收，可展示原始电阻；依赖 Rxy 的 AHE 分析才要求补充。
- LVM 表头明确 `Current`、文件名同时含 `3w`：不能由工作流名把 Current 换算成磁场。
- LVM 后半 10 列尚不知是什么：保留原始列、相关性和异常提示，不能静默丢掉；也不强推为额外硬件 Channel。
- `-8 T`：标准化后仍为负号明确的 `-8 T`，不得成为 `8 T`。
- 文件名同名而内容不同：不能因文件名相同就拒收或合并为同次观测。
- DAT 列 `Resistivity` 出现 Ohm/Ohm-m 不一致：保留原单位文本，标记物理量/单位疑点；不能自动用 Resistance 代替。
- 同一文件已有人工确认 Rxx，后来新规则建议 Rxy：当前人工解释保留；规则不静默覆盖。

**修正解释的交付**：D2 指出变更前/后的含义、依据、涉及哪些来源/通道/对象视图和解释版本，并向 D3/D4 提供受影响关联；D3 管理历史成果与复核标记，D4 提供可选重算，不覆盖已保存成果或 Parameter。

## 9. D2 → D3 / D4 最小接口承诺（语义，不是 schema）

**D2 向 D3 提供**：

- 来源证据（文件名/可能的内容指纹/头部/原始单位文字/时间与时区假设）、完整列与 Channel 列组、共同扫描轴及固定条件。
- 每个信号的物理量、单位、分量、实验角色/谐波、解释依据及未知或冲突状态。
- Sample/Device 归属的已知线索或候选、Channel 与对象关联的适用范围；单一来源可有多个对象视图，并保留共同采集关联。
- 规则版本与重解释变化，原始值和解释状态的分离，以及需要检查的下游依赖范围。

**D3 向 D2/D4 应保证**：正式 Sample/Device/Measurement 及共同采集关系的稳定身份、正式来源和关联、可定位的标准数据视图、权限与生命周期；旧 sidecar/Domain/Library 路径的兼容。D2 不建立私有持久化体系。

**D2 向 D4 保证**：可按明确语义和来源取得适用的标准数据（必要的轴、信号、条件、角色、对象及未决信息）；D4 不需要读 `Bridge N` 列名或 LVM `col5` 才知道输入是什么。但**D2 不保证**每项分析所需条件全部具备、物理模型正确、原始源单位总能解析，或某个计算结果已经有效。

**D4 应声明**：每个分析需要何种 Quantity、单位、角色、几何、扫描变量和前置条件；执行必要的科学计算并形成方法与配置明确的 Result；正式保存与当前采用由 D3 管理。

## 11. 对 D3 / D4 / 主架构的待协调清单

**D3（正式写入前必须协调）**：

1. 一份原始来源、多 Sample/Device 与 D1 Measurement 的关系，及是否需要独立的共同采集标识；一源多视图是否物理复制、引用或混合。
2. Device 正式身份与 `wafer`、`60deg`、`device5` 的区分；用户改变归属、重命名及同设备重测如何表达。
3. 旧 Library 文件+相邻 sidecar 的读侧约束、`hit.id=sidecar path`、图表/Analysis Pack、去重、删除及恢复怎样兼容；不能未经迁移直接删除副本。
4. 已有 `SpinLabDomain.ArchivedRecord` 的真实持久化与 Library 权威关系；旧 sidecar 的部分缺失与 `sourceFilePath` 历史两种语义。
5. 解释版本如何保存、历史成果如何标记复核、人工 Parameter 如何不被新 Result/最新指针覆盖。

**D4（共享能力合同前必须协调）**：

1. 哪些能力实际需要 1ω/2ω/3ω、Rxx/Rxy、波形分量、Device 角度、单位或电流有效值；缺失时如何告知 D2 补充，而不是悄悄推断。
2. `IV_3w` 的 Current 扫描与 3ω 角色如何同时被消费；`I_rms`、`V/I`、背景处理、AHE 提取归科学计算而不藏在统一器。
3. 旧 Workbench 仍按列位置及文件名解释的过渡方式，以及统一数据被多个分析复用的验收。

**D5 / 主架构**：解释规则的前台可编辑、有效版本、Spin Cat 候选与正式规则隔离、变更影响预览；D6 收敛一致的身份/接口与最小实施路线。

**未阻塞 D2 的开放项**：21 列 LVM 后半的硬件意义、Zurich 解调器编号、完整 Quantity/Role 词汇表、具体存储格式与界面控件。它们应保留未知或作为实施测试，而不是用猜测补全。

## 12. 建议送回主架构的决定

1. 将**“一份原始来源可以提供多个对象的逻辑标准数据，但必须保留共同采集关系”**列为 D2→D3 的核心接口需求，不立即指定几份物理文件。
2. 将**Channel / 分量 / 物理量与单位 / 实验角色与谐波 / 条件与角度角色 / Sample/Device 归属**作为独立的语义维度；不要求全部成为数据库实体。
3. 将**“来源读取不能静默丢列、丢符号；工作流不能覆盖有依据的来源轴类型”**列为 D2 的验证约束。
4. 保留当前已有文件副本与 sidecar 的兼容行为，等 D3 完成身份、读侧、成果和清理契约后再讨论改变物理存储。
5. D4 必须消费已解释的数据并声明必需条件，不再自行从文件名和固定列位置定义另一套科研含义。
