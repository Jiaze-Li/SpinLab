## 0. 目标、确认事项与本次收敛

**已经由用户确认、不得由实现者擅改的产品原则：**

1. **Sample 中心**：每个明确创建的 Sample 有终身稳定的 `sampleUID`，同属性的两次独立创建仍是两个 Sample；Notebook 只是视图。
2. **人工 Parameter 只有当前值**：生长温度、日期、衬底、氧压、尺寸、手填电阻等全部作为 Sample 字段；普通更改直接覆盖，**不创建 Observation/Revision/Adopt 日常历史**。
3. **科研资产身份独立**：Source、Dataset、Result、Plot 以及按需 Attachment 均有稳定身份；名称、路径、内容哈希及拼接父 ID 不能取代身份。
4. **Live 自动跟随**：Result/Plot 知道所需输入；Parameter、Dataset 或有效科学方法/解释变化后，受影响的 Live 输出刷新或标记不可作为当前成果。
5. **Snapshot 用户主动保存**：只有明确保存时才固定结果及必要的直接与间接输入，日常变化不累计历史；快照不跟随 Live 漂移。
6. **最少必要关系**：Sample—Asset 关联与数据派生关系分开；允许多 Sample、多 Dataset；不预建通用图数据库、庞大工作流平台或整库迁移。

继续保留：**原始 Source 的可信原貌；统一器只做结构/格式标准化及有依据的等价单位表达，不做科学处理；人工数据与计算 Result 分权；共享资产只解除某处关联不等于全局删除；未知科研角色/归属不得猜测；任何必要安全备份、重试证据不等于可浏览的修改历史。**

**本次主要变化：** 明确 Dataset 当前内容与受保留内容的边界（F01）；完整、无歧义的依赖解析和失效/提交规则（F02）；无历史的 Parameter 幂等并发写入（F03）；Snapshot 的传递依赖闭包和固定归属（F04）；合法的标准数据更正/再解释（F05）；Live 对象重算、操作重试、独立新分析的身份区别（F06）。

## 1. 精简的正式对象模型

| 对象 | 是否独立身份 | 当前权威事实 | 本合同不要求的东西 |
|---|---|---|---|
| **Sample** | 永久 `sampleUID` | 可编辑的人工 Parameter、明确 Batch/必要对象范围、资产关系 | 按材料属性推断同一性，按样品名生成永久 ID |
| **Parameter** | **无单值 UUID**；由 `(sampleUID, fieldKey, exactScope)` 唯一定位字段槽位 | 当前有类型的值、单位/角色/条件、轻量并发校验标记 | 每次修改的 Observation、Revision、Adopt/人工采用对象 |
| **Source** | 独立 `sourceID` | 已登记原始来源、其字节/完整性证据和正式定位 | 将另存副本/改名当成新实验，把 Source 直接当计算 Result |
| **Dataset** | 独立 `datasetID` | 同一独立信号的**当前**标准化内容、来源锚点、解释/作用范围、轻量当前状态标记 | 每次标准化产生用户可查询的旧版本链 |
| **Result** | 独立稳定 `resultID` | 一个明确 Live 科研计算定义、输入绑定、当前输出和计算状态 | 每重算一次就生成新对象、自动写回手工 Parameter |
| **Plot** | 独立稳定 `plotID` | 明确绘图定义、有效输入/当前图像和状态；可以直接绘 Dataset | 强制先造 Result，给 PNG 副本各造一套 ID |
| **Snapshot** | 独立 `snapshotID` | 用户主动固定的输出、有效方法/配置、**全部必要依赖闭包的不可变证据**、保存时明确归属 | 日常自动修订历史、全部原始文件的无差别复制 |
| **Attachment（按需）** | 正式附件 ID | 照片/笔记等独立管理素材与关联 | 立即实现完整笔记/内容管理平台 |

`Batch`、`Device`、`Measurement`、`Run` 不因有一个 UI 字段就强制成为首期独立持久实体；确有跨对象/跨来源消费者时，沿原 G0 不变量先明确范围。独立 Measurement 一旦启用，必须针对一个明确 Sample 或 Device，不能从“同一 Source 含多个 Sample”推成目标不明的 Measurement。

**身份 ≠ 当前内容标记 ≠ 操作标识 ≠ 文件/缓存路径。** 可使用人类友好的 `SMP-/SRC-/DST-/RES-/PLT-/SNP-` 前缀，但 ID 不拼接父 ID；需要来源时通过有类型、可验证的引用表达。字段名与类型可扩展，但其科学量纲、对象及适用范围不能依靠显示文本猜测。物理数据库引擎/表数仍开放。

## 2. 最少必要的关系、唯一权威与不变量

**归属关系（association）**：明确的 Sample/Device 与 Source/Dataset/Result/Plot/Attachment/Snapshot 等资产之间的引用，类型与作用范围明确；一个资产可关联多个 Sample。Snapshot 保存时确定的关系有自己的生命周期，不能随 Live 关联变化而无声变化。允许正式资产暂不归属未知 Sample，但此时不得对它声称已确认的 Sample 归属。

**来源/输入关系（provenance/dependency）**：Dataset 指向 Source 的稳定身份、源段、原始信号锚点及有依据的当前解释；Live Result/Plot 指向**真实使用的全部直接输入**（Dataset、其他 Result、作用范围精确的 Parameter）、有效算法/解释/配置，并能确定传递上游。跨来源联合分析所需时间/采样对齐证据由真正的科研方法决定，不因 Source ID 相同而推断同步。

| 不变量 | 最低规则 |
|---|---|
| **N-I01 身份** | 同一正式对象 ID 不因改名、移动、内容刷新、重启、重试变化；两个独立创建意图即使全部属性相同也不合并。 |
| **N-I02 权威** | 一个领域事实只有一个正式写入责任；UI、Notebook、缓存、Manifest 路径推断不成为第二套来源/归属权威。 |
| **N-I03 无日常历史** | Parameter 与 Live/Dataset 仅正式保有当前内容；内容标记和最小操作回执不构成可查询的逐次编辑历史。显式 Snapshot 与源完整性保留是例外。 |
| **N-I04 科研边界** | 原始 Source 不无声改字节；标准 Dataset 忠实表达所锚定原始信号；科学变换属于 Result/D4；未知条件不自动补全。 |
| **N-I05 当前计算一致** | 对所有影响科学结果的输入、方法、解释、配置、归属变化，相关 Live 及间接下游立即失效；不将过期输出标为 current。 |
| **N-I06 并发/幂等** | 相同提交操作可靠识别；过期写入/过期重算不覆盖较新当前事实；不依赖物理时间戳执行“最后到达者获胜”。 |
| **N-I07 快照可固定** | Snapshot 的内容、传递依赖及归属在提交点固定；不因 Live 改动/Unlink/后续回收漂移或失联。 |
| **N-I08 安全处置** | Unlink 不等于删除资产；未知依赖、损坏/不完整提交不能按空关系处理；本合同不授予生产删除权限。 |
| **N-I09 渐进兼容** | 新合同仅用于经审查批准后的新消费者/范围；旧记录和旧冻结任务保持各自原本保留与验收责任。 |

## 3. Parameter：当前值、无歧义定位和并发提交（F02/F03）

### 3.1 一个字段槽位，一份当前值

- Parameter 是 Sample 直接录入的字段。**槽位身份**是 `(sampleUID, fieldKey, exactScope)`，不是值、录入时间、文件来源或显示名字。`exactScope` 表示当前科学任务确有必要的 Device/子对象、温度、条件、用途等；可采用“Sample 整体”这一明确范围，不是随意空字符串。相同名但不同实际范围保留各自当前值；字段键和条件需要受控规范化及单位语义。
- 一个槽位有 `present / absent` 的区别；零、空文本、未知量/角色不自动等于“未填写”。保存时有类型值、单位及必要科研角色信息。界面可按 Zotero 式字段组织，不需要逐参数 UUID。
- **精确解析**：给定 Sample 身份、字段键、所需科学角色/量、范围、单位约束和目的，只有**唯一满足约束的当前槽位**才能作为计算输入。未找到、多个候选、未知/冲突条件、无依据跨 Device/温度回退，结果为 `unresolved / ambiguous / invalid`，不能凭最近编辑值、相同名字或任意单位直接选一个。若未来允许默认范围继承，必须由首次消费者的科研合同明确且验证其无歧义，不能默许“有一个裸 resistance 就通用”。
- **绑定对象而非标签**：Result 依赖 Parameter 时保存精确槽位身份，以及运算所需的期望物理量、角色、范围和转换规则；读出/提交时核验解析结果及当前值标记，不能只保存 `"thickness"` 文本或把缓存旧值当实时值。删除/改名字段键，或作用范围变化，应使相关依赖失效；若需要移槽位，须明确重新绑定，而非让新同名字段自动继承旧计算。

### 3.2 直接覆盖不等于无并发保护

正式写入一项 Parameter 至少带：**本次操作的可重试身份**、目标准确槽位、用户欲提交的有类型值/单位/范围，以及**用户编辑时看到的预期当前标记**（不存在也有明确初始标记）。数据核心只能执行以下之一：

1. **第一次有效提交**：目标槽位仍匹配预期标记且语义合法，则在同一可靠业务提交中替换当前值、推进该槽位单调校验标记、把受影响 Live 标记失效，并留最小操作结果回执。成功返回新当前状态。
2. **同一请求重试/回执丢失**：操作标识和请求语义完全相同，返回原提交结论；不能再应用一次、生成一个新参数值或使后来用户更正倒退。标识相同而请求体不同则报冲突。
3. **不同操作并发/过期写入**：预期标记不匹配时拒绝自动覆盖，返回冲突及**当前可读值**，由用户重新决定；不以谁最后抵达或设备时钟决定真值。对跨设备延迟消息亦同理。
4. **无法可靠判断是否已提交**：报告 `unknown / reconcile_required`，先按正式槽位及操作结果核对，不把未知当未发生再提交。

**最小持久证据**可以是每槽位单调版本戳/提交代数、已提交的必要幂等回执及恢复标记；其目的是当前一致性、防 ABA、重试与恢复，不是为用户保存每次改动的旧值或建立逐次 Observation History。已确认操作的去重证据在重试仍可能发生的范围内不得提前丢失；若操作回执已依法/按策略清理而无法确定旧请求，拒绝盲目重复提交并要求核对当前值。允许未来手机离线编辑，但上线前必须满足同一冲突合同；手机的具体同步方式不在此决定。

**人工/算法边界**：普通算法/重算绝不写 Parameter；两个手动编辑冲突需要明确用户裁决。Parameter 更正后的计算由 Live 依赖失效完成，无 Adopt 过程；算法结果相同量可并列展示而不自动成为 Sample 手工字段。

## 4. Source 与 Dataset 当前内容、合法更正及保留界限（F01/F05）

### 4.1 Source：原始证据不可偷偷改写

- 一个 `sourceID` 登记一份可核验的原始采集来源：保留已承诺原始字节或等效长期可读的不可变证据定位、完整性摘要、获取状态和必要采集线索。改名、受控移动、相同字节可靠副本不自动改变 Source 身份。
- 如果某个已登记 Source 的实际字节变化，**不能在同一 sourceID 下悄悄替换既有科研证据**。必须报告冲突/重新登记新来源或经过独立批准的明确来源处置；本合同默认按新 Source 身份处理字节不同的采集内容。丢失外部原始文件时不能假称可复现。
- 没有权限、来源完整性或足够解析证据时可以保留未决/不可用状态，但不能让后续 Dataset/Result 宣称可信当前值。

### 4.2 Dataset 当前态：ID 与当次内容标记不同

一个 `datasetID` 识别一个**有明确原始信号锚点的独立标准信号对象**：至少有 `sourceID`、源文件中的确定段/行/索引范围、物理列/通道/必要分量组、明确或待确认的对象范围，及可检查的标准化解释。它可有当前内容、当前解释/角色/单位、可读/未决/损坏状态、**当前内容/语义变化标记**；不自动拥有可查询的完整 `datasetRevision[]` 历史。

- **合法同 ID 更新**：同一个 Source 原始字节及同一个独立信号锚点未变，只是修正此前的**忠实解析错误**（例如列界、数值编码、原始行序恢复）、补正有证据的单位/角色/通道解释、修正有证据的作用范围。更新前须能证明科学对象仍为同一个源段/信号；改变内容或解释时推进当前标记并使所有相关 Live 下游失效，包括仅解释改变而字节相同的情况。
- **必须新建或人工裁定**：换了 Source 字节/实验采集、换成另一独立物理通道/信号/源段、把两次实验并成一个标准信号、改变到无法证明是同一科研对象、或从模糊归属改为可能指向另一对象且不能消歧时，**不能靠保留 datasetID 掩盖身份变化**。建立新 Dataset（必要时新 Source），或留待明确科研裁决及受控关系调整；现有旧关系不自动重指新对象。
- **不得借标准化做科研加工**：平滑、背景扣除、AFM flatten、重采样、拟合、计算 Hc/R_AHE、电阻率、用尺寸计算物理量、选择性删掉异常点，属于有科学意义的处理/Result 或独立分析能力，不得修改 Source 或以“修正标准数据”覆盖原独立信号。严格保留源值、顺序、必要坐标/分量及依据；若提供有依据的等价单位表达，原始数值/单位和变换规则仍可核对，精度/容差有明确验证。未知仪器角色不能按文件名/通道编号猜成科学角色。

### 4.3 旧 Dataset 内容是否保留：规则而非完整历史

| 内容类型 | 新模型最低保留规则 |
|---|---|
| **最新 Dataset 当前内容/解释** | 必须可读、与 Source 证据和当前标记对应，Ready 仅在完整正式提交后成立。 |
| **普通更新前的旧 Dataset 内容** | **默认不保留为可查询的旧修订**。只有在未被任何不可变承诺引用、无未完成事务/外部保留义务时，才允许按有依据的空间清理策略回收；无需建全量版本日志。 |
| **被 Snapshot 引用的旧 Dataset 内容** | 不是可以回收的普通历史：必须在 Snapshot 成功前形成可读取、不可变、完整性可核的冻结内容/可靠持久引用，并在 Snapshot 存续期间保留。引用计数或等效保留责任可以复用同一不可变内容，不强制每次复制整份原始文件。 |
| **旧 v1.4/已冻结任务产生的固定修订引用** | 在旧约束/消费范围未通过单独兼容与迁移验收前继续履行原本版本保留责任；**新 v0.2 不自动授权清理旧数据**。 |
| **Source 原始证据** | 按 Source 的不可变/来源完整性承诺保留；不是“Dataset 旧内容可清理”就可删除原始文件。 |

若先前 Dataset 的旧内容无法保证冻结，相关 Snapshot 请求必须失败/保持未完成；不能保留一个只指向可变 `datasetID` 的“已固定”假快照。对 Live 而言只引用 Dataset 当前标记；对 Snapshot 而言只引用已固定且有保留承诺的内容。正式文件与元数据不能单事务提交时，先准备可验证内容，再公布新当前并失效依赖，失败不得呈现半新半旧的 Ready。

**对旧 G4 的精确替代范围**：仅在未来新模型**被明确切换的 Source/Dataset 消费者**中，以“当前标记 + 快照钉住的不可变输入”替代 v1.4 §3.1/§5.2、D6-B G4-AC1/G4-AC5 对**普通更新也沿用精确修订引用模型**的默认设计；旧合同实际要求的是**已承诺/被引用的修订可以精确读回**，不能误说成所有历史内容必须无限保存。新模型绝不替代 `sourceID`、明确的源段/信号锚点、格式标准化边界、Readiness、错误/重试/兼容保护，亦不追改旧 G4 或其他冻结任务。旧固定修订若仍被消费者引用，其必要内容保留到受控迁移或合法释放后为止。

## 5. Live 的完整依赖绑定、失效和提交检查（F02）

### 5.1 依赖必须覆盖真正影响科研有效性的因素

每个 Live Result/Plot 记录可解析的**计算定义**与有限、有类型的依赖集合；不需要通用图数据库。至少核对以下类别（只收真正被该计算使用的部分）：

| 类别 | 必要绑定与何时会影响 Live |
|---|---|
| **Parameter** | 精确 `(sampleUID, fieldKey, exactScope)`、期望物理量/角色/单位、解析规则、读取到的当前校验标记；值/单位/角色/作用范围变化或失去唯一解析均触发失效。 |
| **Dataset** | 真实 `datasetID`、Source/源段/信号身份、当前内容与解释标记、必要单位/科研条件/归属；更正值、角色、解释、有效性或所属对象的合法关系变化触发失效或阻断。 |
| **其他 Live Result** | 明确 `resultID` 和其计算定义/当前输出标记，传递上游的改变必须使下游继续失效；不能只检查直接输入 Dataset。 |
| **科学方法及有效配置** | 算法/方法身份和科学语义版本、默认值经解析后的有效配置、拟合范围/窗口、背景/几何模型、校准及必要运行条件；方法实现/配置变化影响数值时失效。 |
| **信号解释与关系** | 通道/谐波/角色、Source 解释、Sample/Device 归属、针对计算生效的关联/作用范围、输入有效性；纠正解释或解除必要归属时失效/blocked，不能只比较数据字节。 |
| **Plot 显示定义** | Plot 自身科学输入与显示参数（选择的曲线、坐标、缩放、样式等）；仅纯视觉变化可以只刷新 Plot，不使数值 Result 失效；改变科学数值处理的配置必须沿结果依赖传播。 |

**不要求记录所有 UI 点击或无关全局设置。** 依赖按“真的会改变科学输出/适用性”声明；科学方法是否适用与数值能否算出来分别判断。未知单位、无法确认角色、输入缺失、关联被解除、跨数据集时间不对齐等会使当前计算不成立时，状态为 blocked/error，不能给出伪有效数值或靠旧缓存继续声称 current。

### 5.2 失效/重算/提交是一个完整行为

1. **解析入口**：读取各依赖的正式对象及当前标记，Parameter 精确解析，检查必要归属、角色/单位、有效科学配置和无循环。形成带签名的实际输入集合；若结果依赖图成环，拒绝该计算或定义，不允许无限递归。
2. **变更提交**：Parameter、Dataset、方法/解释/有效配置、作用范围或关联的正式更改，必须与**直接和传递下游的失效状态**具备确定、可恢复的一致性；不能先公布“新输入”却让已知旧计算仍可被读为 current。事务边界/待处理通知需有重启/漏事件恢复依据，不强制现在预选事件总线。
3. **计算期间**：允许后台异步；状态至少区分 `current / needs_update / error / blocked`（具体名称和技术字段可变）。旧输出可留作标注“过期”的参考，但不能作为基于现输入的 current、正式导出或新的可信 Snapshot 输入。
4. **提交再验证**：写入当前输出前，对**全体直接与传递有效依赖**及方法/解释/作用范围/归属重读或核对一致性标记；输出仅在与本次定义和当前输入完全对应时覆盖**同一 Live 对象**并标为 current。期间任何相关输入变更（含 A→B→A 的回环值、重绑或算法版本变化）都使旧计算不能提交为 current；应放弃/排队重算或保留标过期，绝不晚到覆盖。
5. **失败/重试**：算法错误、不合法科学语义、不可读依赖、输入变化及提交失败分别可识别；重启后重新核对并补发所需失效/工作，不把丢失的通知视为“已经重算”。成功报告只在输出、对应输入标记和依赖状态完整提交之后。

**轻量标记不是历史**：Parameter 槽位/Dataset 以及 Live 定义、方法或作用范围所需的单调状态标记，可用于事务比较和读侧校验；不要求保存每个旧版本的值/输出。若数据库与文件分开提交，不得仅凭数据库 current 标记认定尚未落盘的内容存在。读侧至少能核实当前签名，或看到 needs_update/blocked，而不是相信过时缓存。

## 6. Result/Plot 身份与首次 Live 消费者约束（F06）

把**对象身份**与**执行活动**、**操作请求**、**输出等价性**拆开；不将每次运行都造为持久科研实体。

| 场景 | 正式结果 |
|---|---|
| **用户或已有正式定义请求重算一个 Live Result/Plot** | 保持同一个 `resultID/plotID`；成功覆盖当前输出并推进输出标记；输入不符的旧运行不得提交。 |
| **同一“创建或保存”请求的网络/进程重试** | 以同一操作身份复用原提交结论；不产生第二个 Result/Plot；同标识不同请求内容返回冲突。 |
| **用户明确创建一次新的独立分析** | 即使 Sample、输入、方法及数值都与已有 Result 相同，也分配新的 `resultID`（或 `plotID`）；不能根据等价哈希自动合并两个独立意图。 |
| **用户显式修改现有 Live 分析定义** | 如果仍明确是在编辑同一个所选 Live 对象，则 ID 不变、定义标记改变、旧输出失效，重新计算；若语义已变成另一独立分析，则必须显式新建，不能靠方法/名称猜测。 |
| **自动化的重复触发** | 若触发明确绑定既有 Live 定义，则刷新该对象并去重同一触发操作；若规则明确要求创建独立分析，则按独立意图创建。未绑定/歧义不得凭内容哈希任意复用或制造新对象。 |

**留给首个真实 Live 消费者 Task Spec 的技术细化（不再是产品空白）**：选择代表性真实 Result 或 Plot，明确它的“更新已有 / 新建独立 / 同请求重试”入口、操作身份的生成/持久化方式、当前定义等价判断所需字段、并发运行与重启幂等窗口、输出格式、最小科学参考和测试范围。首个消费者必须同时验证三种动作的对照：独立同输入双建；同请求重试单结果；同对象输入改动后旧任务失效、同 ID 重算。不能仅单测一个 helper 或让 UI 私建 ID。

未选定的数据库 engine、重试令牌具体格式、任务调度机制和独立运行日志布局均是实现选择；**身份边界和无歧义操作语义已经由本节确定，不允许 Worker 自行改为“每次重算生成新结果”**。结果是否持久保存、状态是否 current 和科学方法是否适用是不同维度。

## 7. Snapshot：固定传递依赖、内容留存与独立归属（F04）

### 7.1 快照是明确保存的科研成果，不是一次普通计算修订

用户从一个明确、已解析且状态为 **current** 的 Live Result/Plot（或首个消费者定义的同类正式输出）点击保存，形成独立 `snapshotID`。每个**独立**保存意图可产生独立 Snapshot；同一次保存请求的回执丢失/重复提交不得造副本。Snapshot 不依赖之后是否仍存在/选用原 Live 定义，且其归属在保存时明确确认。

### 7.2 必须固定的是完整、可复现的传递输入闭包

Snapshot 保存时至少冻结以下**实际相关**内容；不要求复制无关全库数据：

- 快照本身的数值、曲线/矩阵或图像成果的实际内容，以及需要的单位、有效科研状态/条件和科学/显示配置；仅留 Live ID 或可变 PNG 路径不够。
- 所有直接输入：当时 Dataset 的**不可变标准数值内容或具有保留承诺的内容固定引用**、参数槽位及其当时已解析的值/单位/作用范围、方法/语义版本/配置、必要信号与对象归属。
- **间接输入闭包**：若 `Result C` 依赖 `Result B`，B 又依赖 Dataset 与 Sample Parameter，需沿有类型依赖引用一直展开到必要的 Dataset、Source 证据和 Parameter 值，固定各层的计算定义/科学方法/有效配置与成果内容。不能只保存 B 的当前 `resultID` 作为 C 的唯一输入依据。
- 如果 Plot 使用多个 Dataset、多个 Result 或多个 Sample，则固定实际所有输入和各自确定的归属/作用范围、采样/对齐证据（若方法需要）、图像及对应绘图定义。没有科学意义的纯 UI 状态不要求纳入。
- 包内每个不可变数据引用须包含完整性可核的内容身份/摘要、可读位置及保留责任。原始 Source 仍按原证据政策管理；需要原始字节才能满足宣称的复现范围时，必须可靠保留对应 Source，而不是只存 Source 名称。

**冻结不代表建立 Dataset 日常版本历史**：只有 Snapshot 明确引用的内容需要固定，可通过内容寻址/受治理的不可变副本及共享复用减少实际存储，保留机制由之后存储任务选型。不对普通未快照计算版本无限保留。

### 7.3 快照自身的 Sample 归属不是 Live 的动态镜像

- 保存时确定 `snapshotID` 的 Sample/Device 关联集合和每个关联的必要作用范围；这些是**Snapshot 自身正式关系**。一个快照可关联多个 Sample，但归属必须由明确的上下文/已确认关系构成，不因某 Live Plot 后来新增或解除 Sample 关联而自动变更。
- 用户以后对 Live Result/Plot 的编辑、重算、取消 Sample 关联、重新命名、删除该 Live 定义，都不修改既有 Snapshot 的数据、归属或必要证据。对 Snapshot 本身的明确 Unlink/删除是**另一个独立命令**；没有授权不得因 Source/Live 的清理顺便删除 Snapshot 固定内容。
- 释放已固定内容前必须清点仍存在的 Snapshot 引用及其他受保留承诺的消费者。共享不可变块只在全部引用和义务合法释放后可回收；不要求无限保留无人引用的快照或冗余文件，但不授予本合同中的生产 Purge 操作。

### 7.4 Save Snapshot 的可信提交边界

保存前：读取 Live 最新 current 状态、它的全部直接/间接输入及有效配置；若中间 Result 已过期、存在歧义、输入不可读、保留无法保证，**拒绝报成功**。保存时：准备所有必要不可变内容与归属，核验完整性并持久化所需保留承诺；在提交确认点再次核对整套依赖及输出属于**同一个一致输入状态**。如果并发修改、文件写失败或来源消失，取消/标记未完成并恢复，不留下一个被宣告有效的残缺快照。成功后：固定输出/输入/归属/保留责任一起可独立读回；重复保存请求返回同一 `snapshotID`，不同保存意图可产生另一个 Snapshot。

**可复现承诺分级必须诚实**：只有计算数值和输入闭包固定且可读时才可宣称该输出可按已记录方法复现；若依赖外部软件/校准/原始数据而未保留必要内容，必须阻止过强承诺或在首次 Snapshot 消费者中明确并标注能力边界，不能只凭一张 PNG 宣称科学可复现。

## 8. 提交、错误与删除：无日常历史也必须安全

- **业务提交边界**：对象身份、当前字段/数据、必要正式关系、当前标记、Live 下游失效和操作回执有一致的成功/失败定义；文件系统与数据库若非单一事务资源，必须有恢复或可核查的中间状态。发布 Dataset Ready、Live current、Snapshot saved 均须基于实际可读的已提交内容。
- **失败语义**：区分未提交、已提交、部分提交/待恢复、结果未知、依赖无效、科学方法不适用。数据损坏不等于“不存在”；未决关联和失效状态不静默转成空集合或 0 值。
- **最小幂等性证据**：创建请求/Parameter 编辑/Live 更新/快照保存可各有必要操作键或等效恢复证据，防重复提交与旧响应。不会为每个 UI 点击、每次计算重试生成一条用户可浏览的版本历史；已确认用户意图不能因晚到后台任务被反向覆盖。
- **关联与删除**：Unlink 只解除一条正式对象引用，不删资产本体；删除共享资产及其下游/快照保留必须完整依赖清点和明确授权；未裁定的生产删除功能继续安全拒绝，不能用“自动清理旧 Dataset”绕过保留/来源义务。
- **存储选型**：SQLite + 独立文件仓库为可评估候选，**不是已经批准必须使用的实现**；数据库引擎、表结构、缓存、消息机制、清理策略及同步拓扑不在本合同冻结。Notebook、Workbench/Automation 不成为第二套写入权威。

## 12. 决定状态、开放工程选型与交接

**本轮已经由用户确认的产品决定**：普通 Parameter 和 Live/Dataset **不提供日常历史**；人工更正直接覆盖；Live 依赖当前值自动刷新；用户主动 Snapshot 冻结必要科研依据；Source 原貌与关联安全不变；ID 类型化但不嵌父 ID。

**仍需首次消费者 Task Spec 选择并验证（技术选择，不构成当前缺失的重大产品决定）**：真实 Parameter fieldKey/单位类型及科研作用范围实例；存储引擎/物理表与大型文件持久化形式；技术变化标记/事务/操作回执结构；Snapshot 固定内容的受治理物化/共享保留方案；最小事件/重算调度与科学方法版本绑定；首条 Live 功能的输入/数值容差和等价请求字段。上述选择不能变更 §3–7 的失败/身份/来源语义，也不能未经审查启用破坏性清理。

**延期但需在真正触及时另行授权/裁定**：生产库/旧 XLSX 迁移、Batch 正式改键、手机跨设备同步拓扑、全局物理删除/恢复窗口、外部文件永久存储承诺、首次 Device/Measurement 独立实体。这些不阻塞本次理想新数据库的合同审查；如某实施任务无法避免触及，必须在该任务开始前显式裁定。

**本次需要用户新增产品选择：无。** 设计收敛按已确认原则，不将“从图推断 Sample 身份”、全局永久保留 Dataset 历史、自动删除快照、后台改写手工值偷偷设为默认行为。

**交接**：交付 v0.2、审查修订对照、原 v0.1/旧 v1.4/D6-A/B 和原始 SHA-256 证据，一次交给独立 Reviewer。Reviewer 需从同一 `policy_sha` 读 Reviewer Skill，核对本文件实际字节及 `design_ref`，集中检查 F01–F06 与新旧有效范围，给 `DESIGN PASS / DESIGN REWORK / DESIGN BLOCKED`。设计获批之前只允许只读规划和隔离模型讨论，**不得发布可执行的新数据库实施合同**；任何独立审查 PASS 都不自动授权改代码、commit、push、PR、merge、删除或权限变更。
