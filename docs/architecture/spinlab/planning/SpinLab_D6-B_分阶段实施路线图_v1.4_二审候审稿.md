### 1.2 为什么先 AFM，再 PPMS/AHE

这是 **D6 的执行顺序建议，不是用户已经逐项指定的源码方案**。

AFM 适合较早证明“新数据入库—显式处理—自动出图”的完整路径；PPMS/AHE 适合证明通道语义、结构化指标和当前采用。顺序不是说 AFM 重要性高于电输运，也不是因为现有纯函数就认定其端到端已独立。

若当次仓库事实表明某条路径已完成或前置明显不同，可以调整顺序，必须保留两类验证目标与真实依赖。不要把重新排序变成取消 AHE 语义/治理验证，或反过来取消矩阵与自动执行验证。

### 1.4 Gate 的状态与证明强度

| 状态 | 意义 |
|---|---|
| **设计 Gate（按风险分级）** | REQUIRED 时记录 PENDING / DESIGN PASS / DESIGN REWORK / DESIGN BLOCKED / 有效 USER WAIVED；N/A 只适用于不需独立设计审查的低风险边界。**PENDING 不代表可编译实施 Prompt**，设计通过亦不等于代码已就绪 |
| **implemented-ready（限定范围）** | 基础代码、实际消费者、必要失败/兼容场景都有证据；注明提交与覆盖范围 |

| **deferred / out-of-scope** | 本轮不承诺的能力有明确边界；证明不影响本次 AC，不能用来掩盖必需依赖 |

## 2. 所有任务共同遵守的工作规则

### 2.1 从任务卡到 Prompt

当次 GPT 应补齐：实际仓库/分支/提交与相关修改、已实现前置、当前可复用入口、确切支持范围、最小字段/方法、必要默认值、兼容风险、真实数据与参考证据、可以运行的检查及授权边界。

只核查本任务相关调用链与持久化消费者。旧审计仅提供线索；无法访问的本地状态或真实数据明确标为待 Agent 补证。未决科学或产品选择阻塞相应承诺，不让 Agent 以“实现细节”擅自决定。

任务卡的 AC 是交付要求；当次合同可进一步明确样本范围和验证方式，不得悄悄删除它们。对原本未限定的范围作限定时应先说明产品影响，并在实施前确认。

### 2.2 任务与 PR

一项任务交付一个可理解的科研功能或可依赖的基础性质，可以包含多个 PR。基础任务不需要新增 UI；必须有实际消费者/持久化/失败验证，不能用空接口或一次写 JSON 证明完整架构。功能任务以已通过的基础为输入，不负责暗中重定基础。

近期先细化 G0/G1/G2 与 #194 的收口，再细化 T01/G3/G4 的实际 PR 分界；远期任务不提前写文件级计划。不要把所有数据可靠性和负面路径放到一个最后的“补测试 PR”。

一个任务通过后再决定是否合并和推进。未来任务尚未实施的功能不应成为当前 PR 的虚假失败项；已建立的保护也不能被下一项移除。

### 2.3 验收证据

每项 AC 应有能发现其实际失败的证据。下文 E 编号是证据类别，而不是预设测试命令。

- 纯数值与结构问题：已知答案、边界样例、合理容差或可核验不变量。
- 持久化与迁移：写入后重新读取、重启或迁移后对账，不只查看内存状态。
- 前台能力：真实 App 操作或可用的端到端证据，不只 ViewModel 测试。
- 权限、去重和清理：重复提交、失败重试、删除后重启等实际会暴露问题的场景。
- 科学方法：计算正确性与方法对实验的适用性分别说明；缺少参考不能声称验证完成。

现场验收由用户在 Mac/手机上操作，GPT 提供与本任务对应的简短步骤并核对回传信息。必须确认 App 构建对应待审 PR 提交；截图不能代替数值文件回读。

### 2.4 状态与完成

状态建议使用：**规划 → 准备 → 实施 → 待代码审查 → 待现场验收 → 待合并 → 已完成**。阻塞单独标注原因，不靠改名任务消除失败。

“已完成”需要约定的基础性质或功能、必需证据、代码审查及任务相关的实际验收全部满足，且用户授权合并后最终分支状态已记录。纯基础任务以集成/故障/持久化证据验收，不强行增加 UI 截图；有 UI 的任务必须现场验收对应构建。未获得必需运行证据写“未验证”，而不是给整项 PASS。

## G1 — 既有写入、删除、Registry 改键的数据安全

**依赖：** G0 对应范围确切设计审查 DESIGN PASS（或对相同 `design_ref` 有效风险知情 USER WAIVED，且无实质阻塞）。**不依赖：** 全库 UID 回填、完整删除 UI、云系统。

**目标：** 新增正式记录之前，已有入口不会因误判旧 key、目录或损坏状态破坏本轮资产与关系。

**范围：** 在隔离库构造旧 Sample 抽屉、实际 Workbench 产物命名空间、测量/图/指标引用；核对 Registry 名称派生 key 改变/缺行、样品与批次删除、索引损坏/重建及部分失败。对证实风险作最小防护。无法确认引用范围或删除政策时，明确拒绝受影响破坏操作；不默默删除、不吞掉失败，也不永久禁掉无关旧功能。

**开工选择：** 受影响操作及可复现输入；允许先阻断的范围；现有故障处理/回滚能支持什么。不替用户决定整个硬删除政策。

**验收：**
- **G1-AC1：** 损坏/不完整/未知不是空库；只读清点和预览不写数据、分配 UID 或自动修库。
- **G1-AC2：** Registry 改键/缺行不未经明确身份判断和授权就删旧建新；危险删除覆盖抽屉之外的关联；共享或未识别引用不会被静默切断。
- **G1-AC3：** 删除后同名创建、恢复、重建等反例不会让旧产物错归新对象；未具备正确行为时安全拒绝，而不是假成功。
- **G1-AC4：** 部分失败如实报告；新防护不撤销已确认人工事实；未受影响的受支持旧读取/正常写入保持有效。

**证据：** 真实调用链及最小隔离复现；跨存储命名空间回读；改键/删除/损坏/失败注入；相关旧行为回归。PR 说明不能代替运行证据。

**放行：** 只为已覆盖范围消除风险；这不是完整删除功能验收，也不是 G2 统一身份完成。G2 尚未建立的关系/恢复能力，在 G1 可以用可验证的安全拒绝证明不会误删/误绑，不要求先实现 G2 才能完成 G1。

## G2 — Sample 身份、别名解析与真实下游关联

**依赖：** G0 + 对应 G1 保护；相关生产回填/Batch 方案需按 O-ID1/2 处理。**目标：** UID 真正成为关联权威，而不是一个仅被保存的字段。

**范围：** 复用 #194 可用的创建/存储机制；建立或收敛一个受治理身份解析入口和正式创建/更新边界；保持旧定位键兼容。稳定 UID、别名及范围、独立创建意图与可靠提交幂等性、外部来源稳定记录映射/旧 XLSX 缺身份时受限人工对账、修订/失败保护共同成立。新建、来源映射、旧读侧不得各生成一套身份。

**不做：** 全量迁移、重命名所有目录、改变分析算法、完整 Batch/Device/Measurement 管理、手机同步、T01 UI 美化。普通更新不能改一个已存在的非空 UID。旧 `legacy:<batch>:<key>` 只作过渡引用，不宣称永久身份。

**必须连接的消费者：** 在选定新/旧 Sample 样例上，至少包含 **实际测量关联读侧** 与 **实际 Plot 查询/打开读侧** 两类消费链。消费者可以由兼容适配器间接解析 UID，不要求全部旧文件改字段；测试只能调用新 resolver、没有接入真实调用者，不算通过。

**验收：**
- **G2-AC1：** 两个不同操作 ID 即使 Batch/衬底/名称完全相同且并发提交，也会产生两个不同 UID 及不碰撞的技术 locator，并分别可写后读回；同一操作的重复提交/并发重试只能创建一次；显示改名不改 UID；非法替换 UID 被拒绝。
- **G2-AC2：** 原生及存量映射对象通过同一解析结果；同名旧别名跨命名空间/历史代际及同现行 alias 冲突必须返回明确歧义/历史状态，不能误绑；未映射/冲突/已删除/损坏分别表达；未知不自动新建或取第一个匹配项。
- **G2-AC3：** 测量与 Plot 查询/打开的真实消费者须通过 UID/统一解析后使用受控兼容 locator，而非测试者直接传入预期 sampleKey；旧记录适配后仍可读；同属性双独立对象、跨身份域别名碰撞、改显示名、受控外部 rekey 均不丢关联、不误绑。
- **G2-AC4：** 一个新同名对象不继承已删除对象的旧图/测量；恢复同对象保留原 UID。无法证明安全的歧义操作被阻断。
- **G2-AC5：** 实体、持久映射及必要引用的提交/重试/回执失败不产生双 UID；重启/索引恢复不重新分配；原始数据不被迁移测试破坏。
- **G2-AC6：** 在声明覆盖范围内，相关旧写/删入口同样受保护；未切换消费者明确列出。不能由两条 happy path 宣称全库统一。
- **G2-AC7：** 能透传稳定外部记录 ID/token 的来源跨再导入/改行号/改显示名仍解析到已确认 Sample；无可信 ID/token 的旧行仅在本次已核对范围内人工对账，不承诺任意重新导出后自动识别，不凭属性合并、新建或覆盖；经授权写回 token 后才承诺跨次自动映射。

**证据：** 两个独立操作 ID 同属性并发创建与相同操作并发重试的对照；真实测量/Plot 消费者各自通过 UID 与兼容 locator 读回；相同旧别名跨命名空间/代际/活跃对象的歧义反例；有 token 再导出与无 token 改行号的保守对账；删除同名及故障重试；与 G1 组合回归。常规用户不填写 UID；UI 只在 T01 收口时现场验收。

**交付：** 哪些对象/引用/命名空间已经 implemented-ready、哪些只是兼容读取、哪些仍未映射及禁止操作。T01 用这一基础完成用户创建体验；T02/T03 直接复用，不重新定义身份。

## G3 — 手工记录、修订、采用与附件关系基础（内部独立阶段）

**证据：** G3a 使用正式写入→独立查询→重启、两条件/人工与算法来源、部分失败/旧写入口回归；G3b 使用一份素材关联多个 Sample、取消一处关联、重开及删除反例。可用受控 Result 夹具先证明采用政策，不要求提前实现完整 AHE。

**放行：** G3a 达标即可让 T02 首批电阻/尺寸 UI 进入集成验证；G3b 达标后可交付 T02 的附件/笔记能力；**T02 整体完成仍需 G3a、G3b 及对应 UI/现场验收**。G5/T07 用真实算法输出复验 G3a 采用政策。

## T02 — 手工科研记录与 Parameter 直接修改

**v1.3 开工门槛：** 结构化记录先需 G3a implemented-ready；附件/笔记功能需 G3b implemented-ready。T02 整体验收仍包括两部分，而不只是定义了类型。

**目标：** 用户在 Sample 中录入有意义的电阻或尺寸量，修改确认后当前值立即有效，并可供查询及后续分析使用。

## 8. 阶段验收如何避免“每个 PR 都过了，整体仍不好用”

| 阶段 | 最小整体验收旅程 | 不能拿什么替代 |
|---|---|---|
| M1 | 原生创建 Sample → 记录电阻/尺寸 → 修改确认 → 重启读取 → 相关旧信息仍正确 | 新增结构体、保存一份 JSON 或只有截图 |
| M2 | 导入新 AFM → 标准资产落盘 → 人工处理 → 同配置自动处理/存图 → 关闭开关 → 重复/删除/重开检查 | 纯计算函数测试或在 Workbench 手动读 IBW |
| M3 | DAT 未知通道确认 → 保存规则/新文件复用 → 多对象归属 → AHE 数值与人工采用 → 自动出图不覆盖 | 已知列位置硬编码、PNG 标题里的指标或只测一个 Sample |
| M4 | 固定新来源范围通过标准路径 → 指定历史批次迁移 → 旧引用/人工决定核对 → 相应旧路径有依据退出 | 全目录扫描成功或笼统称“全部支持” |
| M5 | 手机创建 → 桌面读取与修订 → 手机看到当前值 → 旧修订晚到/失败 → 状态与恢复正确 | 静态 Web 列表刷新或 Note API 写入成功 |
| M6 | 新建非内置流程；AI 提案确认前后行为明确；过期提案拒绝覆盖 | 一组预设开关、后台代码修改或一次模型演示 |

阶段整体验收是此前任务性质的组合验证，不是额外的“再写一个大阶段”。必需场景在相应合同开始前明确，避免最后突然追加未商定功能。
