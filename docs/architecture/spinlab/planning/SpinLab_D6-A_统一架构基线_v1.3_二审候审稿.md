## 阅读入口

新实施对话至少收到本文件、D6-B 中选定的完整任务卡，以及相关前置任务的完成反馈。先按当前仓库核查事实，再生成本次 Coding Agent Prompt。无需重新讨论产品愿景，也不能仅凭旧审计认定当前实现。

本文包含三种不同性质的内容：

- **已确认方向：** 来自用户明确要求、D1–D5 中标明已确认的决定及本主架构对话的最新确认。
- **D6 收敛约束：** 为把上述决定组成同一个系统而明确的跨模块边界。它们是后续任务的设计约束，不表示用户逐项选择过相应内部实现。
- **开放选择：** 仍需在相关任务开始前解决的产品默认值、科学方法或技术方案。不得将推荐值写成已确认决定。

当前约束以本基线为统一入口；已确认的后续用户变更应先更新基线或明确记录修订，再进入受影响任务。D1–D5 保留细化依据，V1/V2 保留历史理由，不再分别维护互相竞争的当前总架构。现行仓库协作、安全、审查和技术债规范仍须遵守；与新架构冲突的旧规范需要显式修订，不能静默绕过。

## 1. 产品目标与本轮范围

SpinLab 是以 **Sample 为科研知识中心**的个人科研系统。手工记录、仪器测量、Workbench 结果和自动处理成果共用科研含义、身份、来源与裁决规则。Notebook 是这些记录的统一视图，不是另一份可独立修改的科研真相。[S1–S4]

### 1.1 近期要交付的体验

用户可以在桌面建立 Sample、记录少量有含义的定量信息；新接入的受支持数据经过统一器，成为 Library 中可独立读取的标准数据；人工 Workbench 与自动化复用处理能力。首条自动化完成：

**标准数据正式就绪 → 按已生效预设处理和出图 → 图像及必要成果归入对应 Sample。**

先把这条路径做可靠，再扩展格式、分析、手机记录、历史迁移和前台自由编排。近期不以综合报告、AI 科研推理、通用节点画布或完整训练系统为前置条件。[S6；S7]

### 1.2 已确认的渐进策略

**自动化渐进：** 首阶段允许以 Workflow 预设及自动开关提供操作入口；自动化定义和执行责任仍独立。未来允许多预设、多规则、非内置流程与 Spin Cat 提案，不把“一种 Workflow 只能有一个固定流程”写成不可突破的架构限制。

**数据渐进：** 先建立并验证新标准；受支持范围内的新数据走新路径；旧数据、旧 Workbench 按明确范围逐步迁移。不要求开始前重写全部 Library、全部分析或全部历史文件。

“新数据合格”只在已公布、已验收的来源及分析范围内成立。未覆盖的格式必须明确显示未支持、待解释或旧路径状态，不能自动算作新标准已完成。[S7；D6 收敛]

## 2. 全局架构约束

下列编号供路线图与任务合同引用，不对应强制代码模块。

| 编号 | 约束 | 具体含义 |
|---|---|---|
| K01 | 共同科研语义 | 同一对象、物理量、单位、角色、条件与来源跨入口保持含义一致；不按页面重新定义事实。 |
| K02 | 人工裁决有效 | 用户明确修改并提交后，同一范围的当前值立即更新；机器不能未经授权推翻。普通编辑不强制二次采用。 |
| K03 | 来源和身份可追溯 | Sample、Source、Standard Dataset、Result 的身份承担不同职责；名称、路径和相同数值不能替代科研身份。 |
| K04 | 接入不偷做科学处理 | D2 忠实读取、整理结构、解释有依据的语义；不去噪、flatten、扣背景、剔点、拟合或推导指标。 |
| K05 | 新生产路径使用标准数据 | 已迁移 Workflow 的测量输入来自 Library 管理的 Standard Dataset；不另开原始仪器文件解析后门。 |
| K06 | 人工与自动共用能力 | 共享明确输入、方法、有效配置和科研输出；自动化不调用页面或依赖上次控件状态。 |
| K07 | 科研结果与显示分开 | Result 可包含有类型的标量、曲线、矩阵；图片不是数值结果的替代。视觉设置不暗改计算值。 |
| K08 | 正式保存与当前采用分开 | 计算不自行改变正式记录；D3 管理保存、归属和采用。一次明确 Save 可以同时表达允许的保存与采用。 |
| K09 | 自动化独立且前台可控 | 前台预设、开关和将来的编辑器操作同一正式定义；后台执行服从生效版本，无隐形规则副本。 |
| K10 | 可追溯但不无限积累 | 重复执行不无限追加；独立实验不因同值被删除；明确清理不被刷新或重复事件无声撤销。 |
| K11 | 候选与正式隔离 | 候选计算与 Spin Cat 提案不自行写入正式科研记录、发布配置或改变采用关系；权限可撤销。 |
| K12 | 渐进、可验证、不偷换完成标准 | 每项功能按实际覆盖范围验收；旧路径可过渡，但不能增加另一套科研语义或重复调度。 |

这些约束来自已确认方向及 D6 的接口收敛。具体状态字段、存储引擎、类名、调度框架和技术实现均未因此冻结。[S2–S7]

## 3. D6 对跨专题问题的明确处理

### 3.1 单位规范化不等于数据加工

D2 的单位规范转换与 D5 的“不修改测量内容”统一为以下边界：

**必须保留来源表达及换算依据；允许有依据的等价单位表达；禁止借单位规范化改变科研事实。**

原始数值、原单位文字及来源位置必须可定位、可核验。标准资产可以提供统一单位的表达，也可以提供共享的读取转换视图；物理存储是否并存两份数值，由相关任务选择。不能因为原始文件在别处“可能存在”，就宣称被覆盖的来源表达仍然可靠可追溯。

单位转换须先确定物理量身份和转换前提。相似名称、相同量纲或仪器习惯不足以证明两个物理量等同。无法确定时保留未知，不让各 Workbench 自行猜单位。浮点换算的容差由验证明确，不使用“绝对无损”掩盖精度问题。

V/I、由几何推导电阻率、背景扣除、flatten、平滑和重采样是派生计算，归 D4。规范单位在接入时物化还是在共享读取边界转换，是开放实现选择；无论选择何者，只有一套有效的物理解释与换算依据。[S3 §5–7；S6 §2；S7]

### 3.2 独立标准数据文件是方向，不是一列一个文件

D3 已确认按 Sample、测试段和独立科研信号物化真实标准数据文件。D6 保留该方向，同时限定：**可独立使用才拆，必要分量与共同采样关系不得拆坏。**

例如同一通道的 X/Y、幅值/相位、有效性信息和必要坐标可以保留在同一个资产中。共同 H/T 列允许重复，以降低读取耦合；重复列仍是同一来源的表达，不能各自成为可以无追踪修改的测量事实。

拆分必须保留源段/行位置、原始顺序、分支、坐标及可用的配对关系。不能仅凭文件名中的温度或谐波标签就虚构九个已确认信号。单 Source 可以包含多次或多段采集；多份 Source 也可能属于同一测量。Source ID 只证明文件来源关系，不单独证明逐点同步。

当前不强制新增 Acquisition/Session 持久实体；但必须能表达必要的共同采集、分段和配对关系。D2 确认内容及映射，D3 管理身份和关系，D4 检查联合分析所需对齐证据。[S3 §5、8、11；S4 §3、5、9]

### 3.3 “只读标准数据”约束测量入口，不禁止处理步骤串联

已迁移 Workbench 和自动化不能自行解析原始 DAT/LVM/IBW。来源查看、问题诊断和重解释仍可以回到 Inbox/D2。

一次 D4 操作中，标准数据经过背景处理再提取参数、经过 flatten 再绘图，是正常的处理链；其中间派生值不需要为了继续计算而伪装成新的原始 Standard Dataset。

以后跨次复用已正式保存的 Result，应使用 D3 管理的有类型结果及 D4 明确声明的输入合同，不绕过原始数据边界。是否在首期开放这一入口，不是第一条自动出图的前置要求。[S5 §2–5；S6 §0、2；D6 衔接解释]

### 3.4 预设自动出图不是完整自由编排

首阶段交付默认处理/绘图预设、自动启停、适用数据、试运行和必要状态。可以放在对应 Workbench，也可以有轻量总览。

后台必须拥有与页面生命周期无关的正式预设与自动化定义。当前界面只支持简单流程，不等于底层按 Workflow 写死唯一规则或在导入模块中硬编码后续分析。

能在前台创建非内置流程是后续独立里程碑；不把它提前作为首条闭环门槛，也不能在只有开关时宣布这项长期要求已完成。[S6 §3；S7]

### 3.5 手机同步是独立工作，不附属于分析执行器

手机 Web 创建 Batch/Sample、记录 Recipe；桌面接入测量和分析，是已确认产品方向。它依赖共同身份和正式修订制度，不依赖先完成全部自动化，也不要求第一条自动出图等待云系统上线。

D6-B 单列手机记录与同步任务。同步的正式写入归数据核心，自动化只消费已提交且具备条件的数据。不会让一个“文件来了就执行”的后台任务顺便决定跨设备冲突、Sample 合并或权威迁移。[S4 §0、5、8；S7]

## 4. 共同对象及关系

此处描述语义，不要求创建同名表或一套大而全的 ontology。[S2 §4–7]

| 对象 | 在系统中的意义 | 必须避免的混淆 |
|---|---|---|
| Batch | 一次生长/处理批次；Recipe 可供其多个 Sample 引用 | 不等于一次文件导入集合或后台运行批次 |
| Sample | 由用户明确创建，或由已确认外部来源记录导入/映射形成的稳定科研记录；一次有效新建意图产生独立身份，相同 Batch/衬底/名称等属性可以并存 | 不等于材料、目录名、Registry 行或当前显示编号；不由 App 判断物理同一性 |
| Device | Sample 上的独立加工器件及相应几何语境 | 固定器件角度不等于磁场扫描角度或旋转平面 |
| Measurement | 针对对象的真实测量语境，可关联多个信号、段和来源 | 不强制一个文件、一通道或一张图等于一次测量 |
| Source | 已登记的原始来源及其证据 | Source ID、内容指纹、名称、路径分别有不同职责 |
| Standard Dataset | 独立可访问、有身份与版本的标准科研数据资产 | 不只是某 Workbench 的内存缓存，也不等于 PNG |
| 手工观测/属性声明 | 用户对对象作出的结构化记录或有来源陈述 | 不要求制造仪器文件或虚构 Measurement |
| Parameter | 明确对象、量与适用语境下当前使用的值 | 不等于删除底层观测，也不按同名字段覆盖所有条件 |
| Analysis Activity / Run | 明确输入、解释、方法和有效配置的一次执行 | 重试事件不必产生新的独立科研成果 |
| Result | 可引用的标量、曲线、矩阵或其他科研成果 | 计算成功不等于已正式保存、已采用或科学普适成立 |
| Plot Artifact | 数据/Result 与绘图配置产生的显示成果 | 字体或颜色变化不创造新物理观测 |
| Notebook / Library 视图 | 自动组织正式对象、数据、图与笔记的入口 | 不复制第二份独立可编辑的当前事实 |

### 4.1 同一范围与独立证据

同一 Device 在不同温度的电阻、同条件下两次真实测量、两种方法的结果，都可能独立成立。数值相等不证明重复；换显示单位不创造新观测。修改一条错误记录与新增一次测量是两种动作。

Parameter 的适用范围至少应能区分其实际需要的对象、物理量/角色、条件和用途。不是要求所有记录都填满固定字段，而是禁止在范围不明时静默扩大它。

App 不根据现实中的切割、生长步骤或用户未明确记录的事实决定应有几个 Sample，也不建立片段/切割实体。用户明确新建几个就形成几个独立科研记录；数据是否属于某个 Sample 由明确关联或已获授权且有依据的规则决定。局部尺寸或性质的适用范围仍应如实标明，不能自动扩张到整片 Sample。此处采用 2026-11-09 新确认原则，替代先前 D1/D6-A 的相关同一性推断。

**新建与已有记录同步是两个操作。** 用户明确发起两次新建，即使名称、Batch、衬底、Recipe 完全相同，也是两个 Sample；同一创建请求因重试/回执丢失重复执行不得新建第二个。已有 Obsidian/XLSX 记录的再次导入和未来 Mobile/Desktop 同步，应优先复用可核验的外部记录稳定身份与已保存映射，不凭 XLSX 行号、文件名或样品属性自动合并。旧记录缺少可信来源身份时明确待对账，而非猜测。

**素材本身与归属关系分开。** 一个正式 Source、Dataset、Plot 或附件可由多个 Sample 的组织视图引用，所引用的源段/通道/结果范围要明确。移除一处 Sample 关联，不等于删除共享素材，也不要求移动或复制实际文件。Notebook 仅聚合正式记录与关系，不能成为另一份事实源。

### 4.2 来源通道不等于科研角色

Bridge 编号、LVM `1st/2nd`、列位置、锁相 X/Y、谐波阶数、Rxx/Rxy、Sample/Device 归属要分别有依据。

用户对其特定 LVM 命名语境确认的独立 `3w` 标记，可以作为限定范围内第二 Channel 的三阶信号解释依据；它不是所有 LVM 的硬件通则，也不能把 `2nd` 直接当作 2ω。`Current` 扫描与 3ω 信号可以同时成立，不能由 Workflow 名称把电流轴改成磁场。[S3 §6–8]

## 5. 模块职责与数据流

### 5.1 正常仪器数据路径

**Inbox 接收 → D2 读取与解释 → D3 正式保存标准数据 → Workbench 或 Automation 调用 D4 → D3 保存成果 → Sample/Notebook 展示。**

手工定量记录、照片和实验笔记直接通过相应入口进入共同数据体系，不必绕成仪器文件。手机入口上线后同样如此。

| 责任边界 | 输入及职责 | 输出或允许请求 | 不允许 |
|---|---|---|---|
| Inbox | 原始文件与接入状态、待确认问题 | 调用 D2；展示来源与异常 | 自带另一套自动分析参数、绕过标准数据作图 |
| D2 统一器 | 结构读取、列/矩阵保留、语义和对象归属线索 | 标准数据内容、依据、未知项、解释修订；请求 D3 管理 | 科学清洗/拟合；自建身份权威；静默丢列丢符号 |
| D3 数据核心 | 身份、正式资产、关系、版本、权限、采用和清理 | 可稳定读取的数据；正式提交结果和状态 | 解析仪器格式、决定算法、调度自动化 |
| D4 能力 | 明确数据引用、解释、方法、科学配置及必要绘图配置 | 数值/曲线/矩阵/图和诊断 | 偷读原始文件、偷读 UI 状态、自行改 Parameter |
| Workbench | 人工选择、探索、调参、预览、比较 | 组装明确请求；请求保存/采用；编辑正式预设 | 成为唯一执行入口或私有保存政策 |
| Automation | 已生效定义、匹配条件、就绪信息、授权 | 调用 D4；按权限请求 D3 保存 | 自创算法、私改解释、以新图触发同一流程回环 |
| Spin Cat | 已授权上下文与能力缺口 | 有基线、差异和证据的候选提案 | 隐形正式规则、未经授权发布、把猜测写成事实 |

Library 一词有两种使用场景：前台的组织视图，以及 D3 管理的数据仓库边界。它不意味着必须把全部代码、全部资产装进一个模块或一个物理数据库。

### 5.2 未知、损坏与分析适用性分别处理

“Bridge 有电阻但不知道 Rxx/Rxy”是解释不足；“源文件有列但被读取器截掉”是内容完整性问题；“数据完整但不满足某拟合方法”是分析适用性问题。

接收数据不要求所有解释都完成。只阻塞真正依赖缺失信息的动作。来源截断、单位冲突、丢负号、分支混乱不能被包装成完整成功；仍可保留源文件和已经可靠读取的部分，但必须明确其限制。[S3 §7；S5 §2.2]

## 6. 跨模块最小合同

以下是任务必须落实的语义合同，不规定字段名、API 或事件框架。

### 6.1 “就绪”不是“所有问题都解决”

C05 表示资产提交完成且可以稳定读取，不表示所有 Role 已知或所有方法适用。自动化按 D4 声明的必要条件判断是否可运行；Sample 归属未明确时不得向任意 Sample 自动存图。

同一 Source 拆成多份数据，不要求在内存里做完全部后一次性宣布所有数据可靠；但每一份被标为就绪的资产及其必要来源关系必须真实完整。部分失败应可识别，不得以整批成功掩盖。

未知含义后来补齐、归属更正、历史数据迁移是否触发自动处理，不冒充“新测量首次导入”。其重跑范围在相关任务中明确，默认不通过重建索引无声补做历史工作。[S3；S6 §4–6；D6 收敛]

### 6.2 运行快照与当次有效值

人工选择的参数、方法默认值、预设覆盖、自动选通道结果应在运行前解析成明确快照。预设更新不修改已完成分析，运行中控件变化不改变当前计算。

结果需能定位输入数据与解释修订、实际方法和配置。并非所有软件环境信息都必须记录，只有影响结果或验证所需的信息进入合同。精确数值容差、随机性处理及方法版本规则在相关任务确定。[S5 §2、4、6]

## 7. 正式记录、Parameter 与成果生命周期

### 7.1 原生记录与当前值

用户可无仪器文件、无 XLSX 地建立 Sample，录入结构化标量、照片与笔记。手工记录不强制属于 Measurement。修改并确认 Parameter 后，新值立即成为该范围的当前值，理由不强制填写。

人工声明、仪器观测、算法结果和人工修正后的值保留各自来源。Parameter 引用或表达当前选择，不抹掉底层观测，也不生成一份不可对账的独立事实。[S2；S4]

### 7.2 保存、采用与新旧顺序

**新人工有效修订优先于旧人工修订；人工明确裁决优先于未经授权的机器建议。** 比较范围是同一对象、量、角色及适用语境，而不是所有同名参数。

AHE 的 Save to Library 可以同时保存 Result 并按已明确规则采用。用户必须能够理解本次操作会不会更新当前值。已有人工明确选择时，普通保存新结果不静默替换；明确选择“用此结果更新”可以表达新的人工决定，不要求再完成两轮普通确认。

同步晚到、文件重新导入、缓存刷新或新的计算时间戳，不是新的人工修订。“最新值指针”是实现手段，不能代替上述决定。[S4 §3–6；S5 §5]

### 7.3 科学状态、保存状态、采用状态不混用

不能计算、能算但解释受限、满足已声明方法条件，是科研/方法状态；草稿或候选、已正式保存，是保存状态；当前是否采用，是裁决状态。

这三个维度可以分开表达，不要求现在实现一个复杂通用状态机。零值不能表示缺失；fallback 不能伪装为原方法的可靠结果；“valid”只表示满足已声明条件，不是对科学结论的普适背书。[S5 §2.2、5、7]

### 7.4 图像和数值的保存

纯绘图可以只生成受治理的 Plot Artifact，它引用稳定的标准数据和完整绘图配置。

执行科学处理时必须产生可访问的数值输出，不能只剩 PNG 中的像素或标题。正式发布 Hc/R_AHE 等指标必须保存其量、单位、条件、方法与来源。正式派生曲线/矩阵如何长期保存，允许在“完整数值物化”与“有充分版本依据的可靠重建”间比较；仅留文件路径或未固定默认值不算可靠重建。

临时 flatten、试窗、换色和重复计算不必永久保存。正式、被采用或被下游引用的成果必须符合其保留承诺。标准数据本身是长期资产，不能因为存在可重建缓存，就把用户解释和必要来源一并当临时文件丢掉。[S4 §7；S5 §3；S6 §5]

### 7.5 纠错、删除、重试和恢复

纠正尺寸、单位解释或归属时，当前修订按人工决定生效；受影响的衍生成果标记待复核，不静默改写成“本来就基于新事实”。无关备注或显示变化不使全部分析失效。

同一科学请求的等价重试不无限新增正式 Result；绘图样式变化可形成不同显示成果，但不因此创造新的物理观测。具体等价判据包含实际需要的数据/解释/方法/科学配置/范围；不能仅凭数值或 Sample 名去重。

删除一张图不默认删除其数值、来源或别的 Sample 的引用。明确删除/不再生成的决定必须在重启、重复事件和索引恢复后仍有效；显式重新出图与恢复另行表达。缓存可以再生成，但不能用“重建缓存”之名复活用户明确删除的正式成果。

破坏性变更、歧义合并、需要改变已有科研信息的恢复或清理，沿用 D3 的“发生时交用户裁决”。正常、已授权操作不逐次审批。保留期、硬删除、重算默认值仍开放。[S3 §6；S4 §6–9；S6 §6]

## 8. 自动化与 Spin Cat

### 8.1 首期最小功能

每条启用的自动化至少能说明：匹配什么标准数据、使用什么能力/预设、允许保存什么、归到哪里、是否启用以及最近必要运行状态。

Workbench 的临时设置只影响探索；只有明确保存为预设/应用变化才影响未来运行。多个入口编辑同一个对象，不维护多个开关真相。预设和自动化应能够脱离页面持久保存并被执行。

首期 AFM/AHE 各自独立，不自动串成报告链。常规运行不调用大模型也应成立。首期成功不宣称已经实现任意组合、RHEED 或完整 Spin Cat。[S6；S7]

### 8.2 权限与异常

存图授权不自动包含把指标设为 Parameter。计算、保存 Result、改变当前采用的权限要能区分。任务触发者无私有 Library 写入口。

关闭开关后不受理之后的新自动任务；正在运行任务如何取消或结束、重新开启是否补跑、应用退出后的承诺，需要在自动化任务合同中明确。已撤销的保存权限不能被运行启动时的旧快照绕过。

重复通知、提交后重试和部分失败必须有对应验收；候选试跑不能通过旧 Save 路径进入正式 Library。产生图或 Result 不默认成为这条流程的新测量触发器。[S6 §4–6]

### 8.3 Spin Cat 的后续接入

Spin Cat 可建议来源解释、预设、流程和能力扩展，使用同一正式对象的候选修订。缺少解析器或科学能力时必须说明缺口，不把添加一条流程当作已经支持该能力。

当前未授予其自主发布正式变化的权限；未来可以在用户明确授予的范围内扩展自动升级权。无论授权级别，基线过期、验证失败或超范围都不能静默生效。

经验记录保留明确纠正、采用、拒绝及其背景；删除重复图、普通浏览不等于科学否定。没有理由不猜动机。规则、授权、验证和经验属于 SpinLab，可更换 AI Provider；本轮不预选训练、RAG、热加载或全部行为日志系统。[S1 §7–8；S6 §7]

## 9. 手机、桌面与外部文件

### 9.1 产品分工

手机 Web 是实验现场的生长录入入口，支持 Batch/Sample 与结构化 Recipe；桌面主要处理后续测量、分析，并可纠正先前记录。两端共用正式身份、创建/同步意图与修订制度。手机/桌面不是两种数据权力等级。Obsidian → XLSX → App 等历史入口是来源链路，不再各自决定 Sample 的权威身份；来源身份映射与创建请求的幂等性在共同数据核心治理。

XLSX 保留历史导入，未来主要为可选表格导出或备份出口；不是长期强制中转，更不能在旧表重导入时覆盖已确认修订。表格导出不等于包含全部资产、版本和关系的完整备份。[S4 §0、3、8]

### 9.2 上线前必须解决而当前不预选的技术

必须明确正式记录放在哪里、本地副本与服务端各承担什么责任、身份如何对账、授权及访问边界、离线/冲突/失败如何呈现、怎样备份和恢复。

“用户只主动录入一次”不意味着任何同步都绝无冲突。晚到的旧版本不能凭到达时间成为新值；两个无法自动判断先后的有效修改交用户处理。已经成功保存的本地修订不因同步失败被静默撤销；界面不能把本地已保存误报为远端已同步。

现有静态 Web 导出与 Note API 只作为历史实现线索，不能当作已经具备正式双向同步的证据。上述技术定案在独立手机任务中完成，不要求先把桌面自动化改造成云平台。[S4 §2、8、10；D6 收敛]

## 10. 渐进迁移与兼容规则

### 10.1 按真实覆盖范围切换

以“来源格式/版本或已确认样本结构 + 语义范围 + 消费 Workflow”为迁移单元，不能只按 `.dat`、`.lvm` 扩展名宣布全支持。

每个单元都要记录：新导入是否走标准路径、消费者是否已改读标准数据、哪些旧数据仍依赖旧路径、如何验证和回退。相关任务形成轻量覆盖说明；不必建设新的后台管理平台。

已迁移的新路径出错，先修复标准化或解释，不让 Workbench 临时解析原始文件伪装成功。未迁移旧功能可在原兼容路径继续人工使用，但不接入绕过标准数据的新自动化。[S6 §9–11；S7]

### 10.2 旧模型不能凭名称删除

旧 `sampleKey`、Library 文件、sidecar、`ArchivedRecord`、结果索引及 Analysis Pack 均可能有真实读写者。先按当前代码和隔离数据核查，再决定保留、映射或迁移。

稳定身份以保留旧关联的方式引入，不直接批量替换旧 key/路径；改名和移动不能使结果失联。不可变恢复快照可以存在，但不能成为第二个可独立修改的当前事实。

历史迁移按用户选择的范围执行，先预览/校验，再受控提交和回读；不附带默认重算、批量自动出图、硬删除或全面重写。失败与恢复证据必须与实际承诺相匹配。[S4 §8；S7]

### 10.3 不把可靠性留到最后补

新增正式写入、自动重试、清理、同步或迁移时，本任务就应包含相应的失败与恢复保护。不能先在生产启用自动存图，再在未来 PR 才补避免重复和删除复活。

原始证据的不可变性约束转换和计算，不剥夺用户明确清理的权利。**移除某一关联、归档、进入待删除状态、永久删除实体/物理文件是不同动作**；只在对应操作正式受支持时定义其状态与界面。删除共享资产前须检查其他关系、派生结果与恢复影响；不知道依赖范围时安全拒绝。恢复期限、自动清理、硬删除和备份边界仍由相应任务决定，不以候选 30 天等数值冒充已批准默认值；未授权不得操作真实实验数据。

## 11. 实施、审查与验收制度

已确认的协作方式：**GPT 结合基线、任务卡与当前仓库生成 Prompt → Coding Agent 执行 → GPT 审查 GitHub → 用户与 GPT 在真实 App 验收 → 用户授权合并。**[S7]

### 11.1 任务开始前

GPT 读取适用的仓库规范和当前目标分支/提交；有本地访问时核查工作树，无访问时要求 Agent 在编辑前补证，不假装已经看过。只做与本任务相关的定点核查，不反复全仓 audit。

当次任务合同固定：目标、支持范围、必要前置、架构约束、关键产品/科学决定、验收标准、必需证据和权限边界。可以将一个功能拆成多个 PR；每个 PR 的局部通过不代替整项功能验收。

尚未确定但会改变用户行为、科学含义、迁移、安全或失败后果的事项，在该任务定稿前解决；普通内部实现由 Agent 负责，不交回用户选择类名和目录。[S8]

### 11.2 审查实际代码和实际版本

审查以原任务合同、PR diff、关键调用关系、已有消费者和证据为准，不只读实现者总结。原始需求与代码分别检查，避免把实现者预设的结论当审查结论。

代码/证据通过后才进入相应现场验收。现场应说明正在运行的 App 来自哪个 PR head 或提交、构建标识及测试数据，避免验收旧安装包。工具无法直接操作用户设备时，由用户运行步骤并回传观察或文件，GPT 不声称自己执行过。

代码审查、数值证据、真实交互及写后重读各自证明不同性质。截图不证明数值正确、持久化可靠或权限隔离；测试存在不证明测试运行通过；测试通过也不证明方法科学适用。[S8 §4–5]

### 11.3 完成与变更

缺陷在原任务/PR 及同一验收合同内修复并复审，不能通过改测试预期或缩小验收范围制造通过。新增实质需求单独记录并调整任务/基线，不把无关愿望加入当前验收。

需要的代码审查、必需证据、现场验收均满足后，由用户决定合并。合并后按任务要求确认最终分支构建和必要回归，才将路线图状态设为完成。

本文件不授予当前会话修改代码、提交 PR、推送、合并、修改权限或迁移生产数据的许可。未来每次任务 Prompt 单独明确授权。

## 13. 版本管理与文档权威
