# 任务 8 设计：手机网页新建样品，电脑自动收进 Library

对应简报：[brief-8-phone-new-sample.md](brief-8-phone-new-sample.md)。本文只出方案，不含实现。

## 选定路线：A（云端待收）

手机提交写入网页库已有的云端数据库的一张新表；SpinLab 启动或手动刷新时取走，经"电脑新建"同一条创建路径建样品，成功后在云端标记已收。

## 备选与取舍（Options）

| 路线 | 结论 | 原因 |
|---|---|---|
| A 云端待收 | **选定** | 复用已有的网页库云端数据库、邮箱登录保护、发布流程，以及任务 1 的创建路径；电脑关机不丢；满足"自动出现" |
| B 手机生成文本、手动复制导入 | 拒绝 | 最简单，但没有"自动出现"，需求 4 退化为手动搬运 |
| C 电脑起本地服务、手机直连 | 拒绝 | 电脑关机即失败，违反需求 4，还要把电脑暴露到公网 |
| D 手机直接写共享文件夹里的 Library | 拒绝 | 违反"手机不碰电脑数据"的硬边界 |

## 方案要点

1. **一份数据形状。** 定义"新样品提交 v1"：只含用户填的原始值，不含换算和单位。电脑新建窗口与手机提交产出同一结构。换算、单位补全、能量三个数值标签、频率默认 2 Hz 只在电脑端一个共用映射里实现，Excel 导入也走它（复用现有的 Registry 解析与能量/脉冲规则，补齐样品高度、频率、激光器电压等新标签名）。手机页只收原始数字。
2. **选项与单位只一份。** 实验室、生长材料、衬底三项选项加进规则本；静态库导出时把表单需要的选项和单位文字带进快照，手机页据此渲染，不在页面里另写一份。
3. **一次提交只一个样品（K4，编号 K1）。** 提交编号在打开表单时生成，随表单内容保存在手机；重发是同一编号，云端忽略重复，页面仍显示"已提交"。电脑端以该编号作为样品编号，Library 已有则跳过，所以重复拉取不会多出样品。云端行标记已收而不删除，防止迟到的重发再建一次。
4. **失败不留半成品。** 沿用任务 1 的原子创建（失败时清理已写出的批次文件）。标记已收失败，只会让下次又看到该项，被编号检查跳过。某条提交校验不过：保持待收，在刷新结果里提示，不影响其他条，不新增状态。
5. **取件时机。** 启动与手动刷新，不做后台轮询。
6. **权限。** 站点已在 Cloudflare Access 保护之下（见 `docs/web_library.md`）。开工第一步实测：未登录请求访问提交接口被拒。电脑端用 Access 服务令牌取件，存 macOS 钥匙串；令牌需 Jack 一次性在 Cloudflare 创建并录入。若接口路径未受保护或无法建令牌，停工报告，不自行换方案。
7. **两个仓库。** 云端函数与数据库迁移在 SpinLab-Web-Library（手写部分）；表单页源在本仓库 `Resources/WebLibraryTemplate`，经发布脚本生成到网页库。各一个 PR。
8. **验收4调整。** 手机必须先打开页面才能填表，所以"断网"指页面已打开后网络中断：提交显示"未提交"、内容仍在；恢复后再点成功。

## 分阶段

- **P1** 规则本选项 + 共用映射 + 电脑新建窗口补字段。证明：三入口（新建窗口 / Excel 导入 / 提交结构）对同一内容数值标签与单位一致；旧样品读取不变。
- **P2** 云端新表与提交接口 + 手机表单页。证明：重复提交同编号只存一行；未登录被拒。
- **P3** 电脑端取件。证明：同编号重复取件只一个样品；取件中途失败无半成品；关机期间的提交开机后收进。
- **P4** Jack 按简报七步验收（第 4 步按上条调整）。

## 假设（Assumptions，请确认或划掉）

- 只有 Jack 一人使用，手机与电脑不会同时改同一个样品。
- 站点（含提交接口）已在邮箱登录保护之下，开工时实测。
- Jack 愿意一次性在 Cloudflare 里为电脑创建取件令牌。
- 手机要先成功打开页面才能填表；"断网"指打开之后的网络中断。
- 能量拆三个数值标签只用于新建的样品，旧样品保持单个"能量"。
- 一条校验不过的提交留在云端待收并在 SpinLab 里提示，不会被自动丢弃。
