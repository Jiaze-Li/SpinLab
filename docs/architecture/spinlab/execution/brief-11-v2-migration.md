## 目标

## 11A：审计与设计交付

### A. 功能与路径兼容矩阵

对照当前 main 实际代码和合同，覆盖 V1 的两种 Batch 路径以及 V2 正式路径。每个消费者记录：用户行为、读写对象和权威、代码路径/符号及基线、V1 现状、V2 实际支持/明确拒绝/未知、迁移后影响、证据类型、最小修复建议。不能只因入口存在就判定可用。

至少核查：
- Library 创建/打开/搜索/筛选/编辑、Batch 与 Sample 归属、Growth、Result Definitions 和当前值、Registry/XLSX 同步与 Recompute、手机新建/笔记与 Publish/网页投影；
- Inbox 路由、Apply、原始文件、Sidecar、measurement_sets.json、measurement_data.json、测量/通道/条件及去重；AFM、AHE、RT、3ω、XY 和其他当前启用的 Workflow 按实际代码盘点，不假设都使用同一数据格式；
- Workbench 分析、图/历史 Analysis Pack 的保存、打开、恢复、导出、跨样品图、AHE Result 赋值；AFM 正式 Plot 与自动出图的切换/恢复；
- 废纸篓、恢复、永久删除、共享依赖、历史归属、备份、单写者租约、索引重建、错误/中断后的 fail-closed；所有直接拼 V1 路径、绝对路径、旧 key 的消费者。

分类建议：①必须迁移前解决（既有必要能力丢失、数据/归属/写入不安全）；②可以保留的明确兼容路径（有权威、读写与删除边界，满足 V2 版本合同，无双写或静默回退 V1 正式记录）；③不阻塞、后续按需适配（如尚不存在的新功能）。实际取舍以证据为基础，涉及用户可见退化或科研语义的选择须明确确认，不能用“明确拒绝”冒充功能兼容。无必要不新增统一框架。

### B. 数据清单、语义映射与冲突

设计完整预检/对账清单，覆盖活跃及废纸篓 Sample、合法唯一 sampleUID、历史 legacySampleKey 映射（手工/手机新建无旧 key 合法）、Batch 归属、旧 sampleKeys、Growth 重复/冲突、未知字段、Result Definition ID 与精确数值/单位/空值、Registry/提交与笔记、原始文件及其哈希、测量集/Sidecar、历史图/Pack/共享资产和外部/绝对路径引用、AFM 已有资产与关联（如实际存在）。区分可重建索引与正式数据、独立信号与多通道、明确旧数据映射与无法确定的来源。只报告无法解释的冲突、孤儿或未知，不猜测、不自动合并、删除、补零、覆盖、标准化科研内容或自动重算结果。

明确每类数据的迁移策略（保留/忠实转换/可验证重建/受控兼容/需人工决定）、输入输出身份映射及对账标准。保留原始字节和历史必要元数据，按 K5–K12 保持科研归属/依赖和唯一权威。无可信来源时，不虚构 Source/Dataset/Plot 关系；未登记文件不得被当作垃圾删除。

### C. 迁移与恢复设计（本阶段不写实现）

比较最小可行的副本构建与切换方案，并给出推荐及风险：源库保持完整、只读预检、备份及恢复验证、隔离副本预演、结构/语义对账、版本标记与单写者、切换前重新校验源状态、切换提交边界及中断恢复、切换后验收与可执行回退。明确旧 App 不可写 V2、新 App 仍须支持合法 V1；禁止半迁移/双写/静默路径回退。说明切换后已有新写入时的回退限制及避免数据丢失的策略，不默认覆盖新数据。复用已有保护机制，不提前创建通用迁移引擎、历史库或第二套数据库。

### D. 执行顺序与交付

1. 提交 `design-11-v2-migration-readiness.md`：源码证据、兼容矩阵、数据清单、阻塞项及最小独立任务、迁移/恢复方案、风险和验收计划，明确未验证及待用户决策。
2. 依据矩阵提出必要的消费者适配顺序及独立范围；可并行则不强制串行，不以完成所有未来 Workflow 为前提。11A 不实施这些修复。
3. 11B 在必要兼容验证及设计确认后另行授权，实施迁移工具、隔离副本与失败/恢复验收；真实库迁移仍为单独授权。涉及真实数据格式迁移的 major version 按 AGENTS 另行明确批准，不因本 design PR 自动授权。
