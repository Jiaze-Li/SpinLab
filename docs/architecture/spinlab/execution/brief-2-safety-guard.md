# 任务 2：Registry 少一行不再删样品，删除功能暂时关闭

对应原 G1-01。代码已经写好，在 PR #195（分支 `G1-01`，叠在 `T01` 上）。本任务是把它收尾并合并，不是重写。
流程：**直接 code 模式**，不需要 design 模式。前置：任务 1 已合并到 `main`。

## 目标

Registry 表格里缺行或改了编号时，同步不删除任何样品；App 里删除样品、删除批次的入口暂时关闭并说明原因。

## 需求

1. Registry 表格里某个样品的行没了，或者它的编号变了，我点同步：样品文件夹、测量文件、图都原样保留，并告诉我是哪个样品、为什么没同步。
2. 在 App 里删除样品或删除批次：被拒绝，提示"删除功能暂未开放"。文件一个都不动。
3. 只是查看、预览、搜索，不会改动 Library 里任何文件。
4. Library 里某个文件坏了读不出来：报错并停下，不当作"没有这个样品"继续同步。
5. 正常的同步（表格里新增样品、改了属性）照常成功。

## 不做

- 废纸篓、恢复、彻底删除。
- G1-01 补充设计 v0.1–v0.4 里的任何内容：跨进程锁、Root 身份登记、pending / completed 记录、落盘顺序。**这些已停止，不要实现。**
- 改样品编号规则、迁移数据。

## 代码现状（PR #195 HEAD `01e19d8`）

- `Sources/SpinLabApp/Library/LibraryMutationSafetyGuard.swift`（新增）：写入前的安全检查。
- `LibrarySyncService.swift`：`applyBatch` / `applyAll` 在写入前拒绝缺行和改键引起的删除（提交 `af79b16`）。
- `Tests/SpinLabAppTests/LibraryMutationSafetyTests.swift`：约 2350 行测试。**评审机器人只读了前 600 行，这个文件还没被完整审过。**
- 评审机器人待处理 F001：`LibraryMutationService.deleteExistingDrawer` 先读索引、后删除、再把旧索引写回，可能覆盖别处刚写的内容。

## 要做的事

1. 任务 1 合并后，把 `G1-01` 变基到 `main`，解决冲突。
2. 关闭全部递归删除入口：`deleteExistingDrawer`、`deleteSampleDrawer`、`deleteBatchDrawer`，包括不经过界面的直接调用。删除一关，F001 描述的路径就不可达；在 PR 里按此说明关闭 F001。
3. 核对需求 1–5 各有测试覆盖，并且测试确实走到了被保护的那一步，不是在更早的检查处就返回了。
4. 让评审机器人把测试文件完整审一遍。

## 我怎么验收（在测试 Library 里）

1. 准备一个带测量和图的样品。从 Registry 表格里删掉它那一行，点同步。样品、测量、图都还在，界面说明了原因。
2. 在 App 里尝试删除一个批次。被拒绝，文件夹原样。
3. 在表格里新增一个样品，点同步。新样品正常出现。

## 需要你确认的一点

需求 1 的做法是：只要某个批次里有缺行或改键，**这个批次的这次同步整个不执行**，直到表格里把那一行补回来。这是 PR #195 现在的行为，最保守。另一种做法是"其余照常同步，只是不删那个样品"，更方便，但编号改动时会多出一个空的新样品。如果你更想要后一种，在派任务时说明。
