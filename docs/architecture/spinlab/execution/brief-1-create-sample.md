# 任务 1：新建样品，编号永久不变

对应 D6-B 的 T01 和 G2 中属于样品编号的部分。在 PR #194（分支 `T01`）上继续，不另起炉灶。
做法已经定好，不需要单独的设计阶段。

## 目标

用户不依赖 Excel 表格就能新建样品；每个样品有一个永不改变的编号；属性完全相同的样品可以并存。

## 需求

1. 没有导入 Excel、没有仪器文件时，我能新建一个样品，并在 Library 里找到它。
2. 同一批次、同一衬底，我能建两个样品。两个都在，互不覆盖，各有各的文件夹。不需要我手动加序号来区分。
3. 关掉 App 重开，样品还在，编号和建的时候一样。
4. 我点一次"创建"，只出现一个样品，哪怕程序卡了一下或我多点了一次。
5. 保存失败时明确告诉我失败，不留下一个打不开的半成品。
6. 改样品的名字，不改变它的编号，它的测量和图也不丢。
7. 我已有的旧样品不受影响：照常显示、照常打开测量和图。

## 不做

- 删除样品。
- 给旧样品补编号。
- 参数编辑、素材链接、SQLite。
- 改分析算法、改 Library 界面布局。

## 代码现状（PR #194 HEAD `d29d914`，Agent 开工前须自行复核）

- `Sources/SpinLabApp/Library/NativeSampleCreationService.swift`：创建时已生成 `smp_` 加 UUID 的 `sampleUID`。
- 同一文件约第 147–212 行：样品的 `id`（也就是文件夹名）是"批次_衬底"拼出来的，并据此拒绝重复。**这与需求 2 和骨架 K2、K3 冲突，是本任务的主要改动。**
- `Sources/SpinLabApp/Library/Domain/LibraryDomainModels.swift`：`sampleUID` 是可选字段；没有它的旧样品用"`legacy:`批次`:`旧 key"顶替。旧样品保持这样，本任务不动。
- 样品文件夹路径由 `LibraryStore+PathsAndCache.swift` 的 `sampleDirectoryURL(batchID:sampleKey:)` 决定。
- PR #194 评审机器人留下两条待修：
  - F001：`isNativeOrManual` 把"没有来源表名"的样品都当成手工样品，会让旧的 Registry 样品被冻结、不再同步。应只按 `origin == "native"` 判断。
  - F002：`NativeSampleUITests.swift` 用了真实的设置文件，跑测试会改写开发者自己的 Library 路径。应改用临时设置。

## 已定的做法

- **新样品的文件夹名（`id`）直接用它的 `sampleUID`。** 这样永不冲突，改名、换批次都不影响，以后同名的新样品也不会接到旧样品留下的图。用户看到的始终是显示名，不是文件夹名。
- **衬底、批次只是属性。** 去掉按"批次 + 衬底"判断重复并拒绝创建的逻辑。
- **打开新建表单时就生成好 `sampleUID`。** 提交时如果这个编号的样品已存在，返回已有的那个，不再新建。不新增任何操作记录文件。
- **旧样品的 `id` 和文件夹保持原样。** 不改名、不补编号。

## 我怎么验收（在测试 Library 里）

1. 不导入 Excel，新建样品 A（批次 X，衬底 STO）。能在 Library 里看到。
2. 再建样品 B，批次、衬底、名字和 A 完全相同。A 和 B 都在。
3. 退出 App 重开。A、B 都在；打开文件夹看两个 `sample.json`，编号与创建时一致且互不相同。
4. 把 A 改名。A 的编号不变。
5. 打开一个旧样品，它的测量和图照常显示。

Agent 另需用自动测试证明：同一编号重复提交只产生一个样品；写入失败不留半成品；旧样品读取不变。
