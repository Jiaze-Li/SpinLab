# SpinLab 数据骨架

每次给 Agent 派任务都原样附上这一页。它由 G0 v1.4（§1–§3）和新数据库 v0.2（§0–§2）合并而来，冲突之处按用户 2026-11-11 的决定取舍。这里的内容不在单个任务里重新讨论；要改，先改这一页。

## 有哪几种东西

| 类型 | 含义 | 编号前缀 |
|---|---|---|
| Sample | 样品 | `smp_` |
| Parameter | 样品上的一个字段（温度、厚度、电阻……），只有当前值 | 无单独编号，由"样品 + 字段名 + 适用条件"定位 |
| Source | 原始仪器文件 | `src_` |
| Dataset | 从原始文件整理出的标准数据 | `dst_` |
| Result | 分析算出来的数值（如 Hc、R_AHE）；不含曲线 | `res_` |
| Plot | 图，连同画这张图用到的曲线数值 | `plt_` |
| Snapshot | 用户主动保存的一份定格 | `snp_` |
| Attachment | 照片、笔记 | `att_` |
| 链接 | 一行记录"哪个样品、哪个素材、什么关系" | 无 |

批次（Batch）是样品的一个属性，不单独成类。

## 规则

每条前面的编号供任务合同引用。

- **K1 编号永不变。** 编号在创建时随机生成，之后不因改名、换批次、移动文件、重启、重试而变化。
- **K2 编号不含含义。** 编号不由名字、批次、衬底、路径或文件内容推算，也不拼接其他对象的编号。
- **K3 建几个就是几个。** 用户明确新建两次，就是两个样品，即使名字、批次、衬底完全相同。程序不判断两个样品在现实中是不是同一片。
- **K4 同一次操作不重复生效。** 同一次点击因卡顿、重试、重复触发被提交多次，只产生一个结果。
- **K5 素材和归属分开。** 素材有自己的编号；它属于哪个样品，记在链接表里。一个素材可以链接多个样品。
- **K6 取消链接不等于删除。** 取消链接只删掉链接表里那一行，素材本身和它的其他链接不动。
- **K7 原始文件不改写。** Source 的内容登记后不被修改。从原始文件整理成 Dataset 时只做格式整理和有依据的单位换算，不做平滑、扣背景、拟合等科学处理；这些属于分析，产出是 Result 或 Plot。
- **K8 Parameter 只有当前值。** 修改经用户一次明确确认后覆盖旧值；只输入数字不确认，不生效。不保留逐次修改历史。
- **K9 分析结果不自动改 Parameter。** 算出来的数值是 Result，不会自己写进样品的手填字段。
- **K10 输入变了，结果标记过期。** Parameter 或 Dataset 变化后，用到它的 Result 和 Plot 标记为"需要更新"，不再当作当前结果展示。
- **K11 快照不跟着变。** Snapshot 保存当时的输出和所用的输入值，之后不随任何修改而变。
- **K12 不知道就留空。** 归属、单位、通道含义不明确时保持"未知"，不按文件名、通道号或最相近的名字猜。
- **K13 损坏不等于不存在。** 文件读不出来、索引缺失时报错并停止，不当作空库继续写。

**Dataset 同 ID 更正的安全底线（任务 5 才实现）：** 只允许同一 Source 的同一信号做忠实解析或有依据的解释更正；更正启动时记下该 Dataset 的当前内容标记，正式提交前再次核对。若期间已被其他操作更新，则拒绝过期提交并报告冲突，不让晚完成的旧任务覆盖新确认的内容。同一操作的重复提交不生效两次；更新成功后按 K10 使下游结果过期。单写者保证提交串行，但不能代替过期校验。具体实现由任务 5 的设计决定，不要求现在建立历史版本库或跨进程协调日志。

**Live / Snapshot 提交的安全底线（首次消费者才实现）：** 后台计算只产生候选输出；把已有 Result/Plot 发布为 `current` 时，须在**同一不可交错的正式提交边界**内核对全部直接及传递依赖的当前标记、方法/配置/归属和该 Live 对象自身的定义/状态标记，并完成输出发布与状态更新。输入变更及其下游失效必须与发布共享这一串行提交次序；不能先检查再放开保护、随后另行标记 `current`。若标记或绑定已变，拒绝旧输出、保持过期状态；即便值从 A→B→A 也不能把旧任务重新判为有效。用户主动保存 Snapshot 时，同样须在不可交错的提交确认点核实所固定的 Live 输出、完整依赖及归属，并且只在必要的不可变内容可读、固定成功后宣告 `saved`；有并发变动则拒绝/重试，不产生伪有效快照。可用单写者内的串行临界区/本地事务满足，具体存储与恢复策略留给任务 6 或首次 Snapshot 消费者设计；不要求任务 1–5 提前实现跨进程 CAS 或新日志系统。

## 存在哪里

- **样品本身**继续存在现有的 Library 文件夹里（每个样品一个 `sample.json`）。现有旧库不搬家、不批量改写。
- **新增的记录**（链接表、Source / Dataset / Result / Plot / Snapshot / Attachment 的登记信息）存进 Library 里的一个 SQLite 数据库文件，用样品编号与样品对应。
- **大文件**（测量数据、图片）仍放在文件夹里，数据库只记它们的位置和校验值。
- Parameter 存在样品自己的 `sample.json` 里（见 `brief-4`）。

## 使用上的前提

- 同一个 Library 同一时间只有一个 SpinLab 进程可写；第二个实例只读打开。
- 用户不绕过 SpinLab 手动改 Library 里的文件。
- 所有开发和测试都在单独的测试 Library 里进行，不碰真实数据。

## 现在不做

- 删除样品、删除批次：保持禁用，等链接表做好、删除方式（进废纸篓、可恢复多久）定下来再开放。
- 旧样品批量补编号、旧数据迁移。
- 手机同步、批次改编号、独立的 Device / Measurement 类型：等第一个真正需要它的功能出现时再定。
