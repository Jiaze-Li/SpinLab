# SpinLab D6-B — 分阶段实施路线图与验收任务卡

**版本：** v1.0  
**日期：** 2026-11-08  
**依赖基线：** `SpinLab_D6-A_统一架构基线_v1.0.md`。  
**性质：** 功能目标、依赖、计划、约束与验收依据；不是 Coding Agent Prompt，不指定未来源码路径、函数、测试命令或 PR 编号。  
**初始状态：** 本路线图尚未执行任何开发任务。下文“未开始”指本计划中的交付与验收，不能据此断言当前仓库完全没有相关功能。

## 0. 怎样使用这份路线图

每次在新 GPT 对话中上传 D6-A 和本文件，选定一个任务。可以附上后续两个任务作依赖背景，**但默认只要求为当前一个任务生成实施 Prompt**，不能把选中的三个编号自动合并成一次大重构。

GPT 核查当前仓库、已完成前置和相关旧消费者，确定实际缺口；解决本任务的必要产品/科学选择；再生成一个自包含的 Coding Agent 任务合同。现有能力已满足的部分直接复用，不为了完成任务编号重复开发。

流程固定为：

**选任务 → GPT 对照当前 repo 形成合同 → Agent 开发与提交证据 → GPT 审查 GitHub → 用户在对应构建中验收 → 用户授权合并 → 回传完成事实 → 下一任务。**

本文件写“应该证明什么”；当次 Prompt 写“本次用什么范围、实现边界和证据证明”。任务合同一旦确认，不通过降低验收标准掩盖失败。

## 1. 里程碑与建议顺序

### 1.1 产品里程碑

| 里程碑 | 完成后用户获得什么 | 任务 | 完整验收边界 |
|---|---|---|---|
| M1 桌面原生科研记录 | 不依赖 XLSX 或仪器文件建立 Sample，记录和纠正有语义的 Parameter、关联照片/笔记，重启仍可用 | T01、T02 | 身份、当前值、必要来源与旧功能兼容 |
| M2 第一条标准数据与自动出图闭环 | 新 AFM 经过标准化入库，人工与自动从同一标准数据处理、出图、归档 | T03、T04、T05 | 接入、独立计算、真实开关、重试/删除/权限及现场使用全部成立 |
| M3 表格语义与 AHE 成果闭环 | PPMS 通道在前台解释与复用规则；AHE 正确读取、产生结构化结果并受控采用；随后自动出图 | T06、T07、T08 | 多对象/多条件不混、无效值不伪装、人工采用不被覆盖 |
| M4 扩大覆盖与有选择地迁移 | 一类 LVM 用途进入新路径；历史数据可按范围迁移，不破坏旧结果 | T09、T11（按范围滚动） | 不按扩展名宣称全支持；每个迁移批次独立验证 |
| M5 手机生长记录协同 | 手机创建 Batch/Sample、录入 Recipe；桌面读取和纠正，版本及同步状态可信 | T10 | 正式身份、权限、晚到版本、失败与恢复验证；不只是静态网页可编辑 |
| M6 增加自主配置与受管理 AI 提案 | 前台创建非内置自动化；Spin Cat 对已有正式配置提出可确认、可验证的变化 | T12、T13 | 不是隐藏脚本、未批准候选不生效、过期提案不覆盖新决定 |

**主线建议：先完成 M1，再尽早跑通 M2，再扩展 M3。** M4、M5、M6 并非必须按表中位置全部串行。特别是手机架构准备可在 M1 后启动，历史迁移按各已验收的新路径分批进行；Spin Cat 提案不必等任意编排编辑器完全建成。

### 1.2 为什么先 AFM，再 PPMS/AHE

这是 **D6 的执行顺序建议，不是用户已经逐项指定的源码方案**。

AFM 适合较早证明“新数据入库—显式处理—自动出图”的完整路径；PPMS/AHE 适合证明通道语义、结构化指标和当前采用。顺序不是说 AFM 重要性高于电输运，也不是因为现有纯函数就认定其端到端已独立。

若当次仓库事实表明某条路径已完成或前置明显不同，可以调整顺序，必须保留两类验证目标与真实依赖。不要把重新排序变成取消 AHE 语义/治理验证，或反过来取消矩阵与自动执行验证。

## 2. 所有任务共同遵守的工作规则

### 2.1 从任务卡到 Prompt

当次 GPT 应补齐：实际仓库/分支/提交与相关修改、已实现前置、当前可复用入口、确切支持范围、最小字段/方法、必要默认值、兼容风险、真实数据与参考证据、可以运行的检查及授权边界。

只核查本任务相关调用链与持久化消费者。旧审计仅提供线索；无法访问的本地状态或真实数据明确标为待 Agent 补证。未决科学或产品选择阻塞相应承诺，不让 Agent 以“实现细节”擅自决定。

任务卡的 AC 是交付要求；当次合同可进一步明确样本范围和验证方式，不得悄悄删除它们。对原本未限定的范围作限定时应先说明产品影响，并在实施前确认。

### 2.2 任务与 PR

一项任务交付一个可理解的功能目标，但可包含多个 PR。纯基础 PR 允许存在，前提是它建立下一步确实需要、可独立验证的性质；不得把“加了接口或文件”称为整个功能完成。

最前面 T01–T03 的具体 PR 分界，在当前仓库核查后确定；远期任务不提前写文件级计划。不要把所有数据可靠性和负面路径放到一个最后的“补测试 PR”。

一个任务通过后再决定是否合并和推进。未来任务尚未实施的功能不应成为当前 PR 的虚假失败项；已建立的保护也不能被下一项移除。

### 2.3 验收证据

每项 AC 应有能发现其实际失败的证据。下文 E 编号是证据类别，而不是预设测试命令。

- 纯数值与结构问题：已知答案、边界样例、合理容差或可核验不变量。
- 持久化与迁移：写入后重新读取、重启或迁移后对账，不只查看内存状态。
- 前台能力：真实 App 操作或可用的端到端证据，不只 ViewModel 测试。
- 权限、去重和清理：重复提交、失败重试、删除后重启等实际会暴露问题的场景。
- 科学方法：计算正确性与方法对实验的适用性分别说明；缺少参考不能声称验证完成。

现场验收由用户在 Mac/手机上操作，GPT 提供与本任务对应的简短步骤并核对回传信息。必须确认 App 构建对应待审 PR 提交；截图不能代替数值文件回读。

### 2.4 状态与完成

状态建议使用：**规划 → 准备 → 实施 → 待代码审查 → 待现场验收 → 待合并 → 已完成**。阻塞单独标注原因，不靠改名任务消除失败。

“已完成”需要约定的功能、必需证据、代码审查和现场验收全部满足，且用户授权合并后最终分支状态已记录。未获得运行证据时写“未验证”，而不是给整项 PASS。

# 3. 近期任务卡

## T01 — 桌面原生创建 Sample，并保持稳定身份

**状态：** 规划 / 未开始。  
**所属里程碑：** M1。  
**目标：** 用户在桌面不依赖仪器文件或 Registry XLSX，能够创建、找到并重新打开一个 Sample；它有稳定身份和基本 Batch/衬底关系。

### 输入与依赖

D6-A 的 K01–K03、K08、K12；当前 Sample/Batch 创建、显示、保存、重新加载及旧 key 关联。先清点真实读写链，不假设已有类型等于已有完整用户功能。

### 范围

新增或复用一个清楚的桌面创建入口；可创建/选择必要的 Batch，填写足以表达既定 Sample 身份的最小信息。建立新 Sample 的正式身份、Library 可见性和必要旧 key 映射；Notebook 复用现有组织视图即可，不重做整个 Library UI。

现有受影响的编辑/读取路径应继续有效。对已有 Sample，只在确有必要的范围内引入可重复、不会重生的身份映射；不开展全面搬目录或旧数据清理。

**不做：** 全量 Recipe/entry 设计、完整 Device 管理、Piece 实体、手机同步、分析算法、自动化、所有旧数据迁移。

### 生成 Prompt 前必须补齐

最小创建字段和默认命名、Batch 与 Sample 的选择方式、现有创建/持久化入口、永久身份与旧 key 的最小兼容方案、创建失败与重复身份如何提示。UID 编码和存储机制按事实选择，不由路线图预选。

### 验收标准

| AC | 必须成立 |
|---|---|
| T01-AC1 | 未配置/未导入 XLSX、没有仪器文件时，用户仍能创建正式 Sample 并在 Library 中找到。 |
| T01-AC2 | 重新读取和重启后身份与 Batch/衬底关系保持不变；不因每次解析或展示重新生成身份。 |
| T01-AC3 | 新 Sample 和已有 Sample 可共同浏览；本任务涉及的旧测量、图和参数引用不失联。 |
| T01-AC4 | 相同既定身份的重复创建不无声制造第二个 Sample；关联依据有歧义时不擅自合并。 |
| T01-AC5 | 保存失败明确可见，不显示“创建成功”后留下不可读取的伪正式对象；重试不会制造多个身份。 |
| T01-AC6 | 已存在的改名/编辑入口在本任务覆盖范围内不会把合理名称变化当作新的科研对象；不要求为了本 AC 新建完整改名管理系统。 |

### 必需证据与现场验收

**T01-E1 → AC1/2：** 隔离 Library 中无 Registry 创建 → 实际落盘检查 → 退出并重开 → 对照身份和内容。  
**T01-E2 → AC3/4：** 至少一个旧样品含已有引用的兼容样例，以及重复/歧义场景。  
**T01-E3 → AC5/6：** 可控写失败/重试与受影响编辑路径的定向验证。

现场只需走清楚的用户路径：新建一份测试 Sample，关开 App 找回，再确认一份旧 Sample 的结果仍能打开。失败注入由 Agent 在隔离测试中完成，不要求用户破坏真实 Library。

### 交付及下游承诺

交付实际创建功能、最小身份/保存边界、测试与运行证据；回传哪些旧对象已映射、哪些未迁移、正式写入入口和需要下游继承的性质。T02/T03 直接复用，不另外创建样品权威。

## T02 — 手工科研记录与 Parameter 直接修改

**状态：** 规划 / 未开始。  
**所属里程碑：** M1。  
**依赖：** T01 的稳定 Sample 身份与正式写入边界。  
**目标：** 用户在 Sample 中录入有意义的电阻或尺寸量，修改确认后当前值立即有效，并可供查询及后续分析使用。

### 范围与非目标

用少量真实需要的字段证明共同语义：至少覆盖电阻和一种尺寸量。准确字段、单位选项、默认对象/条件及显示方式在本任务定稿前明确。已有合适的物理量/单位机制应复用，不重建完整 ontology。

支持独立手工结构化记录，不要求仪器文件或虚构 Measurement。保留必要来源和修订关系；提供至少一种能证明按量/单位使用数据的查询或读取方式，而不只是拼成一段文字。

同时保留非定量入口：用户可以直接给 Sample 关联一张照片/普通附件或自由笔记，Notebook 展示同一份关联，不要求把照片解释成数值。优先复用已有入口；可以作为本任务的独立小 PR，不发展成图像处理或笔记编辑平台。

**不做：** 完整量表、所有科研条件编辑器、图像测量、AHE Result 采用流程、云同步和模型训练。

### 生成 Prompt 前必须补齐

O01 的首批 entry 和适用范围；现有 Parameter/metric 读写者；“更正当前值”与“新增观测”的用户入口区别；是否复用已有历史查看及查询界面；重新导入或重建涉及的实际覆盖路径。

### 验收标准

| AC | 必须成立 |
|---|---|
| T02-AC1 | 手工值以明确量、数值、单位、对象及已知语境存在；不依赖仪器文件，也不只保存显示字符串。 |
| T02-AC2 | 将同一范围的 520 Ω 改为 500 Ω 并确认，当前值立即为 500 Ω；不要求第二次 Adopt，不凭此增加一次测量。 |
| T02-AC3 | 对另一明确条件/对象的观测，能保留为独立信息；未知条件不被伪造，局部尺寸不被自动扩大到整个样品。 |
| T02-AC4 | 重启、相关旧导入/刷新或重建路径不把已确认人工值无声恢复为旧值；保留必要修订与来源。 |
| T02-AC5 | 至少一个查询/读取场景能按量与单位取值或比较等价单位表达，而不是靠页面文本解析。 |
| T02-AC6 | 写失败不误报成功，旧有效值与当前采用关系不因失败丢失；相同重复提交不造成无意义历史堆积。 |
| T02-AC7 | 照片/普通附件与自由笔记可直接关联 Sample，重启后仍可查看；不强制 Measurement，不另复制一份 Notebook 权威。 |

### 必需证据与现场验收

**T02-E1 → AC1/2/5/7：** 检查结构化持久内容及非显示文本的读取结果；实际 UI 录入、修改和查询，并关联照片与笔记后重开读取。  
**T02-E2 → AC3/4：** 两个不同条件/范围样例；人工纠正后经过相关重导入/重建并重新读取。  
**T02-E3 → AC6：** 隔离的失败与重复提交验证。

现场使用一份测试 Sample 输入和纠正电阻、添加一张照片和简短笔记，再重开确认；不要求为一次普通编辑填写来源问卷或理由。

### 交付及下游承诺

交付有限但真实的结构化记录功能、明确当前值与修订制度、首批量的读取合同。M1 至此验收；T07 必须在此基础上接入算法结果，不能引入另一套人工值优先级。

## T03 — 新 AFM 文件进入可独立读取的标准数据体系

**状态：** 规划 / 未开始。  
**所属里程碑：** M2。  
**依赖：** T01；C01/C02 的最小资产保存规则。可与 T02 的不冲突部分并行。  
**目标：** 新导入的明确受支持 AFM 来源，经 Inbox/D2 生成真实标准数据资产，Library 能在重启后直接读取它，而不重新解析原始仪器文件。

### 范围与非目标

从已有真实样例和读取能力选择一种明确格式/版本/通道范围，优先考虑已存在的 IBW 路径。登记 Source，形成有身份和来源关系的 Standard Dataset，正确关联已知 Sample；Library 能查看资产及必要元数据/状态。

保留原测量内容、矩阵形状、坐标、通道及 Trace/Retrace 等已知语义。支持范围之外的来源内容不得静默丢弃后宣称整份已转换；应保留证据和未支持状态。

**不做：** flatten、粗糙度提取、论文级热图、自动化、全部 AFM 格式、LVM/DAT 或历史批量转换。

### 生成 Prompt 前必须补齐

准确样例与格式范围、源副本或可靠引用策略、标准文件/元数据格式、可用通道与未知处理、源单位表达与共享转换方式、数值比较容差、入库成功/部分失败与就绪边界。

D3 的真实文件方向需要落实，但不以此强推“一列一个文件”；需要共同解释的分量按 D6-A §3.2 保持关系。

### 验收标准

| AC | 必须成立 |
|---|---|
| T03-AC1 | 从 Inbox 导入受支持样例后，Library 中有正式 Source 登记及可定位的 Standard Dataset，关联正确 Sample。 |
| T03-AC2 | 对照源文件可核验矩阵值、维度、坐标、顺序、源单位、通道及符号；有单位表达转换时保留依据并满足约定精度，不执行科学数据加工。 |

**目标：** 用户选择一批历史数据，将其接入已稳定的新标准路径，旧测量、图像、指标、人工决定与来源关系不失联；有依据地退出对应旧读取路径。

**范围：** 每轮固定格式/用途、样品集合、资产数量及旧消费者。任务可标为 T11.1、T11.2 等批次，但不是重复建设不同迁移系统。第一次仅选有限范围；正式迁移真实数据需要明确授权。

**先确认：** 实际旧对象与消费者、Source/旧 key/sidecar 缺项、归属歧义、转换策略、预览与备份、失败续作/回退边界、验证读侧。不能根据早期审计错误删除 ArchivedRecord，也不把缺失历史信息补成确认事实。

**验收：** T11-AC1，执行前预览范围、冲突及将改变的内容；T11-AC2，迁移后身份、来源、数值和人工采用可回读对账；T11-AC3，现有成果及引用不失联，删除决定不被复活；T11-AC4，重复执行与中断恢复不产生额外正式副本或半迁移假成功；T11-AC5，未选范围不受影响，正常旧功能保持；T11-AC6，只有读写者和回退条件经过验证后才移除对应旧路径，不顺带自动重算或重画全部历史图。

**必需证据：** 旧 fixture/隔离 Library 副本的迁移前后对照、失败与重复执行、恢复证明；生产数据由用户按已确认范围验收，不先拿全库试验。

**交付：** 本批覆盖和遗留范围说明、迁移证据及下一批约束。单批完成不等于全库已迁移。

## T12 — 用户在前台新建非内置自动化

**状态：** 规划 / 未开始。**依赖：** T05 机制稳定，组合所需能力真实可用；建议在 T08 后验证复用。**里程碑：** M6。

**目标：** 用户用已存在能力和预设创建自己的自动化，选择范围、输出和启停，不修改后台代码。

**范围：** 先采用简单规则/步骤列表即可；不要求通用节点画布、任意代码执行或复杂报告依赖。允许同 Workflow 多预设/多自动化，前台不同入口共用权威定义。

**先确认：** 首批可创建的动作、组合约束、多个规则同时命中时的行为及成果归属、变更对历史/当前运行的影响。不要借“自由度”默认产生重复提交或相互覆盖。

**验收：** T12-AC1，用户创建一条不同于内置预设的流程并实际运行；T12-AC2，可修改、停用、重启恢复和试跑隔离；T12-AC3，多规则命中有明确处理，不各自私存副本；T12-AC4，不打开 Workbench 也执行且使用同一 D4 能力；T12-AC5，既有简单开关和保存/删除/权限机制继续正确。

**必需证据：** 真实前台创建、匹配新数据、改动生效和交叉回归；仅编辑 JSON 或后台脚本不算通过。

**交付：** 前台可创造流程的能力；可在此时宣称已实现对应范围的自定义自动化，而非在 T05 就提前宣称。

**状态：** 规划 / 未开始。**依赖：** 目标预设/解释规则已有稳定正式对象、修订和候选隔离；无需完整 T12。**里程碑：** M6。

**先确认：** 首批可操作对象、允许读取的数据、模型调用权限、验证样例及发布方式；当前不默许上传全部科研数据或自主改生产代码。

**验收：** T13-AC1，用户能看懂建议改什么、对哪些数据生效及证据限制；T13-AC2，确认前候选不影响正式配置/数据，试跑不入正式库；T13-AC3，确认后前台显示、正式修订与实际执行一致；T13-AC4，基线过期的提案不能覆盖后来人工修改，拒绝/撤销按合同处理；T13-AC5，AI 不在线时既有日常自动化仍可运行，经验与规则不只存在于 Provider 聊天；T13-AC6，一次局部调整不自动变为无限适用规则，不为学习记录全部点击。

**必需证据：** 完整提议→试跑→批准/拒绝→实际运行链路、过期提案反例、脱离模型的日常运行与正式记录回读。

**交付：** 受管理的 AI 提案能力；不因此宣称已经获得任意自我修改、科学正确性保证或自主训练能力。

## 7. 阶段验收如何避免“每个 PR 都过了，整体仍不好用”

| 阶段 | 最小整体验收旅程 | 不能拿什么替代 |
|---|---|---|
| M1 | 原生创建 Sample → 记录电阻/尺寸 → 修改确认 → 重启读取 → 相关旧信息仍正确 | 新增结构体、保存一份 JSON 或只有截图 |
| M2 | 导入新 AFM → 标准资产落盘 → 人工处理 → 同配置自动处理/存图 → 关闭开关 → 重复/删除/重开检查 | 纯计算函数测试或在 Workbench 手动读 IBW |
| M3 | DAT 未知通道确认 → 保存规则/新文件复用 → 多对象归属 → AHE 数值与人工采用 → 自动出图不覆盖 | 已知列位置硬编码、PNG 标题里的指标或只测一个 Sample |
| M4 | 固定新来源范围通过标准路径 → 指定历史批次迁移 → 旧引用/人工决定核对 → 相应旧路径有依据退出 | 全目录扫描成功或笼统称“全部支持” |
| M5 | 手机创建 → 桌面读取与修订 → 手机看到当前值 → 旧修订晚到/失败 → 状态与恢复正确 | 静态 Web 列表刷新或 Note API 写入成功 |
| M6 | 新建非内置流程；AI 提案确认前后行为明确；过期提案拒绝覆盖 | 一组预设开关、后台代码修改或一次模型演示 |

阶段整体验收是此前任务性质的组合验证，不是额外的“再写一个大阶段”。必需场景在相应合同开始前明确，避免最后突然追加未商定功能。

## 8. 每个新对话应获得的最小材料

上传 **D6-A 当前版本 + D6-B 当前版本**，明确当前 Task ID。附上相关前置任务的反馈，提供当前 PR 链接或本地可访问环境；主仓库已在 D6-A 列明，不需要反复补充；任务涉及真实格式或科学计算时，再提供必要样例和语义说明。

不必每次上传全部 D1–D5；若当次问题需要追溯具体来源、旧审计或未纳入基线的讨论，再补充相关专题。任务引用的基线版本必须明确，不能假定新对话自动知道其他聊天。

规划 GPT 的输出应包含：当下可复用能力、任务真实缺口、必要决定、建议 PR/阶段边界及一份可交给 Agent 的完整合同。实际命令、文件路径和测试入口来自当时仓库，不从路线图猜测。

GitHub 代码审查需同时拿到原合同与最终 diff/提交。只提供 Agent 的“全部通过”总结不足以验收。现场验收的步骤应短而直接，每一步说明看什么结果；数值与持久化证据由独立回读支持。

## 9. 每项完成后的回传记录

以下是记录字段，不是预制 Coding Agent Prompt。将事实记入该任务的完成反馈，路线图只保存状态和引用，避免复制大量日志。

| 字段 | 内容 |
|---|---|
| 任务与合同 | Task ID、D6-A/D6-B 版本、当次合同版本及实际完成范围 |
| 代码基线 | 仓库、base/head、PR、最终合并提交；受影响规范是否同步更新 |
| 构建与现场 | App 版本/构建标识、对应提交、使用的数据范围及脱敏方式 |
| 验收结果 | 每项 AC 的证据位置、代码审查结论、用户现场观察；失败与修正复验 |
| 持久化与兼容 | 实际采用的资产/身份/解释/保存合同，已迁移及仍旧路径范围 |
| 未完成与限制 | 未支持格式、未验证科学范围、阻塞点；不能用“后续优化”掩盖必需 AC 未通过 |

| 权限与状态 | 用户是否批准合并、合并后必要检查、Task 当前状态 |

技术债进入现有 TASK_BOARD，不在反馈和路线图里另建平行的债务状态。共同契约改变需回主架构协调；内部实现变化只记录对下游有意义的接口，不要求用户评审全部代码细节。
